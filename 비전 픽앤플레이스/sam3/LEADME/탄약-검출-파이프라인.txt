----------------------------------------------------------------------
0. 결론 요약
----------------------------------------------------------------------

색도 쓰지 않고, 분류에 깊이도 쓰지 않는다. SAM 3에 형태 프롬프트 bullet 하나만 주어 물체를 찾고,
분류는 실루엣 비율과 윗면 명암으로 한다. 깊이는 집기 좌표(3D 위치)를 낼 때만 쓴다.


    SAM 3 (RGB, 프롬프트 "bullet")  →  물체 마스크 N개
            │
            ├─ 종횡비 < 2.2  →  꽂힘 (위에서 보면 원형)
            │        └─ 윗면 중심−중간 밝기 ≥ 10 → 탄피 (평평한 뇌관이 빛을 되쏨)
            │                              미만 → 탄두 (둥근 돔이 빛을 흩음)
            │
            └─ 종횡비 ≥ 2.2  →  누움 (길쭉함)
                     └─ 테이퍼 ≥ 0.15 → 탄두 (한쪽만 뾰족한 물방울)
                                  미만 → 탄피 (폭이 일정한 원통)


실행:


    ~/sam3_env/bin/python scripts/run_sam3_depth.py --prompt bullet --display


8개 물체(꽂힌 탄두 2, 꽂힌 탄피 2, 누운 탄두 2, 누운 탄피 2)를 전부 정확히 분류했다.
깊이가 측정되지 않은 물체도 올바르게 분류됐다. 속도 1.3 FPS.


[ 왜 분류에서 깊이를 뺐나 ]

처음에는 깊이 높이로 자세와 종류를 모두 판정했다. 그 방식은 배치가 바뀔 때마다 무너졌다.

| 상황 | 결과 |
|---|---|
| 카메라를 41cm → 23cm로 당김 | 1280x720 깊이가 최소측정거리(28cm) 밖이 되어 유효 픽셀 8% |
| 화면을 트레이가 채움 | 기준면이 매트가 아닌 트레이 바닥으로 잡혀 높이가 축소 |
| 카메라를 기울임 | 배경 깊이가 198~1416mm로 퍼져 단일 기준면이 무의미 |
| 탄피가 셀 안으로 내려앉음 | 격자 벽에 가려 깊이 측정 자체가 실패 (유효 0~12px) |
| 탄두·탄피를 서로 다른 트레이에 | 트레이 깊이 차가 부품 길이 차를 상쇄해 둘 다 24mm |

전부 깊이 기반 높이가 절대량이라 생기는 문제였다. 지금 쓰는 종횡비·테이퍼·상대 밝기는
모두 물체 내부에서 계산하는 비율이라 거리·각도·배경·트레이에 영향받지 않는다.
실제로 테이퍼는 네 번의 서로 다른 배치에서 같은 값이 재현됐다.


----------------------------------------------------------------------
1. 실측 임계값
----------------------------------------------------------------------


[ 자세 판정 — 종횡비 ]

마스크 주축 길이 ÷ 최대 폭. 위에서 본 꽂힌 물체는 원형이라 1에 가깝고, 누우면 길쭉하다.

| 대상 | 실측 |
|---|---|
| 꽂힘 | 1.11 ~ 1.73 |
| 누움 | 2.78 ~ 5.34 |

--pose-aspect 2.2 — 마진 1.05


[ 꽂힌 물체의 종류 — 윗면 명암 ]

마스크 중심에서 반경을 5등분해 평균 밝기를 재고, (중심링 − 중간링)을 본다.
탄피 바닥은 평평하고 광택이 있어 빛을 카메라로 되쏘아 중심이 밝다.
탄두 끝은 둥근 돔이라 빛을 흩어 중심이 어둡다. 물체 내부의 상대값이라 재질 색에 덜 민감하다.

| 대상 | 중심 − 중간 |
|---|---|
| 탄두(꽂힘) | −15.5 ~ −6.1 |
| 탄피(꽂힘) | +27.6 ~ +28.2 |

--center-bright 10 — 부호가 갈리고 마진 34


[ 누운 물체의 종류 — 테이퍼 ]

마스크 주축을 10구간으로 나눠 폭을 재고, 앞 3구간과 뒤 3구간의 평균 폭 차이를 최대폭으로 나눈다.
한쪽만 뾰족해지는 물방울(초코송이) 형태면 크고, 폭이 일정한 원통이면 0에 가깝다.

| 대상 | 테이퍼 | 종횡비 |
|---|---|---|
| 탄두(누움) | 0.19 ~ 0.25 | 2.78 ~ 3.93 |
| 탄피(누움) | 0.06 ~ 0.11 | 4.84 ~ 5.34 |

--taper-th 0.15 — 마진 0.09. 네 번의 서로 다른 배치(거리 337·410mm, 기울기·배경 상이)에서 재현됐다.


[ 깊이는 집기 좌표에만 ]

분류에서 빠졌으므로 깊이가 실패해도 클래스는 나온다. 3D 위치가 필요할 때만 쓴다.

- --stand-mm 20 — 참고용 높이 표시
- 국소 평면 적합: 물체 주변 링에 z = ax+by+c를 맞춰 그 위 높이를 잰다. 카메라가 기울어도,
  물체가 매트·트레이·수납함 어디에 있어도 각자 놓인 면 기준으로 측정된다 (--ring-px 14)


----------------------------------------------------------------------
2. 프롬프트 — 무엇이 되고 무엇이 안 되나
----------------------------------------------------------------------

레퍼런스 사진 9장과 실시간 화면으로 검증한 결과다.


[ 쓸 수 있는 것 ]

| 프롬프트 | 용도 | 점수 |
|---|---|---|
| bullet | 탄두·탄피 전부 (자세·색 무관) | 0.74 ~ 0.97 |
| cylinder | 원통형 (탄피 + 꽂힌 탄두) | 0.89 ~ 0.95 |
| plastic box | 트레이 | 0.77 ~ 0.88 |
| pointed cone | 누운 탄두 | 0.86 ~ 0.94 |


[ 쓰면 안 되는 것 ]

| 프롬프트 | 문제 |
|---|---|
| gold cylinder | 색 의존. 회색조 변환하면 0.46 하나로 붕괴 |
| silver bullet | 색 의존. 구리색·건메탈색 탄두에서 0개 |
| bullet casing | 탄두까지 같이 물어 이중 계수. 장면에 따라 점수가 0.225~0.82로 요동 |
| cartridge, projectile, bullet tip, shell casing | 정식 용어일수록 0개가 잦다 |

교훈: 짧고 흔한 명사가 잘 먹힌다. 그리고 색을 넣은 프롬프트는 조명이나 도금이 바뀌면 무너지니 쓰지 않는다.


[ 색 의존성 검증법 ]

회색조 + CLAHE로 변환해 같은 프롬프트를 돌려본다. 점수가 유지되면 형태 기반, 무너지면 색 기반이다.


    g = cv2.cvtColor(im, cv2.COLOR_BGR2GRAY)
    g = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8)).apply(g)
    gray3 = cv2.cvtColor(g, cv2.COLOR_GRAY2BGR)

----------------------------------------------------------------------
3. RealSense 설정 — 반드시 지킬 것
----------------------------------------------------------------------


[ 컬러 노드 찾기 ]

D435는 /dev/video* 노드를 6개 만든다. 컬러는 보통 /dev/video4, video2는 IR(흑백)이다. 번호는 재연결하면 바뀔 수 있으므로 BGR 채널 편차로 판별한다.


    d = np.mean(np.abs(f[:,:,0].astype(int) - f[:,:,2].astype(int)))
    # d > 3 이면 컬러, 0에 가까우면 IR


[ 노출 ]

기본 상태가 심하게 어둡다(mean 36). 이러면 검출이 거의 안 된다.


    cap.set(cv2.CAP_PROP_AUTO_WB, 1)
    cap.set(cv2.CAP_PROP_AUTO_EXPOSURE, 1)
    cap.set(cv2.CAP_PROP_EXPOSURE, 600)     # mean 155 부근


후처리로 밝기를 올리는 건 효과가 없다. 밝기 3.2배 + 화이트밸런스를 적용해도 검출 개수가 원본과 완전히 동일했다. 없던 정보는 만들어지지 않으니 촬영 단계에서 잡아야 한다.


[ 깊이 스트림 — 필터를 끄고 해상도를 올린다 ]


    cfg.enable_stream(rs.stream.depth, 848, 480, rs.format.z16, 30)
    align = rs.align(rs.stream.color)
    # spatial_filter / hole_filling_filter 는 쓰지 않는다


해상도는 848x480을 쓴다. 1280x720은 최소 측정 거리가 약 28cm라 근접 촬영에서 깊이가 통째로 빈다.
실제로 카메라를 23cm까지 당겼을 때 유효 픽셀이 8%로 떨어졌고, 848x480(최소 ~20cm)에서는 74%였다.

spatial/hole-filling 필터가 작은 봉우리를 뭉갠다. 필터를 켜면 윗면 기복이 1~3mm로 죽고, 끄고 1280x720으로 올리면 4~12mm로 살아난다. 노이즈를 줄이려다 판별 신호를 지우는 셈이다.

기준면(테이블)은 물체 마스크를 제외한 전체 깊이의 중앙값으로 잡는다. 카메라 높이가 바뀌어도 자동으로 따라간다.

----------------------------------------------------------------------
4. 왜 이 구조인가 — 버린 접근들
----------------------------------------------------------------------


[ 비디오 트래커를 쓰지 않는 이유 ]

Sam3VideoModel은 첫 프레임에 트랙을 만들고 전파하는 구조다. 물체가 움직이면 재검출이 즉각 일어나지 않아 카운트가 어긋나고, 새 트랙이 계속 생겨 VRAM이 쌓이다 3~4분 만에 CUDA OOM으로 죽는다.

| | 비디오 트래커 | 매 프레임 검출 |
|---|---|---|
| 이동 대응 | 트랙이 어긋남 | 즉시 반영 |
| 속도 (3프롬프트) | 1.2~2.0 FPS | 2.18 FPS |
| VRAM | 3.4 → 5.37 GiB 증가 | 2.03 GiB 고정 |
| 3~4분 후 | OOM 사망 | 안정 |
| 해상도 | 672로 낮춰야 함 | 1008 전체 |

포기하는 것은 객체 ID 연속성 하나뿐이다. 필요하면 검출 결과에 IoU 기반 프레임 간 매칭을 붙이는 편이 SAM 3 트래커보다 가볍고 안정적이다.


[ 속도를 올리는 방법 — vision 임베딩 공유 ]

프롬프트마다 전체 추론을 돌리면 3배가 든다. vision 인코더는 프레임당 한 번만 돌리고 텍스트 프롬프트들이 공유하게 한다.


    ve = model.get_vision_features(pixel_values=img_inputs.pixel_values)
    for prompt in prompts:
        out = model(vision_embeds=ve, **text_inputs[prompt])


단일 프롬프트 337ms → 3개 프롬프트 459ms. 추가 프롬프트당 60ms만 든다.


[ 해상도를 낮추면 안 되는 이유 ]

작은 물체가 먼저 사라진다. 클래스가 통째로 없어지므로 속도를 위해 낮추면 안 된다.

| image_size | FPS | 탄피 | 탄두 | 박스 |
|---|---|---|---|---|
| 1008 | 0.94 | 8 | 1 | 2 |
| 672 | 1.33 | 9 | 1 | 2 |
| 560 | 2.23 | 9 | 0 | 0 |
| 448 | 2.52 | 5 | 0 | 0 |


[ 명암(밝기) 기반 분류 — 실패 ]

꽂힌 탄두와 탄피를 회색조 밝기의 중앙-테두리 차이로 가르려 했으나 값이 겹쳐 실패했다(탄두 -1.9~+16.4, 탄피 -7.6~+9.3). 조명 반사에 좌우되어 신뢰할 수 없다. 같은 정보를 깊이로 재면 마진 16mm로 확실하게 갈린다.

| --smooth | 꺼짐 | 켜면 봉우리가 사라지니 주의 |
| --display | | 실시간 창 |
| --dump | | 객체별 높이·기복 수치 출력 |

      "IMEAGE/a.jpg,IMEAGE/b.jpg" "bullet|cylinder|pointed cone" 0.4

----------------------------------------------------------------------
6. 한계와 다음 단계
----------------------------------------------------------------------


[ 부품 규격에 묶인 값 ]

--split-mm 55는 이 부품 길이와 트레이 깊이에 맞춘 값이다. 규격이 다른 탄종이 섞이면 다시 재야 한다. 반면 --taper-th는 형태 비율이라 크기에 덜 민감하다.


[ 검증 표본이 적다 ]

각 클래스당 2~3개로 임계값을 잡았다. 조명·자세·부품을 바꿔가며 더 모아야 실제 마진을 알 수 있다.


[ 속도 ]

1.0 FPS다. 로봇 픽앤플레이스에는 부족할 수 있다. 올리려면

1. SAM 3로 자동 라벨링 → YOLO 학습. 같은 8GB에서 30~60 FPS. 학습도 가능하다 (SAM 3 파인튜닝은 최소 16GB VRAM 필요라 이 PC에서 불가)
2. torch.compile, flash-attn-3
3. 카메라를 물체에 더 가깝게 — 물체가 커지면 낮은 해상도를 쓸 수 있다


[ 정확도를 더 올리려면 ]

카메라를 15~30도 기울인다. 바로 위에서 내려다보면 높이 정보가 시야에서 사라져 꽂힌 탄두와 탄피가 비슷해 보인다. 기울이면 원뿔 옆모습이 드러나 RGB와 깊이 양쪽에서 명확해진다. 지금은 깊이로 우회했지만 근본 해법은 이쪽이다.
