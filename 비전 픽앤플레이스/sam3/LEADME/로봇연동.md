## 1. 동작 개요

```
SAM 3 + 깊이로 탄두/탄피 검출
        │
        ├─ 우선순위로 대상 하나 선택
        │     탄피 → 탄두,  같은 종류면 로봇에 가까운 쪽
        │
        ├─ 비주얼 서보잉: 대상이 화면 중심에 올 때까지 X/Y 반복 이동
        │
        └─ 중심 정렬되면 깊이로 잰 실제 거리만큼 Z 하강 → 파지 → 들어올리기
```

**핸드아이 캘리브레이션이 필요 없다.** 픽셀 오차를 보고 되먹임으로 맞추므로,
카메라를 옮겨도 야코비안만 다시 학습하면 된다(3장).

기존 `vision_pick_and_place.py` 는 ArUco 마커 위치를 `calib_transform.npz` 로 로봇 좌표에 변환하는
개루프 방식이라 카메라를 옮기면 캘리브레이션을 다시 해야 한다. 이쪽은 그 제약이 없다.

## 1-1. 하드웨어 구성 — eye-in-hand

**카메라는 팔 끝에 붙어 있다.** 손목 오른쪽으로 흰색 브래킷이 나오고 그 끝에 카메라가 아래를 향한다.
그리퍼는 그 옆에서 수직으로 내려온다. (`MUJOCO/Screenshot from 2026-09-08 16-28-06.png`)

이 구성이 방식 전체를 정한다.

| | eye-in-hand (현재) | eye-to-hand (고정 카메라) |
|---|---|---|
| 팔이 움직이면 화면 | 같이 움직인다 | 그대로다 |
| 비주얼 서보잉 | **성립한다** | 성립하지 않는다 |
| 하강량 | 측정거리 − 오프셋 | 좌표 변환 필요 |
| 캘리브레이션 | 불필요(야코비안만 학습) | 핸드아이 필수 |

`vision_pick_and_place.py` 가 쓰는 `calib_transform.npz` 의 `R, t` 도 월드 고정이 아니라
**손목 기준 고정 오프셋**이다. 카메라가 팔에 붙어 있으므로 그렇게 성립한다.

## 3. 야코비안 학습 — 캘리브레이션 대체

픽셀 오차를 로봇 이동량으로 바꾸려면 둘 사이의 관계가 필요하다.
로봇 X/Y를 조금씩 움직여 픽셀이 얼마나 움직이는지 직접 재서 2×2 행렬을 만든다.

```
[du, dv]ᵀ = J · [dx, dy]ᵀ        서보 시에는 J⁻¹ 로 역산
```

```bash
~/sam3_env/bin/pythonVISIONSCRIPTS/sam3_pick_ros2.py --probe
```

- 대상 하나를 잡은 상태에서 X축 ±12mm, Y축 ±12mm로 **작게 4회** 움직인다
- 결과는 `../VISIONSCRIPTS/servo_jacobian.npz` 에 저장된다
- `--probe-mm` 으로 시험 이동량을 조절한다

**다시 학습해야 하는 때**: 카메라를 옮기거나 각도를 바꿨을 때, 렌즈/해상도를 바꿨을 때.
물체 배치만 바뀌는 것은 상관없다.

## 4-1. MuJoCo 시뮬로 미리 보기

실제 로봇을 켜기 전에 궤적을 눈으로 확인한다. 백엔드는 `../VISIONSCRIPTS/mujoco_backend.py`.

```bash
# 뷰어를 띄우고 시뮬로 동작
~/sam3_env/bin/pythonVISIONSCRIPTS/sam3_pick_ros2.py --sim --grasp --z-offset-mm 35

# 뷰어 없이 로직만
~/sam3_env/bin/pythonVISIONSCRIPTS/sam3_pick_ros2.py --sim --sim-noviewer --grasp --z-offset-mm 35

# 백엔드 단독 점검 (카메라 없이도 된다)
~/sam3_env/bin/pythonVISIONSCRIPTS/mujoco_backend.py
```

모델은 `~/fr5_mujoco/fr5.xml`. 감쇠 최소자승 역기구학으로 위치를 풀고,
손가락 끝 두 개의 중점을 TCP로 본다. 관절 리밋을 매 스텝 클램프하므로 `j6` 의 상한 `0.021` 도 지켜진다.
실측 결과 역기구학 오차는 0.12~0.38mm.

### 시뮬로 확인되는 것 / 안 되는 것

**확인된다**: 역기구학 수렴, 관절 리밋 위반 여부, 그리퍼 동작, 명령 순서

**확인되지 않는다**

- **비주얼 서보잉** — MuJoCo 안에는 카메라도 탄두·탄피도 없다. 시뮬 팔이 움직여도
  실제 카메라 화면은 그대로여서 픽셀 오차가 변하지 않는다. 되먹임 루프가 수렴할 수 없으므로
  `--sim` 에서는 개루프 1회 이동만 하고 하강·파지 단계로 넘어간다
- **하강 거리의 타당성** — 시뮬 홈 포즈는 바닥에서 TCP Z=50mm 인데 실제 작업 자세는 테이블 위 약 300mm다.
  기준이 달라 시뮬에서 303mm를 내리면 Z가 음수가 된다. **시뮬에서 바닥을 뚫는 것은 정상이며,
  하강량 검증에 시뮬을 쓰면 안 된다**
- **충돌** — 작업대·트레이·지그가 모델에 없다
- **자세(RX/RY/RZ)** — 위치만 푼다. FR5의 오일러 각 규약이 확인되지 않아,
  틀린 자세를 맞다고 보여주느니 빼는 편을 택했다

### 개선 여지

시뮬 시작 자세를 실제 작업 자세로 맞추면 하강 검증도 의미가 생긴다.
ROS2 `/nonrt_state_data` 에서 현재 관절값을 읽어 시뮬 초기값에 넣는 방식이 자동이라 낫다. (미구현)

## 5. 실행 전 반드시 실측할 두 값

이 둘은 장비에서 재야 하는 값이라 기본값을 쓰면 안 된다.

### `--z-offset-mm` (기본 0, 반드시 교체)

깊이가 주는 거리는 **카메라 원점 → 물체**다. 실제로는 **그리퍼 파지점**까지 내려야 하므로 그 차이를 더한다.
기존 `vision_pick_and_place.py` 의 `Z_GRASP_OFFSET_MM = 34.6` 에 해당한다.

**측정 방법**

1. `--move` 로 대상을 중심에 정렬한다
2. 그때 화면에 찍힌 거리(mm)를 적어둔다 — 이것이 카메라→물체 거리
3. Jog으로 그리퍼를 물체를 감싸는 높이까지 내리고, 내려간 Z 변화량을 읽는다
4. `z_offset = (실제 내려간 양) − (화면 거리)`

0인 채로 `--grasp` 하면 경고를 낸다.

### `--center-x` / `--center-y` (기본 320, 240)

**그리퍼 TCP가 화면의 어느 픽셀에 오는지**다. 화면 정중앙이 아닐 수 있다.

**측정 방법**: 물체를 하나 두고 Jog으로 그리퍼 TCP를 그 물체 바로 위에 맞춘 뒤,
그 순간 화면에서 물체 중심 픽셀을 읽는다. 그 값이 center-x/y다.

## 6. 옵션

### 서보잉

| 옵션 | 기본 | 의미 |
|---|---|---|
| `--tol-px` | 8.0 | 이 픽셀 안이면 정렬 완료 |
| `--gain` | 0.6 | 1회 이동량 비율. 1.0이면 한 번에 목표까지(진동 위험) |
| `--max-step-mm` | 15.0 | 1회 이동 상한 |

| `--probe-mm` | 12.0 | 야코비안 학습용 시험 이동량 |

### 파지·이동

| 옵션 | 기본 | 의미 |
|---|---|---|
| `--speed` | 10 | 로봇 속도 % |

| `--robot-side` | bottom | 화면에서 로봇이 있는 방향. 같은 종류면 가까운 쪽 먼저 |

## 7. 안전 장치

- **기본이 미리보기**다. `--probe` / `--move` / `--grasp` 를 줘야 실제로 움직인다
- 미리보기에서는 모든 로봇 명령이 `[dry-run]` 으로 출력만 된다
- 속도 10%, 1회 이동 15mm 상한
- 정렬 실패, 대상 소실, 거리 계산 실패 시 파지로 진행하지 않고 중단
- 처음 `--probe` / `--move` 를 돌릴 때는 로봇 주변을 비우고 비상정지에 손이 닿는 상태에서 진행할 것

## 8. 우선순위 규칙

```python
sorted(dets, key=lambda d: (0 if d["kind"]=="탄피" else 1, near(d)))
```

1. **탄피가 먼저**, 그다음 탄두
2. 같은 종류면 **로봇에 가까운 쪽**. `--robot-side` 가 화면상 어느 방향이 로봇인지 정한다
   (`bottom` 이면 화면 아래쪽이 로봇에 가깝다고 본다)

자세(꽂힘/누움)는 우선순위에 넣지 않았다. 필요하면 이 정렬 키에 항목을 추가한다.

## 9. 아직 검증되지 않은 것

**미리보기(dry-run)까지는 실행해 확인했다.** 8개 검출에서 우선순위 규칙대로
탄피 4개 중 로봇에 가장 가까운 것을 골랐고, 픽셀 오차 151.7px를 계산했다.
MuJoCo 백엔드도 역기구학·그리퍼·파지 시퀀스가 도는 것을 확인했다.

**실제 로봇으로는 한 번도 움직여보지 않았다.** `--probe` / `--move` / `--grasp` 는 모두 미검증이다.

처음 돌릴 때 확인할 순서:

1. 미리보기로 대상 선정이 맞는지 — `--display` 만
2. `--probe` 로 야코비안 학습. 출력된 `du/dv` 부호가 상식과 맞는지
3. `--move` 로 정렬. 몇 회만에 수렴하는지, 진동하지 않는지 (진동하면 `--gain` 을 낮춘다)
4. z-offset 실측 후 `--grasp`

`--grasp` 는 마지막에, 두 실측값을 넣은 뒤에만 시도한다.
