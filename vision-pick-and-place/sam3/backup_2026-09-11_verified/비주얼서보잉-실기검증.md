## 1. 동작 구조

절대 좌표는 세 군데뿐이고(홈·경유점·놓을 위치), 검출부터 들어올리기까지는 전부 상대 이동이다.

```
① 그리퍼 35 로 개방       ActGripper + MoveGripper
② 시작 위치로 이동        JNTPoint + MoveJ(JNT1)       ← 관절값, 절대
③ SAM 3 검출 → 대상 선택   탄피 우선, 같은 종류면 로봇에 가까운 쪽
                         한 번 고르면 계속 추적한다 (track_target)
④ 보폭 기준 거리 1회 측정   Z0 — 서보 중 고정
⑤ while 서보 (X·Y 동시)   move_rel(dx, dy, 0)          ← 상대
⑥ 정렬 좌표 기록          aligned_poses.json
⑦ 보정 이동              move_rel(gx, gy, 0) → move_rel(0, 0, gz)   ← 상대
⑧ 그리퍼 22 로 파지       done=2 면 물림
⑨ 들어올리기              move_rel(0, 0, +100)          ← 상대
⑩ 경유점으로 이동          PLACE_APPROACH                ← 카테시안, 절대
⑪ 놓을 위치로 하강         PLACE_POSE                    ← 카테시안, 절대
⑫ 그리퍼 35 로 놓기
```

⑦ 을 XY 와 Z 두 단계로 나눈다. 한 번에 비스듬히 들어가면 그리퍼가 물체를 밀어낸다.
⑩⑪ 도 같은 이유로 나눈다 — 경유점과 놓을 위치의 X/Y 를 같게 잡아 ⑪ 을 순수 수직 하강으로 만든다.

**물체가 어디로 옮겨져도 동작한다.** 화면에서 보이는 오차만큼만 상대로 움직이므로
물체의 절대 위치를 알 필요가 없다. 되먹임이라 몇 번 반복하면 수렴한다.

### 상대 이동(트랜스)의 실제 구현

UR 로봇의 `pose_trans` 에 해당하는 것이 Fairino 의 `MoveL` offset 파라미터다.

```
MoveJLC_offset_flag  = 1        # 1=공작물/베이스, 2=공구(pose_trans 와 같은 의미)
MoveJLC_offset_pos_x = dx
MoveJLC_offset_pos_y = dy
MoveJLC_offset_pos_z = dz
CARTPoint(1, 현재좌표 그대로, 현재자세 그대로)
MoveL(CART1, speed, tool, user)
```

목표점에는 현재 위치를 그대로 넣고 이동량은 offset 으로만 준다.
기준 좌표계 변환을 로봇이 처리하므로 계산 오차가 누적되지 않는다.

자세는 항상 현재 값을 유지하므로 베이스 기준(1)과 공구 기준(2)이 같은 결과를 낸다.

## 2. 검증된 실행 명령

```bash
# 탄피 전 구간. 09-11 5회 연속 완주
~/sam3_env/bin/python -u sam3_pick_ros2.py --descend --display --sign "+,-" \
    --threshold 0.15 --min-len-mm 0 --exclude "430,0,640,480"

# 탄두(격자에 꽂힌 물체) 전 구간. 09-11 3회 연속 완주
~/sam3_env/bin/python -u sam3_pick_ros2.py --descend --display \
    --detector sam3 --threshold 0.03 --min-len-mm 0 \
    --sign "+,-" --exclude "430,0,640,480"
```

꽂힌 탄두는 위에서 링만 보여 점수가 낮게 나오므로 `--threshold 0.03` 으로 내린다.
낮춘 만큼 오검출이 늘지만 전부 `--exclude` 영역(브래킷) 안이고, 같은 물체의
중복은 `--dedup-px 15` 가 지운다.

> ⚠️ `--detector both --require-both` 를 쓰지 마라. 깊이 검출이 트레이를 한 덩어리로
> 만들어 **합의할 상대가 없어져 검출 0개**가 된다. 5장 "깊이 검출은 왜 못 쓰나" 참고.

`--tol-px`(4) · `--simultaneous`(기본) · 속도는 모두 기본값이라 줄 필요가 없다.

`--exclude` 는 고정대 브래킷을 빼는 **배치 전용 좌표**라 기본값에 박지 않고 인자로 준다.
카메라나 작업대가 바뀌면 다시 재야 한다.

보정값은 `grip_offset.json` 에서 자동으로 읽는다. 시작 위치는 `HOME_JOINTS` 상수다
(09-10 정리 때 하드코딩으로 결정 — `home_pose.json` 은 더 읽지 않는다).

| 옵션 | 값 | 근거 |
|---|---|---|
| `--sign` | `+,-` | Y 축 부호가 반대. `+,+` 로는 오차가 발산한다 |
| `--speed` | 5 | 기본값 |
| `--tol-px` | 5 | 0 이면 물체 반크기(약 12px)로 자동 |
| `--movecmd` | MoveL | 직선. 서보 보정에 적합 |
| `--hold` | | 정렬 후 하강하지 않고 대기 |
| `--hold-redo` | | 대기 중 물체가 움직이면 다시 추종 |
| `--kind` | 탄피 / 탄두 | 종류 고정. 분류가 흔들려 대상이 갈아타는 걸 막는다 |
| `--len-split-mm` | **17** | 09-09 의 20.0 은 탄피가 경계에 정확히 걸렸다 (아래) |
| `--tol-px` | **4** | 약 1.72mm. 09-11 에 5 → 4 로 조임 |
| `--speed` | **5** | 서보 정렬. 보폭이 1~15mm 라 낮게 둔다 |
| `--speed-move` | **10** | 보정·하강·들어올리기·경유점·놓기. 큰 이동만 빠르게 |
| `--simultaneous` | **기본 켜짐** | X·Y 동시. `--sequential` 로 09-11 이전 방식 |
| `--z-split-mm` | **268** | 거리로 종류를 가른다. 가까우면 탄피, 멀면 탄두 |
| `--dedup-px` | **15** | 중복 검출 제거 반경. 면적이 큰 마스크를 남긴다 |
| `KIND_CFG[...]['after']` | `[(0,-2,0)]` | 박기 마지막 좌표에서 **이어서** 갈 상대 이동. 박기를 교체하지 않고 덧붙인다 |
| `--lift-mm` | 100 | 파지 후 들어올릴 높이 |
| `--track-radius-px` | 60 | 추적 반경 |
| `--regain-radius-px` | 90 | 놓쳤다 재등장 시 이어갈 반경 |

### 동작 단계별 옵션

| 옵션 | 하는 일 |
|---|---|
| (없음) | 그리퍼 35 → 홈 → 검출 → 서보는 미리보기 |
| `--move` | 위 + 서보 실제 이동 |
| `--move --hold` | 정렬 후 그 자리에서 대기 |
| `--descend` | **전 구간** — 정렬 → 하강 → 파지 → 들어올리기 → 경유점 → 놓기 |
| `--no-servo` | **현재 위치에서** 하강 → 파지 → 들어올리기 → 놓기 (검출·홈 없음) |
| `--no-place` | 들어올린 자리에서 끝낸다 |
| `--save-grip-offset` | 정렬 기록과 현재 위치의 차이를 저장 |
| `--dry` | 로봇을 전혀 건드리지 않는다 |
| `--no-home` | 시작 위치로 가지 않는다. 지금 프레임을 그대로 진단할 때 |

**시작 위치까지는 `--move` 없이도 실제로 간다.** 안 가면 카메라가 작업대를 보지 않아
검출 확인 자체가 무의미하다. 막으려면 `--no-home` 또는 `--dry`.

### SAM3 프롬프트 — 09-10 의 가장 중요한 발견

**서보 중 대상이 사라지던 원인이다.** 3회 연속 같은 패턴으로 재현됐다:
X 는 늘 5회에 수렴하는데 Y 후반에서 검출이 0개가 되어 무한 대기에 빠졌다.
한 번은 130초를 넘겨 중단했다.

화면을 떠 보니 **물체는 이미 화면 중심에서 5px 안에 있었다.** 정렬은 끝났는데
검출만 안 되고 있었다. 같은 프레임에 프롬프트를 바꿔 걸어 점수를 비교한 결과:

| 프롬프트 | 최고 점수 | 마스크 수 | 비고 |
|---|---|---|---|
| `circle` | 0.867 | 31 | 격자 셀 구멍이 전부 원형 — 오검출 |
| `small metal object` | 0.848 | 81 | 고정대까지 잡는다 |
| **`metal ring`** | **0.703** | 43 | **채택.** 금속+링을 함께 요구해 플라스틱 격자를 배제 |
| `metal cylinder` | 0.178 | 11 | |
| `nut` | 0.066 | 6 | |
| **`bullet`** | **0.029** | 2 | 09-09 의 기본값. `--threshold 0.15` 를 못 넘는다 |
| `cartridge case` · `bullet casing` · `shell casing` · `ammunition` | — | **0** | 탄약 용어 계열은 전부 실패 |

전부 같은 물체를 찍는다 (중심 324.6/241.4, 면적 461~467px, Z=259.0mm 일치).

**핵심은 자세다.** 비스듬히 보이는 꽂힌 탄피는 원통 형태가 드러나 `bullet` 이 통한다.
그런데 화면 중심으로 정렬해 **수직으로 내려다보게 되면 링만 남아** 점수가 0.029 로 떨어진다.
즉 **정렬에 성공할수록 검출이 실패하는** 구조였다.

그래서 두 표현을 병행한다 — 09-10 부터 기본값이다.

```
--prompt "bullet,metal ring"
```

SAM3 는 이 물체를 "탄피"로 인식하지 않고 **"금속 링"으로** 본다. 탄약 용어로는 안 잡힌다.

> 부작용: `metal ring` 은 고정대 금속 브래킷도 잡는다. 09-10 에 브래킷이
> 길이 31.7mm 로 탄피로 분류돼 **우선순위 1위**가 되면서 서보가 291.8px 만큼
> 엉뚱한 방향으로 가려 했다. `--exclude` 로 빼야 한다.

> 부작용 2: `metal ring` 은 링만 잡으므로 **길이가 절반으로 측정된다**
> (`bullet` 일 때 19.6~20.2mm → `metal ring` 일 때 10.7mm). 그래서 같은 물체가
> `탄피` 에서 `탄두` 로 분류된다. 하강은 `grip_offset` 상수를 쓰므로 영향이 없지만,
> `--kind` 로 종류를 고정하려면 `--len-split-mm` 을 다시 잡아야 한다.

### 2026-09-11 — 세 가지 개선과 전 구간 완주

**① 대상 추적 복원 (`track_target`)**

690줄 버퍼 기준으로 코드를 자를 때 빠져 있었고, 매 프레임 우선순위로 대상을 다시
고르고 있었다. 같은 물체가 두 프롬프트(`bullet` / `metal ring`)에서 중복 검출되어
1~3px 차이로 두 개씩 잡히는데, 추적기가 그 사이를 오갔다.

```
(387,283) L=10.7  /  (388,283) L=10.5     ← 1px 차이, 같은 물체
(312,283) L=13.1  /  (312,286) L=10.6     ← 3px 차이
```

복원 후 **X 서보 14회 → 5회**. 처음 한 번만 우선순위로 고르고 이후에는 직전 위치에서
가장 가까운 검출을 잇는다. 분류가 흔들려도 처음 판정을 유지한다.

**② XY 동시 서보를 기본으로 (`--simultaneous`)**

순차(X 먼저 → Y)는 Y 를 맞추는 동안 X 가 틀어져 **최종 재정렬이 매번 발생**했다.

```
[X] 5회 완료 4.2px → [Y] 4회 완료 4.9px → [최종] 6.4px — X 재정렬 필요
```

동시 모드는 오차 벡터의 두 성분을 함께 환산해 대각선으로 이동하고, 종료 조건이
처음부터 합산 오차라 재정렬 단계가 없다. 허용치를 5px → 4px 로 **조였는데도** 개선됐다.

| | 순차 (5px) | 동시 (4px) |
|---|---|---|
| 회차 | X 5~6 + Y 4~5 + 재정렬 = 10~13 | **3~5** |
| 최종 오차 | 2.9~4.9px | 2.7~3.7px |
| 재정렬 | 매번 | 없음 |

4회 실행 실측: 5회/3회/4회/4회, 오차 2.7~3.7px. `--sequential` 로 이전 방식 사용 가능.

**③ 속도 분리 (`--speed` 5 / `--speed-move` 10)**

서보는 보폭이 1~15mm 라 5% 로 두고, 정렬 이후 큰 이동만 10% 로 올렸다.
전체 시퀀스가 약 4분 → 2분. 타임아웃은 거리 비례식이라 자동으로 따라간다.

Z 하강 194mm 편차 비교 (같은 동작 반복 측정):

```
5%   (-0.92,+2.16,+1.95) (-0.79,+2.00,+1.95) (-0.78,+2.47,+1.99)
     (-0.75,+2.38,+1.97) (-0.72,+2.30,+1.91)      평균 (-0.81,+2.26,+1.95)
10%  (-0.64,+1.78,+1.81) (-0.54,+2.51,+1.88) (-0.49,+2.50,+1.97)
     (-0.92,+1.84,+1.97)
```

X 가 0.3mm 정도 개선됐고 Y·Z 는 비슷하다. **속도를 바꾸면 이 편차가 변하므로
보정값을 다시 확인해야 한다** — 보정값 판단에 이 편차가 섞여 있다.

### 놓기 구간 — 경유점과 박기

09-10 에 파지 위치에서 놓을 위치로 **곧장** 230mm 카테시안 이동을 시도해 사고가 났다.

```
20:04:35  warning  Currently in a singular pose
20:04:37  error    1~6 Axis slave station configuration error
20:05:09  error    The number of active slave stations is wrong: 1
20:05:09  warning  Power off and restart the control box if the joint communication is abnormal
20:05:09  error    1~6 Shaft dropping from station
```

목표에서 **626mm 어긋나** 비상정지했고, 급정지 중 6축 전부가 EtherCAT 슬레이브에서
탈락했다. 관절값이 전부 `0.000000` 으로 읽히고 에러 `5,1` 이 남았는데
`ResetAllError()` 는 0(성공)을 반환하면서도 알람을 지우지 못했다.
**컨트롤 박스 전원 재투입**으로만 복구됐다 (컨트롤러 로그가 그렇게 안내한다).

> 알람 원문은 웹 UI 로그(`/action/get`, `cmd: get_log_data`)에서 읽었다.
> `GetRobotErrorCode` 의 주/부코드 표는 `lang/ko.json` 에 없다 —
> `setErrorDict` 는 RPC 반환코드(500 계열) 표이고 컨트롤러 알람 표가 아니다.

해결은 **경유점**이다. 놓을 위치 위로 먼저 가서 수직으로 내려간다.

```
PLACE_APPROACH = [125.969, -1145.936, -189.006, 179.766, 0.124, 179.307]
PLACE_POSE     = [125.971, -1145.926, -271.083, 179.766, 0.124, 179.307]
PLACE_PRESS    = Z 를 -272.083 / -273.083 / -274.083 으로 1mm 씩 세 번
```

두 가지를 지킨다:

- **X/Y 를 같게** — 0.01mm 이내. 마지막이 순수 수직 82mm 하강이 되어 트레이 벽을
  치지 않는다. 실측 도달 오차 X/Y 0.04mm
- **자세를 파지 자세와 통일** — `rx=179.77, ry=0.12`. 09-10 의 경유점은 `rx=-177.40`
  이었는데, 파지 자세 `+179.77` 과 물리적으로 2.8도 차이지만 숫자로는 357도라
  손목이 한 바퀴 도는 경로가 생길 수 있다

**박기 3단계** — 물체를 쥔 채 1mm 씩 세 번 누르고 그다음 그리퍼를 벌린다.
한 번에 3mm 내리지 않는 이유는 걸렸을 때 어느 깊이인지 알 수 있기 때문이다.

```
놓을 위치   -269.62
박기 1/3    -272.04   차이 +0.04mm   (실제 2.42mm)
박기 2/3    -272.34   차이 +0.74mm   (실제 0.30mm)
박기 3/3    -273.95   차이 +0.13mm   (실제 1.61mm)
```

단계별 이동량이 고르지 않다. 놓을 위치 도달 시 Z 편차 +1.46mm 가 이미 누적돼 있고
판정 허용치(`tol=1.0`)가 이동량(1mm)과 비슷해 단계가 뭉개진다.
**최종 깊이는 목표와 0.13mm 차이**라 결과는 맞다. 균등하게 누르려면 `tol` 을
0.3 정도로 조여야 하는데 그러면 도달 못 해 타임아웃 날 위험이 있다.

### 종류별 시퀀스 분리 (09-11 후반)

탄피를 놓은 뒤 탄두를 그 위에 올리는 조립이 목표라, **검출된 종류에 따라 시퀀스가
갈라져야** 한다. `KIND_CFG` 표에 종류별로 담고 `kind_cfg(kind)` 가 골라준다.

| 항목 | 탄피 | 탄두 |
|---|---|---|
| `grip` 파지 보정 | `(+34.94, -86.46, -194.23)` | `(+38.23, -87.87, -200.99)` |
| `close` 파지 그리퍼 | 22 | **17** (탄두가 얇다) |
| `approach` 경유점 | `(125.969, -1145.936, -189.006)` | `(127.630, -1146.598, -239.396)` |
| `pose` 놓을곳 | `(125.971, -1145.926, -271.083)` | `(127.630, -1146.600, -245.397)` |
| `press` 박기 | `-1, -2, -3mm` | `-1.16mm` |
| `release` 놓기 | True | False (쥔 채 멈춤) |
| `back` 복귀 | True | False (그 자리 멈춤) |

**파지 보정값을 종류별로 분리한 이유** — `grip_offset.json` 은 탄피 기준 실측값이다.
종류별 값이 없을 때 이 값을 물려받게 두면 탄두가 6.76mm 얕게 내려가 안 물린다.
그래서 `"grip": "json"` 이라고 명시한 종류만 json 을 쓰고, `None` 인 종류는
그 단계에서 멈추고 무엇을 재야 하는지 알려준다.

탄두 보정값은 정렬 기준 `(286.748, -1160.084, -86.586)` 에서 Jog 으로 재고
자세 차이 0.000도를 확인했다. 탄피보다 Z 가 6.76mm 깊은데, 탄두 15mm /
탄피 21mm 의 길이 차이와 맞는다.

### 놓은 뒤 경유점 복귀 → 홈

놓은 자리에서 바로 홈으로 가면 트레이 셀 안에서 옆으로 쓸며 방금 놓은 물체를 친다.
**경유점으로 수직 복귀한 뒤 홈으로** 간다. 루프를 돌 때 다음 사이클이 같은 조건에서
시작하게 하는 목적도 있다. `back: False` 면 이 단계를 건너뛴다.

### 분류를 거리(Z)로 (`--z-split-mm 268`)

길이 기준(`--len-split-mm`)이 계속 실패했다. 09-11 실측:

| | 길이 `L` | 거리 `Z` |
|---|---|---|
| 탄피 | 15.8~16.1mm | **260mm** |
| 탄두 | 11.7~14.3mm | **277~284mm** |

길이는 탄두 14.3 과 탄피 15.8 이 1.5mm 차이로 붙어 있는데 **거리는 17mm 이상 벌어진다.**
같은 평면에 꽂혀 있으면 긴 쪽(탄피)이 카메라에 가깝기 때문이다.

실제로 길이 기준이던 09-11 오전에 **탄피가 탄두로 분류돼 집혔다** (`--kind 탄두` 로
고정했는데도). Z 기준으로 바꾼 뒤에는 `[Z]  (Z 경계 268 에서 10mm)` 처럼 여유까지
로그에 찍히고 오분류가 사라졌다.

> Z 는 절대 거리다. **시작 위치를 다시 잡으면 재측정해야 한다.**
> `--z-split-mm 0` 으로 두면 길이 기준으로 돌아간다.

검출 로그에 판정 근거가 `[Z]` / `[L]` / `[밝기]` 로 찍힌다.

### 중복 검출 제거 (`--dedup-px 15`)

프롬프트를 여러 개(`bullet,metal ring`) 쓰면 한 물체가 프롬프트마다 잡힌다.
게다가 마스크 범위가 달라서(`bullet` 은 물체 전체, `metal ring` 은 링만)
길이가 다르게 측정되고 **분류까지 갈린다** — 같은 물체가 탄피와 탄두로 동시에 나왔다.

```
(365,279) L=15.8mm → 탄피      ← bullet 이 물체 전체를 잡음
(369,284) L=10.6mm → 탄두      ← metal ring 이 링만 잡음, 5px 차이
(369,284) L=10.1mm → 탄두      ← 또 중복
```

중심이 15px 안이면 같은 물체로 보고 **면적이 큰 것**을 남긴다. 큰 마스크가 물체
전체를 덮은 것이라 길이 측정이 정상값에 가깝다.

```
넣기 전  검출 5개 (물체 3개)
넣은 후  검출 3개 — 실제 물체 수와 일치
  탄피 (365,279) area=784px  (+2 중복 제거)
  탄두 (375, 70) area=536px
  탄두 (295, 98) area=494px
```

면적도 종류를 잘 가른다 (탄피 784 / 탄두 494~536px).

### 탄두 정렬 실패 — 시야 차단 (미해결)

탄두 정렬이 **세 번 연속 같은 지점에서 실패**했다. 회차별 오차가 소수점까지 같다.

```
[XY 1] 171.6px → [XY 2] 140.9 → [XY 3] 109.3 → [XY 4] 76.3px → 검출 0개 (40초+)
매 회 dy=-14.2mm (보폭 상한 15mm)
```

그 지점에서 **프롬프트 12개 전부 0개**다. 화면을 떠 보니 격자 트레이와 브래킷만
보이고 물체 형태가 드러나지 않았다. 그나마 잡힌 두 개는 배제 영역 밖의 브래킷·배경
(`x=561~635`, Z=302~443mm)이었다.

원인은 기하 구조다. 카메라가 세로로 57mm 다가가면서 **시선이 셀 안쪽을 비스듬히
보게 되고 셀 벽이 탄두를 덮는다.** 탄두가 15mm 로 짧아 셀 깊이에 거의 잠기기
때문이다 — 탄피 21mm 는 충분히 솟아 있어 같은 조건에서 5회 연속 성공했다.

**프롬프트로 풀 문제가 아니다.** 물체를 셀에서 더 솟게 놓거나, 홈에서 본 좌표로
한 번에 이동(되먹임 포기)해야 한다.

### 깊이 검출 + 첫 선정 합의 — 탄두 정렬 해결 (09-11)

SAM3 만으로는 탄두 정렬이 **네 번 연속 같은 지점에서 실패**했다. 두 가지를 더해 풀었다.

**① 깊이로 찾기 (`--detector depth` / `both`)**

트레이 바닥보다 솟은 덩어리를 찾는다. 색·조명·프롬프트에 의존하지 않아
검은 물체도 잡히고, SAM3 점수가 낮아도 무관하다.

```
09-11 실측 깊이 분포 (트레이 영역)
  320~330mm  29073px  ████████████████  바닥/폼
  310~320mm   6827px  ██████
  290~300mm   1988px
  260~270mm   2478px  물체 높이
→ 바닥 322~326mm / 물체 260~290mm, 25~60mm 차이
```

바닥 깊이를 프레임마다 ROI 분위수(`--depth-floor-pct 75`)로 추정하므로
카메라 높이가 바뀌어도 따라간다. 그보다 `--depth-bump-mm 25` 넘게 얕으면 후보다.

**SAM3 가 `metal ring` 0.052 로 놓친 물체를 깊이로는 찾았다** — 위치도 3px 차이로 일치.

트레이 테두리·격자 리브도 바닥보다 높아 같이 걸리므로 두 조건으로 걸러낸다:

| | 물체 | 격자 리브 | 트레이 벽 |
|---|---|---|---|
| 종횡비 | 1.16 | 1.78 | 3.06 |
| 바닥 위 높이 `h` | 42~43mm | 36mm | 57~65mm |

`--depth-aspect-max 1.6` · `--depth-height-max 45` 로 9개 → 4개까지 줄었다.

**② 첫 선정만 합의 (`--require-both`)**

깊이 단독은 여전히 오검출 3개가 남았고, 그중 하나는 크기가 진짜와 비슷해
면적·길이로 못 갈랐다 (진짜 `area 855 L 20.5` vs 오검출 `area 653 L 18.9`).

**SAM3 와 깊이가 같은 자리를 가리킨 것만 채택**하니 정확히 1개가 남았다.
SAM3 는 점수가 낮아도 위치는 맞히고, 깊이는 형태를 본다 — 서로의 약점을 메운다.

```
깊이 단독   4개 (진짜 1 + 오검출 3)
SAM3 단독   0개 (0.052 로 임계 미달)
합의        1개  ✅
```

**다만 합의를 서보 중에도 요구하면 안 된다.** 카메라가 다가가면 SAME3 가 물체를
못 보기 때문이다 — 실측에서 **깊이는 7회 연속 찾았는데 SAM3 는 7회 연속 0개**여서
합의가 성립하지 않고 멈췄다.

```
[깊이] 후보 11~14개 중 1~3개 통과     ← 깊이는 계속 찾는다
[합의] SAM3 0개 · 깊이 1~3개 → 0개    ← SAM3 때문에 막힌다
```

그래서 **합의는 첫 대상 선정에만** 적용한다 (`_locked["uv"] is None` 일 때만).
한 번 고른 대상은 `track_target` 이 직전 위치로 이어가므로 깊이 단독으로 충분하다.

**결과**

```
~09-11 오후   탄두 정렬 4회 연속 실패 (76~115px 에서 검출 0개)
09-11 최종    [XY] 3회만에 완료 (오차 2.7px ≤ 허용 4.0px)  ✅
              [정렬 완료] TCP = (294.30, -1091.68, -86.61)
```

물체를 화면 중앙 쪽에 놓아 초기 오차를 205px → 41px 로 줄인 것도 함께 작용했다.

**검증된 실행 명령**

```bash
~/sam3_env/bin/python -u sam3_pick_ros2.py --descend --display \
    --detector both --require-both --threshold 0.03 \
    --min-len-mm 0 --sign "+,-" --exclude "430,0,640,480"
```

`--threshold 0.03` 으로 낮춘 이유는 SAM3 를 **위치 확인용으로만** 쓰기 때문이다.
종류 판정은 `--z-split-mm`, 오검출 배제는 깊이 조건과 합의가 맡는다.

### 검은 물체는 검출되지 않는다 (09-11 실측)

밝은 황동색 물체로는 5회 연속 완주했는데, **검은색 물체로 바꾸면 검출이 무너진다.**
라이브 감시로 25회 이상 측정한 결과다 (`watch_detect.py`, 1.5초 주기, 변화 시만 출력).

```
검은 물체 점수    0.08 ×5  0.09 ×2  0.11 ×2  0.17 ×3  0.18 ×2  0.19  0.23  0.43  0.44  0.52  0.53
                 중앙값 0.17   최소 0.08   최대 0.53
밝은 탄피 점수    0.42~0.70 (안정)
```

| | 밝은 탄피 | 검은 물체 |
|---|---|---|
| SAM3 점수 | 0.42~0.70 안정 | **0.08~0.53, 5배 이상 요동** |
| `--threshold 0.15` 통과율 | 거의 100% | **약 50%** |
| 위치·면적 | 안정 | 안정 (513~573px) — 위치는 정확하다 |
| 깊이 `Z` | 안정 (260mm) | **`nan` 3회** — 적외선 반사가 약하다 |
| 잡은 프롬프트 | `metal ring` | `bullet` / `metal ring` 둘 다 |

**위치는 정확한데 신뢰도만 부족하다.** 그래서 임계값 조정으로는 풀리지 않는다:

- `0.15` — 0.08~0.11 구간을 놓친다 (약 절반)
- `0.08` — **면적 27023px / 51514px 오검출**이 나온다 (화면의 9~17%)
- 그 사이 값 — 여전히 절반은 놓친다

점수가 0.52~0.53 까지 오른 순간이 두 번 있었으나 2초를 못 갔다. 조명·각도가 잠깐
좋아진 것으로 보이며, **안정적인 조명을 고정하면 유효할 가능성**이 여기서 나온다.

> `--max-area` 를 이때 추가했다 (기본 5000px). 임계값을 낮춰 검은 물체를 잡으려면
> 큰 오검출을 막을 상한이 반드시 필요하다.

**학습된 YOLO 모델(`SAM3/PT/best (1).pt`)도 검은 물체에는 안 된다.** 아래 참고.

### 학습된 YOLO 모델 — 로봇 카메라에 전이되지 않는다

`SAM3/PT/best (1).pt` 는 이 작업 전용으로 학습된 모델이다.

```
yolo26n, detect, 100 epochs, imgsz 640
클래스   0: bullet-detect   1: cartridge (탄피)   2: warhead (탄두)
성적     precision 0.920  recall 0.876  mAP50 0.924  mAP50-95 0.760
```

클래스로 탄피/탄두를 **직접 분류**하니 길이·거리 추정을 대체할 수 있어 보였다.
그런데 로봇 카메라 영상에서는 전혀 검출되지 않는다.

| 입력 | 결과 |
|---|---|
| 휴대폰 사진 원본 4000x3000 | ✅ `warhead 0.72` / `cartridge 0.62`, 4~6개 |
| 같은 사진 640x480 축소 | ⚠️ `warhead 0.18~0.29`, 1~2개 |
| **로봇 카메라 640x480** | ❌ **0개** (conf 0.05 까지 낮춰도) |
| 추론 해상도 상향 (`imgsz` 640~2048) | ❌ 0개 |
| 2~4배 업스케일 후 추론 | ❌ 0개 |
| 중앙 35% 크롭 → 640 확대 | ⚠️ `cartridge 0.34` — 크롭만 통한다 |
| 타일링 (25~35% 창, 겹침 50%) | ⚠️ 검출되나 **상자 크기·위치가 실제와 안 맞음** |

**해상도가 아니라 물체가 프레임에서 차지하는 비율이 관건이다.** 학습 데이터가 근접
사진이라 260mm 거리의 20~30px 물체로 전이되지 않는다. 타일링으로 억지로 맞추면
검출 상자가 `22x120px`·`122x119px` 처럼 왜곡되고 좌표가 SAM3 와 어긋나
서보에 쓸 수 없다 (서보는 픽셀 중심이 정확해야 한다).

`ultralytics` 는 `--no-deps` 로 설치했다 — 그냥 설치하면 torch 를 건드려
SAM3(2.11.0+cu130)가 깨진다. 부족한 것만 따로 넣었다 (`scipy` `py-cpuinfo` `matplotlib`).

**절충안**: 위치는 SAM3, 종류는 YOLO. SAM3 가 찾은 위치 주변을 잘라 확대해 YOLO 에
주면 YOLO 는 학습 조건과 같은 근접 영상을 보게 되고, **클래스만 채택하므로 상자
왜곡이 무관해진다** (`hybrid_test.py`). 밝은 물체로는 아직 검증하지 못했다 —
시험하려던 시점에 장면이 검은 물체로 바뀌어 SAM3 단계에서 이미 0개였다.

### 프롬프트 10장 평가 — 결론은 "쓸 게 없다"

사진 10장(4000x3000, 640 폭으로 축소)에 프롬프트 15개를 걸어 점수를 냈다.

| 프롬프트 | 평균 점수 | 검출 0인 장수 | 평균 마스크 수 |
|---|---|---|---|
| `small metal object` | 0.911 | 0 | **83.3** |
| `screw head` | 0.567 | 0 | 36.6 |
| `brass` | 0.281 | 0 | 8.0 |
| `metal object in cell` | 0.231 | 0 | 30.7 |
| `bullet` | 0.166 | 0 | 13.1 |
| `circle` | 0.148 | 0 | 5.2 |
| `metal ring` | 0.144 | 0 | 4.9 |
| `brass ring` | 0.047 | 0 | 1.4 |
| `pointed metal` | 0.044 | 1 | 8.6 |
| `bullet tip` | 0.043 | 4 | 1.0 |
| `cone` | 0.034 | 4 | 1.6 |
| `metal cylinder` | 0.027 | 2 | 1.5 |
| `projectile` · `cartridge case` · `bullet casing` | 0.000 | **10** | 0.0 |

**점수와 선택성이 반대로 간다.** 포괄적인 표현일수록 점수가 높고 오검출도 많다 —
물체가 1개인 장면에서 `small metal object` 가 83개를 잡는다(격자 셀·프레임·브래킷).

그리고 **이 순위를 로봇 화면에 옮길 수 없다.** 같은 `metal ring` 이 사진에서 0.144,
로봇 화면에서 0.703 으로 5배 차이다. 조명·각도·센서가 달라 점수 척도 자체가 다르다.

얻은 것은 두 가지뿐이다:

- 탄약 용어 계열(`projectile`·`cartridge case`·`bullet casing`)은 확실히 안 된다
  (사진 10장 + 로봇 화면 모두 0)
- 탄두 형태 표현(`bullet tip`·`cone`·`pointed metal`)도 기대와 달리 나빴다

> SAM3 는 텍스트 프롬프트 모델이다. **사진 10장으로 가중치를 고칠 수는 없다.**
> 이 평가의 용도는 프롬프트 후보를 걸러내는 것뿐이다.

#### 조기 통과 — 숫자로 본 증거

같은 명령을 고치기 전후로 돌린 값이다. 세 지점 모두 허용치 **바로 아래**에서 통과했다.

```
                        고치기 전            고친 후
하강 목표차   (-0.65, +1.54, +1.73) mm   (-0.05, -0.02, +0.04) mm
들어올리기         +98.21 mm                 +99.95 mm
놓기 목표차        +2.99 mm                  +0.13 mm
박기 목표차        +0.04 mm                  +0.04 mm
그리퍼 17         done=1 (빈손)            done=2 (물림)
```

박기만 고치기 전에도 정확했던 것이 결정적 단서였다 — 직전 이동 거리가 4.2mm 뿐이라
감속 구간이 짧아 우연히 제대로 멈췄다. **로봇의 정상 상태 오차가 아니라 코드의 조기
판정**이라는 뜻이다.

> ⚠️ 꽂힌 탄두는 리브 위로 물릴 구간이 2~3mm 뿐이다. 1.8mm 부족만으로 헛닫힘이 된다.
> 탄피는 잡을 높이 여유가 커서 같은 버그를 안고도 5회 연속 완주했다 —
> **한 종류가 되는 것이 판정 로직의 검증이 아니다.**

#### 탄두 파지 — 정렬은 원인이 아니다 (09-11 결론)

`--no-servo` 로 **검출 없이** 이미 정렬된 자리에서 하강시켜 갈랐다. 사용자가 눈으로
중앙 정렬을 확인한 자리였고, 하강 정확도 0.09mm 였는데도 빈손이었다.
**정렬·검출·도달 판정은 모두 원인에서 배제된다.**

파지 6회를 정렬 TCP 의 X 로 늘어놓으면 경계가 뚜렷하다.

```
성공   X = 318.27   329.07   333.65               (모두 318 이상)
실패   X = 304.64   315.45   315.61   315.78      (모두 316 이하)
```

**예측을 세워 검증했다.** 7번째는 하강 전에 `X = 315.45` 를 읽고 "빈손이 나와야 한다"
고 예측한 뒤 내렸고, `done=1` 로 예측이 맞았다 (하강 정확도 0.08mm).
7회 전부 예외 없이 이 경계로 갈린다 — 우연이 아니다.

현재 위치만 읽는 유틸 (로봇을 건드리지 않는다):

```bash
~/sam3_env/bin/python scripts/pose.py     # TCP · 관절 · 그리퍼
```

**X ≈ 317 에서 깨끗하게 갈린다.** 상대 보정값이 정확하면 정렬 위치와 무관해야 하므로,
탄두 보정값 `(38.23, -87.87, -200.99)` 은 실측 조건(X ≈ 325 근방)에서만 맞고
X 가 낮아지면 손가락이 물체를 벗어난다는 뜻이다.

물체 2개가 서로 다른 격자 칸에 꽂혀 있으니 어느 칸을 고르느냐가 정렬 X 를 결정한다.
그래서 같은 명령으로 실행마다 성공과 실패가 갈렸다.

> ⚠️ **한 위치에서 1회 실측한 보정값을 위치 무관 상수로 쓰면 안 된다.**
> 탄피는 놓는 자리가 고정이라 이 문제가 드러나지 않았다.

진단 명령 (검출·정렬을 건너뛰고 파지만 본다):

```bash
~/sam3_env/bin/python -u sam3_pick_ros2.py --no-servo --kind 탄두
```

#### 정렬되면 검출이 죽는다 — 기다리지 않고 하강한다

`--require-both` 를 매 프레임 합의로 되돌린 뒤 증상이 그대로 재현됐다.

```
[XY 3] 오차 8.1px (허용 4.0) → 상대이동 dx=+0.4 dy=+2.2 mm
[대기] 정렬 중 대상이 사라졌습니다 — 다시 나타날 때까지 기다립니다
[합의] SAM3 0개 · 깊이 1개 → 합의 0개     ← 깊이는 계속 찾는데 SAM3 가 0
... 104초 경과, 검출 0개
```

물체가 화면 중심으로 올수록 위에서 수직으로 내려다보게 되어 링만 남고 SAM3 점수가
떨어진다 (09-10 실측: `bullet` 0.029). **맞을수록 검출이 죽는다.**

그래서 대상이 사라졌을 때 **이번 보정으로 남을 오차**를 계산해 허용치 안이면
기다리지 않고 하강으로 넘어간다.

```
남을 오차 = 오차 x (1 - 실제 명령 비율)
실제 명령 비율 = |명령한 보폭| / |오차를 전부 없앨 보폭|
```

`--gain 0.6` 이나 `--max-step-mm` 상한 때문에 한 번에 다 못 줄이는 것을 반영한다.
위 로그에 대입하면 갈린다.

```
[XY 1] 49.1px → 명령 13.8 / 전체 23.0mm = 60%  → 남을 오차 19.6px > 4.0  → 기다린다
[XY 3]  8.1px → 명령  2.2 / 전체  3.8mm = 59%  → 남을 오차  3.3px <= 4.0  → 하강한다
```

#### 탄두 파지 5회 기록 — 위치 의존이 남아 있다

`settle()` 수정 후 5회 중 3회 성공. 파지 지점으로 늘어놓으면 실패가 한쪽에 몰린다.

```
결과   파지 지점 (X, Y)        정렬    하강 목표차          그리퍼
성공   (367.26, -1157.00)     4회    (-0.05,-0.02,+0.04)  done=2  3.9초
성공   (371.87, -1158.48)     4회    (-0.01,-0.04,+0.04)  done=2  3.9초
성공   (356.44, -1162.81)     3회    (-0.07,-0.00,+0.06)  done=2  3.9초
실패   (353.98, -1158.58)     9회    (-0.03,-0.04,+0.07)  done=1  4.3초
실패   (342.83, -1170.15)     4회    (-0.04,-0.01,+0.04)  done=1  4.3초
```

**실패 2회가 X 하한·Y 외곽이다.** 상대 보정값이 정확하면 위치는 무관해야 하므로,
이건 보정값에 위치 의존 오차가 남아 있다는 뜻이다. 보정값을 측정한 정렬 기준
`(286.748, -1160.084)` 에서 계산되는 파지점은 `Y ≈ -1248` 이고, 지금 물체 위치
`(-1157 ~ -1170)` 와 **80~90mm 떨어져 있다.**

파지 소요 시간도 판정에 쓸 수 있다 — **성공은 3.9초, 실패는 4.3초**다.
물체에 걸려 일찍 멈추면 짧고, 끝까지 닫히면 길다. `done` 값과 같은 정보지만
독립적으로 확인된다.

한 번(9회 정렬)은 마스크가 조각이었던 별개 원인이다.

```
성공 마스크   L=16.2mm area=759px
실패 마스크   L= 9.7mm area=348px   ← 링 테두리 조각. 무게중심이 물체 중심이 아니다
```

`--threshold 0.03` 으로 내린 대가다. 조각 마스크를 중심에 맞추면 픽셀 오차는
수렴하지만 손가락은 물체 옆으로 내려간다. `--min-area 300` 은 348px 를 통과시킨다.

> ⚠️ 남은 진단은 로그로 안 된다. `--grip-offset "38.2,-87.9,-150"` 으로 **50mm 위에서
> 멈춰 손가락과 물체의 X/Y 어긋남을 눈으로 재는 것**이 유일한 방법이다.

#### 깊이 검출은 왜 못 쓰나 (09-11 결론)

물체와 격자 리브가 **같은 높이**라 "바닥보다 솟음" 기준으로는 원리적으로 안 갈린다.
게다가 코드가 `MORPH_CLOSE` 를 쓰기 때문에 격자 구멍까지 메워져 트레이 한 판이
단일 덩어리가 된다 — 문제를 악화시키는 방향이었다.

`MORPH_CLOSE` 를 `MORPH_OPEN` 으로 바꿔 리브를 침식해 없애는 것도 시도했으나
**리브 교차점이 물체만큼 굵어서** 실패했다.

```
OPEN  5x5 : 격자가 덩어리째 살아남음 (4653px, 3610px)
OPEN  7x7 : 물체 2개가 리브와 뭉쳐 하나로 (317,239) 63x59
OPEN  9x9 : 교차점 조각이 물체와 같은 크기로 29개 남음
OPEN 11x11: 물체도 같이 깎여나감
```

같은 프레임에서 SAM3 단독은 깨끗했다.

```
(304,255) 0.068   ← 물체 1
(330,227) 0.064   ← 물체 2
(331,229) 0.041   ← 물체 2 중복 (--dedup-px 15 로 제거)
나머지 5개는 전부 x >= 430 배제영역
```

> ⚠️ 09-11 초반에 깊이 합의가 한 번 통한 것은 **운이었다.** 트레이가 프레임에서
> 조금만 움직여도 덩어리 분할이 완전히 달라진다. 재현성이 없다.

**깊이를 쓸 올바른 방법은 독립 검출기가 아니라 Z 범위 게이트다** (미적용).
실측 근거: 실제 물체 281~283mm / 바닥·브래킷 오검출 298~323mm / 손 170~220mm.
SAM3 결과를 `Z ∈ [255, 295]` 로만 걸러도 리브 문제를 안 건드리고 오검출이 빠진다.

#### 트레이 깊이 실측 (홈 위치, 09-11)

```
흰 바닥              326 mm
매트                 319 mm
트레이 테두리        267 ~ 292 mm
격자 리브 top        285 ~ 287 mm
물체(탄두) top       285 mm      ← 리브와 같은 높이
빈 격자 칸           nan (검은 구멍, 깊이 무효)
```

물체가 리브 위로 솟지 않으므로 `--depth-bump-mm` / `--depth-height-max` 조합으로는
물체와 리브를 가를 수 없다. 구분되는 신호는 **빈 칸은 깊이가 무효(nan)이고 막힌 칸은
유효**라는 것뿐이다. 트레이 안 유효 깊이 비율은 32% 였다.

### 코드에서 고친 것

- **로봇 응답 코드 검사** — 이전에는 `send()` 반환값을 버려서 14/74/154 가 나와도 조용히 넘어갔다.
  지금은 0 이 아니면 그 자리에서 멈추고 코드를 출력한다. 이 하나만 있었어도 위 문제들을 몇 시간 일찍 찾았다

- **야코비안 학습 제거** — 픽셀→mm 를 깊이와 초점거리로 직접 구한다 (`mm = px * Z / fx`).
  학습 단계가 없어졌고, 물체가 멀어지면 보폭이 자동으로 커진다

### 카메라 — 09-10 에 원인 규명

```bash
grip.py <위치>              # 그리퍼만. 작을수록 닫힘 (35 개방 / 22 파지)
```

### 남은 작업 (우선순위 순)

1. **탄두 시야 차단** — 가장 큰 걸림돌이다. 두 방향뿐이다:
   - 탄두를 셀에서 더 솟게 놓는다 (대가 없음. 탄피가 성공한 조건)
   - 홈에서 본 좌표로 한 번에 이동한다 (되먹임 포기, `--max-step-mm` 상향 필요)

2. **박기 단계 균등화** — 지금은 이동량이 2.42 / 0.30 / 1.61mm 로 고르지 않다.
   `tol` 과 Z 편차(+1.5mm)의 관계 때문이다. 최종 깊이는 맞으니 급하지 않다

3. **브래킷 배제를 좌표 말고 다른 방법으로** — 지금은 `--exclude "430,0,640,480"` 로
   화면 오른쪽을 통째로 뺀다. 카메라가 움직이면 무효가 된다. 프롬프트를 좁히거나
   깊이/평면 기준으로 거르는 쪽이 낫다

3. **`--len-split-mm` 재설정** — `metal ring` 프롬프트에서는 링만 잡혀 길이가
   절반이 된다 (10.7mm). 지금 17 은 `bullet` 기준이라 `--kind` 를 쓰려면 다시 재야 한다

5. **USB 커넥터 고정** — 원인은 규명됐고 조치가 안 됐다

6. **격자 트레이에서의 깊이** — 물체 위치의 깊이가 무효가 되는 경우가 있다
   (물체 ±5px 유효 78% / ±20px 23%). 지금은 통과하지만 여유가 없다

6. **다른 스크립트 코드 정리** — `sam3_pick_ros2.py` 는 09-10 에 정리했다. 남은 것:
   - 분류 함수(`shape_feats`)가 `run_sam3_depth.py` / `sam3_center.py` / `autolabel.py` 에 복제돼 있다
     (알고리즘은 동일, 반환값만 다름). `center_brightness`·`local_plane_height` 는 두 파일이 바이트 동일
   - `run_sam3_depth.py` 의 죽은 옵션: `--stand-mm` `--peak-mm` `--aspect-th` `--split-mm` `--global-plane` (참조 0회 확인)
   - `grasp_info()` 가 국소 평면이 아닌 전역 평면을 쓴다 (화면 높이와 JSON 높이가 갈린다)

### 하면 안 되는 것

- **관절 차이를 보정값으로 쓰기** — 위치가 바뀌면 무의미하다. TCP 차이(mm)만 상수다
- **`--roi` / `--exclude` 에 배치 전용 좌표를 기본값으로 박기** — 카메라를 옮기면 엉뚱한 영역을 지운다
- **로봇 응답 코드 무시** — `send()` 반환값이 0 이 아니면 반드시 멈춘다
- **타임아웃을 고정값으로 두기** — 5% 속도에서 194mm 는 81초다. 거리에 비례해서 잡는다
- **매 프레임 Z 다시 재기** — X/Y 서보는 Z 를 안 움직인다. 선정 시 1회면 되고,
  다시 재면 측정 편차(260~285mm)가 보폭만 흔든다
- **그리퍼 완료를 `done != 0` 으로만 판단** — 명령 직후의 값은 직전 동작의 잔상이다.
  `0` 을 한 번 본 뒤부터 완료로 인정한다
- **먼 거리를 경유점 없이 카테시안으로 이동하기** — 09-10 에 230mm 직행으로
  626mm 어긋나 6축이 슬레이브에서 탈락하고 컨트롤 박스 전원 재투입이 필요했다.
  경유점을 거치고, 두 지점의 자세를 같게 둔다
- **`rx` 부호가 뒤집히는 자세를 목표로 주기** — `+179.77` 과 `-177.40` 은
  물리적으로 2.8도지만 숫자로는 357도다. 파지 자세를 그대로 유지하는 게 안전하다
- **매 프레임 대상을 다시 고르기** — 중복 검출 사이를 오가며 회차가 3배로 늘어난다.
  `track_target` 으로 한 번 고른 물체를 붙잡는다
- **X·Y 를 순차로 맞추기** — Y 를 맞추는 동안 X 가 틀어져 재정렬이 매번 필요하다.
  동시(`--simultaneous`)가 회차 절반 이하이고 정밀도도 낫다
- **속도를 바꾸고 보정값을 그대로 두기** — 가감속 편차가 속도에 따라 달라진다.
  보정값 판단에 그 편차가 섞여 있다
- **프롬프트를 물체 이름으로만 짓기** — SAM3 는 이 탄피를 "탄약"으로 인식하지 않는다.
  `cartridge case`·`bullet casing`·`shell casing`·`ammunition` 은 모두 0개다.
  **보이는 형태**를 쓴다 (`metal ring`). 그리고 자세에 따라 맞는 표현이 달라지므로 병행한다
- **검출 0개를 카메라 문제로 단정하기** — 09-10 에 130초 무한 대기의 원인은
  프롬프트였고, 그때 물체는 이미 화면 중심 5px 안에 있었다.
  **화면을 떠서 눈으로 확인**하는 게 가장 빠른 진단이다
- **`Robot.RPC` 로 직접 붙기** — `ros2_cmd_server` 와 제어 경로가 갈려 명령이 거부된다.
  그리고 `MoveCart(desc_pos=...)` 는 카테시안이라 관절값을 넣으면 안 된다
