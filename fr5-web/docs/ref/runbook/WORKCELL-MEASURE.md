# 작업셀 재기 — 상판과 벽을 로봇 좌표계로 옮긴다

분류: **SSOT**. 조건 12(작업영역)의 빈 절반을 채우는 **일회성 실측** 절차다.
작업대를 옮기거나 로봇을 다시 고정하면 그때 다시 한다.

**왜 자로 잰 숫자로 안 되나** — 자는 바닥 기준이고 게이트는 **로봇 베이스 기준**이다.
둘을 잇는 변환이 없다. 로봇 자신에게 짚게 하면 변환이 필요 없다.

## ⚠ 함정 둘 — 읽는 값은 **손끝**이고, 좌표계는 **베이스가 아니다**

### ~~우리가 읽는 값은 플랜지다~~ → **틀렸다. 손끝이다** (2026-08-07 실기 readback)

`toolCoordId: 0` 이 "툴 없음"이라 플랜지일 것이라고 적어 뒀는데, 실기
`GetCurToolCoord` 되읽기가 **`[0, 0, 135, 0, 0, 0]`** 이다. 누군가 툴 0 에 그리퍼 길이를
넣어 뒀고, 그래서 `/state.tcpMmDeg` 는 **손끝**이다.

결과적으로 아래 "기준이 같으면 상쇄된다" 는 여전히 성립하지만, **전제가 틀린 채로
남아 있으면 다음 사람이 135mm 를 두 번 빼거나 안 뺀다.**

### 좌표계가 베이스가 아니다 — 이게 더 크다

`frame: {toolId: 1, userId: 1}` 이고 **`user1` 은 베이스에서
`(−401.8, +497.3, +342.1)` 떨어져 있다** (회전 0 · `GetWObjCoordWithID(1)`).
그래서 여기서 얻는 모든 좌표는 **user1 기준**이다. 화면에 그리려면 환산해야 한다
(`/state.coordDefs` · `Shared/view3d/workspace.js` `toBase()`).

2026-08-07 에 이걸 몰라서 하루를 잃었다 — 전말 `evidence/2026-08-07/workcell-remeasure.md`.

**그래도 괜찮다 — 잴 때와 판정할 때 기준이 같으면 오프셋은 상쇄된다.**
핑거를 상판에 닿게 하고 그때의 **플랜지 z** 를 기준선으로 삼으면, 게이트도 플랜지 z 로
판정하므로 손끝까지의 거리를 몰라도 성립한다.

**조건 하나 — 4점을 전부 같은 손목 자세로 잰다** (핑거가 수직 아래를 보게).
기울이면 손끝이 더 내려가는데 플랜지는 안 내려가 기준선이 거짓이 된다.

**천장** — 그래서 이 게이트는 "손목 수직" 자세 전제다. 기울이는 동작을 넣으려면
툴 좌표계 캘리브레이션이 선행이다 (`Vision/AGENTS.md` ⛔ 선행 ①).

## 준비

- **로봇 옆에 사람** (하드 룰 3) · 펜던트 사용 가능
- 화면에서 조종권 → 현장확인 → **ARM**(서보 ON) → 헤더 안전 바의 **`수동으로`** (D72).
  **DISARM 하지 않는다** — 드래그 티칭은 서보가 켜져 있어야 된다
- 브리지는 연결된 채로 둔다 — 값은 `20004` 실시간 스트림이라 펜던트와 별개로 흐른다.
  수동 모드에서 우리 조그·moveJ 는 어차피 거부되므로 로봇이 저절로 움직일 일은 없다

## 읽는 명령 (한 점마다 한 번)

```bash
rtk proxy curl -s http://192.168.30.240:5055/state \
 | python3 -c 'import json,sys;s=json.load(sys.stdin);print(s.get("mode"),s["safety"]["inDragTeach"],[round(x,1) for x in s["tcpMmDeg"]])'
```

출력은 `모드 드래그중 [x y z rx ry rz]`. **`드래그중` 이 `True` 가 아니면 그 값은 버린다.**

## 순서

1. 헤더의 **`수동으로`**. 위 명령의 첫 값이 `0` → `1` 로 바뀌는지 본다
   — **이게 우리가 실제로 읽고 있다는 증거다.** 안 바뀌면 여기서 멈춘다
2. 펜던트에서 **드래그 티칭 ON** (인에이블 스위치를 쥔 채로). 드래그가 안 되면 펜던트
   조그로 옮겨도 된다 — 재는 값은 같다
3. 아래 4점을 **같은 손목 자세**로 짚고 각각 한 번씩 읽는다

| 점 | 어디 | 무엇이 나오나 |
|---|---|---|
| P1 | 상판 모서리 — 로봇에서 **가장 가까운** 쪽. 핑거를 상판에 **닿게** | 원점 + 높이 기준선 |
| P2 | P1 에서 **긴 변(808mm)** 따라 반대 모서리 | x 축 방향 |
| P3 | P1 에서 **짧은 변(598mm)** 따라 모서리 | y 축 방향 |
| P4 | 벽면에 한 점 (핑거를 벽에 살짝) | 벽 평면 |

4. 펜던트 드래그 **OFF** → **자동 모드**. 첫 값이 `0` 으로 돌아오는지 확인

## 그 자리에서 교차검증 — 안 맞으면 다시 잰다

```
|P2 − P1| ≈ 808 ± 10 mm
|P3 − P1| ≈ 598 ± 10 mm
(P2−P1)·(P3−P1) ≈ 0        ← 직각인가
```

⚠ **이 두 기준값을 2026-08-08 에 고쳤다** (옛 `858 × 580`). 정본은
`Shared/data/workcell.js` `CART` 이고, 여기는 그걸 따라간다 — **여기서 값을 새로 만들지
않는다.** 옛 858 은 줄자값이 아니라 게이트 상자(로봇이 795 까지만 짚고 나머지를 넓게 외삽한
값)를 옮겨 적은 것으로 보인다. 기준값이 틀리면 이 절의 ±10mm 교차검증이 **맞게 잰 것을
틀렸다고 되돌려보낸다** — 실제로 858 로는 줄자 808 이 50mm 밖이라 영영 통과 못 했다.

**안 맞는 채로 넘어가지 않는다.** 틀린 작업영역은 없는 것보다 나쁘다 — 사람이 막혔다고
믿는데 안 막힌다.

## 벽은 유효기간이 있다

작업대에 **캐스터가 달려 있다.** 상판은 로봇과 함께 움직이므로 P1~P3 은 영구하지만,
**P4(벽)는 작업대를 굴리는 순간 거짓이 된다.** 그래서 벽은 잰 시각과 함께 저장하고
오래되면 화면이 다시 재라고 말한다.
