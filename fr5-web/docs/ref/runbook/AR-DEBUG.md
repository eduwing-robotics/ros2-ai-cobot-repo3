## 원칙 — **폰에는 콘솔이 없다**

손에 든 폰에서 `console.log` 는 볼 수 없다. 원격 디버깅은 되지만 케이블·설정이 필요하고
현장에서 마커를 들고 움직이며 쓰기 어렵다.

→ **필요한 숫자를 화면에 띄운다.** 그게 `⚙` → **진단 수치 보기** 다.

## 1. 화면 진단판 읽는 법

`⚙` 버튼 → **진단 수치 보기**. 또는 URL 에 `?diag=1`.

```
fps 28   인식률 74%   놓침 12회 / 430프레임
지금  원시 인식 · 표시 ON   거리 1.35m
카메라 640×480   검출캔버스 640×480
마커 #2 · 143mm · 스케일 6.99배 · 억제 중
```

| 숫자 | 뜻 | 나쁜 값이면 |
|---|---|---|
| **fps** | 렌더 프레임 | 15 미만이면 폰이 버거워 검출도 같이 나빠진다 → 그리퍼 몸통 경량화 |
| **인식률** | 전체 프레임 중 마커를 잡은 비율 | 50% 미만이면 인쇄 대비·조명 문제. §3 참조 |
| **놓침** | 잡고 있다가 놓친 횟수 | 이 숫자가 오르는 만큼 깜빡인다. **억제를 올린다** |
| **원시 / 표시** | 원시=이번 프레임 검출 · 표시=화면에 보이는 상태 | 원시가 자주 꺼지는데 표시가 켜져 있으면 **억제가 일하는 중**이다 (정상) |
| **거리** | 카메라 ↔ 마커 실거리 | "몇 m까지 되나"를 재는 값. 마커 크기가 정확해야 맞다 |
| **카메라 / 검출캔버스** | 영상 해상도 / 검출에 쓰는 해상도 | 320×240 이면 빠르지만 원거리에 불리 |
| **스케일** | `1000 / 마커mm`. 로봇 크기를 결정 | 로봇이 크거나 작으면 마커 크기가 틀린 것 |

**거리 값이 가장 쓸모 있다.** 마커를 들고 뒤로 물러나며 몇 m에서 인식이 끊기는지 바로 읽힌다.

## 2. URL 파라미터 — 파일을 고치지 않고 값 바꾸기

```
?mm=143     마커 실측 크기(mm). 로봇 크기를 결정한다
?bc=2       바코드 번호. **인쇄물과 같아야 한다**
?sm=off     깜빡임 억제. off·low·mid·high (한글 없음·약·중·강 도 됨)
            **폰에서 URL 에 한글 타이핑은 고통이므로 영문을 쓴다**
?diag=1     진단 수치 켜고 시작
?cv=640     **검출 캔버스 폭**(240~1280). 없으면 AR.js 자동 — 폰에서 320 을 고른다.
            검출 한계가 "마커가 검출 캔버스에서 24px" 이라 **이 값이 곧 검출 거리**다.
            올리면 픽셀이 4배라 fps 를 먹는다. 진단판의 `검출캔버스` 와 `fps` 를 같이 본다.
?log=1      진단 수치를 dev 서버로 보내 `.diag/<날짜>.jsonl` 에 쌓는다 (**dev 전용**).
?tag=80mm-1m  그 로그에 붙일 구간 이름. 마커·거리를 바꿀 때 같이 바꾼다
```

예) `https://<주소>/ar.html?mm=143&bc=2&sm=high&diag=1`

**URL 값이 저장값을 이긴다.** 링크로 "이 값으로 열어봐"를 넘길 수 있다.
`⚙` 로 손으로 바꾼 값은 그 폰에 저장돼 다음에도 유지된다.

### 배포 기본값은 `.env` 에서 온다

URL·`⚙` 는 **그 폰에서만** 바뀌는 임시값이다. 모두에게 적용되는 기본값은 `.env` 다.

```bash
vi .env                            # FR5_MARKER_MM · FR5_MARKER_BARCODE 등
node scripts/build/config.mjs      # Shared/data/config/*.json 생성
```

`Shared/data/config/*.json` 은 **산출물이다 — 직접 고치지 않는다.** 고치면 게이트가 잡는다.
값이 범위를 벗어나거나 바코드 원본이 없으면 **생성 자체가 멈춘다** —
번호가 틀리면 화면에 아무것도 안 뜨는데 콘솔 에러도 없어서, 미리 막는 편이 싸다.

## 3. 증상 → 원인

| 증상 | 먼저 볼 것 | 원인·해결 |
|---|---|---|
| **검은 화면** (권한 허용 후) | 상단 상태 문구 | `카메라 …×…` 가 보이면 카메라는 열린 것 → 표시 문제. `body` 에 불투명 배경이 있으면 영상이 가려진다 (D13). 배경은 `html` 에만 |
| **카메라 여는 중** 에서 멈춤 | — | 권한 거부 또는 HTTPS 아님. 주소가 `https://` 인지 확인 |
| **아무것도 안 뜸** (영상은 보임) | 진단판 `인식률` | 0%면 ① `bc` 가 인쇄물과 다름 ② 대비 부족. **번호 불일치가 가장 흔하다** |
| **깜빡임** | 진단판 `놓침` | 억제를 **중 → 강**. 그래도 심하면 대비·조명 (§4) |
| **로봇이 너무 크거나 작음** | 진단판 `스케일` | `mm` 이 인쇄물 실측과 다름. 자로 검은 사각형을 재서 `⚙` 에 넣는다 |
| **로봇이 마커에서 밀림** | — | `#arjs-video` 크기를 CSS로 건드리면 영상↔투영 대응이 깨진다 (D13). 건드리지 않는다 |
| **한참 기다려야 뜸** | — | 정상이다. 검출기가 첫 인식까지 수십 프레임을 먹는다 (실측 1~36 프로브) |

## 4. 깜빡임 — 억제 말고 남은 수단

억제(`?sm=강`)는 **증상을 가린다.** 근본은 검출률이다.
실측에서 검출을 결정하는 것은 크기가 아니라 **흑백 명도차**였다 —
약 130(0~255) 미만이면 크기와 무관하게 실패한다
(`archive/evidence-2026-07/2026-07-30/marker-detect.md`).

효과 순서대로:

1. **조명을 고르게.** 마커에 직접 반사광이 들어오지 않게. 광택지면 무광으로 다시 인쇄
2. **평평하게.** 딱딱한 판에 붙인다. 휘면 사각형 검출이 깨진다
3. **진한 인쇄.** 토너 절약 모드를 끈다. 검정이 회색으로 나오면 실패한다
4. **가까이.** 진단판 거리를 보며 인식률이 안정되는 거리를 찾는다
5. **폰을 두 손으로.** 흐림 3px에서 최소 검출 크기가 16→24px로 나빠진다

## 6. 화면 녹화 — 겹쳐 보이는 그대로 남기기

⚙ 조정판의 **[● 녹화]**. 카메라 영상과 3D 겹침을 합쳐 mp4 로 떨군다.
폰 앨범으로 바로 보내거나(공유 시트) 내려받는다. **3분이면 스스로 멈춘다.**

**폰 내장 화면 녹화와 무엇이 다른가** — 버튼바·진단판이 **안 찍힌다.**
합치는 것이 영상과 WebGL 캔버스 둘뿐이라 HTML UI 가 애초에 안 들어간다.
반대로 **진단 수치를 영상에 남기고 싶으면 폰 내장 녹화를 써야 한다.**

**함정 셋**

- 캔버스만 `captureStream` 하면 **로봇만 있고 배경이 빈 영상**이 나온다.
  카메라는 뒤에 깔린 별도 `<video>` 다 (D13)
- 합성은 **`renderer.render()` 바로 다음**에서만 된다. `preserveDrawingBuffer: false` 라
  애니메이션 루프 밖에서 캔버스를 읽으면 빈 화면이다
- **녹화 중에는 fps 가 떨어진다** (프레임마다 한 장 더 그리고 인코딩한다).
  녹화본의 끊김을 실제 성능으로 읽지 않는다 — 수치는 `[측정 30초]` 가 정본이다

근거와 확인 안 한 범위는 `archive/evidence-2026-07/2026-07-31/ar-record.md`.

## 7. 자동화(에이전트) 환경의 한계 — 실제로 막힌 것들

Claude/MCP 탭은 **백그라운드**(`document.visibilityState === 'hidden'`)라 아래가 안 된다.
AR을 자동으로 검증하려 할 때 여기서 시간을 버렸다.

| 안 되는 것 | 증상 | 우회 |
|---|---|---|
| 카메라 권한 | `getUserMedia` 가 응답 없이 대기. `video` 요소가 생기지 않고 콘솔 에러도 없다 | **폰·사람이 해야 한다.** 자동으로는 못 넘는다 |
| `requestAnimationFrame` | 아예 안 불린다 → 검사가 영원히 멈춤 | 동기 호출로 바꾼다 |
| `setTimeout(0)` | 1초로 묶인다 | 같음 |
| CSS `transition` | 진행되지 않아 **중간 상태**가 찍힌다 | 검증 중 `*{transition:none}` 주입 |
| `img.decode()` | resolve 되지 않는다 | `fetch → createImageBitmap → drawImage` |
| 스크린샷 | AR 페이지 2개를 iframe 에 띄우면 렌더러가 멈춘다 | 한 번에 하나만. 수치로 판정 |

**미디어쿼리를 시험할 때** 창 리사이즈는 안 먹는다. 좁은 `iframe` 을 쓰면 자기 뷰포트를
가지므로 미디어쿼리가 실제로 발동한다.
