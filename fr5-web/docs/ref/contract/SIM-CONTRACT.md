⛔ **좌표계를 반드시 바꾼다.** `config.yaml` 의 상자·벽은 `workspace.frame`(user1) 값이고

`Sim/fixtures/<robot>.json` 으로 얼려 건넨다(불변식 1 — 시뮬은 브리지에 못 묻는다).

## D74 와의 관계 — 무엇이 되살아나고 무엇이 안 되살아나나

D74 는 *"후보 생성은 PRD `§범위 밖` 이고 시뮬레이터는 안 들인다"* 로 Optimize 패널을 지우고,
슬롯 수명주기에서 `simulated`·`reviewed` 를, 저장 단위에서 `simulationJob`·`candidate` 를
삭제했다. **그 결정은 유효하다.** 이 계약은 그것을 뒤집지 않는다.

| D74 가 지운 것 | 이 계약에서 | 왜 |
|---|---|---|
| 시뮬이 **후보 궤적을 만들어** 승인 파이프에 넣는다 | **여전히 안 한다** | PRD 「배치 최적화 자동 탐색 — 최적해를 찾지 않는다」 그대로 |
| 슬롯 상태 `simulated` | **안 되살린다** | 시뮬 결과는 슬롯의 상태를 바꾸지 않는다. 승인은 사람이 실기 앞에서 한다 |
| `simulationJob`·`candidate` 저장 단위 | **안 되살린다** | 시뮬 산출은 `~/fr5-data/` 가 아니라 §데이터 의 별도 자리에 쌓인다 |
| — | **새로 여는 것**: 승인된 슬롯을 **읽어** 증식·재생·계측 | 후보를 만드는 게 아니라 **이미 승인된 것을 여러 조건에서 재는** 것이다. 방향이 반대다 |

한 줄로: **시뮬은 실기에 무엇을 넣지 않는다. 실기가 이미 정한 것을 읽어 갈 뿐이다.**

## 이 계약이 지키는 것 — 불변식 다섯

1. **시뮬은 브리지 주소를 모른다.** `Sim/` 는 `robot_adapter`·`endpoint`·`arm`·`step` 을
   import 하지 않는다. 실기에 닿는 cmd 허용목록에 **새 이름을 0개** 더한다
   (`PROGRAM-CONTRACT.md` §이 계약이 지키는 것과 같은 규약).
2. **데이터 흐름은 단방향이다.** `브리지 → 시뮬` 만 있다. 시뮬이 만든 어떤 값도
   `POST /slots`·`/points`·`/step` 으로 되돌아가지 않는다. 되돌리고 싶어지면 그때
   `PROGRAM-CONTRACT.md` 를 먼저 고친다.
3. **정본을 베끼지 않는다.** 시뮬 장면은 **생성물**이다 — URDF·`config.yaml`·`workcell.js` 에서
   구워 낸다. 좌표를 손으로 옮겨 적지 않는다 (하드 룰 5, 그리고 `workcell.js` 가 하루를 잃고
   적어 둔 이유 그대로).
4. **제한구역은 게이트가 이미 아는 것이다.** 시뮬이 구역을 새로 정의하지 않는다 —
   `config.yaml` 의 `workspace.boxes`(카트 상판·작업대)와 `walls`(옆 판)를 그대로 읽는다.
   **판정이 게이트와 갈라지면 그 화면은 근거가 아니라 그림이다.**
5. **시뮬 결과는 `docs/evidence/` 가 아니다.** evidence 는 실물 검증의 자리다(하드 룰 2).
   시뮬 산출은 시뮬 산출로만 인용하고, "실기가 이렇게 된다" 로 옮겨 적지 않는다.

## 단계 — S0 · S1 · S2 와 각 칸의 천장

골 사다리(1~6)와 **다른 축이다.** 번호를 겹치지 않게 `S` 를 붙인다.

### S0 — 증식과 물리 (학습 없음)

승인된 슬롯 1개 + 지터 스펙 → N 개 인스턴스를 한 화면에서 동시에 재생한다. 접촉·중력이
실제로 계산되고, 구역을 넘으면 게이트와 **같은 정의로** 위반이 잡힌다.

- **학습은 없다.** 라벨 없이 여러 대가 도는 화면은 보는 사람이 학습으로 읽으므로 화면이
  **글자로 말해야 한다.** 천장: 정책 없음 · 보상 없음 · 실기 미접속

**진입 조건** (하나라도 못 채우면 착수하지 않는다). 엔진은 **`@mujoco/mujoco` 3.11.0** —
DeepMind 공식 WASM 바인딩, npm 프리빌트라 Emscripten 빌드가 필요 없다 (`STACK.md` 등재 대상).

| | 재는 것 | 통과선 | 2026-08-08 실측 |
|---|---|---|---|
| 1 | FR5 URDF 를 엔진이 그대로 읽나 | 7 링크 · 관절 한계가 URDF 값과 일치 | **통과** — body 7 · joint 6 · geom 7 · mesh 7. **MJCF 변환 없이** `MjModel.from_xml_path` 하나로 읽는다. 단 STL 7개를 `mj.FS.writeFile` 로 가상 파일시스템에 먼저 올려야 한다 |
| 2 | 한 대가 실시간으로 도나 | 1× 이상 | **통과** — 접촉 포함 브라우저에서 40~120× |
| 3 | N 의 실측 상한 | 60fps 아래로 내려가는 N | **통과** — 그리면서 **96대 @60fps**. 아래 표 |

접촉은 **평균 4.1쌍 · 최대 6쌍**이 실제로 잡혔다(0 이면 벤치 무효). node 판과 소수점까지
같았다 — 같은 장면이 양쪽에 올라갔다는 교차검증이다.

### ⚠ 물리만 재는 벤치로는 상한을 정하지 않는다

한때 "물리만 35대" 라고 적혀 있었다. **그 숫자는 못 쓴다** — 같은 기계에서 다시 돌리니 **4배**가
흔들렸고(1대 31.8×→120.4×), 범인은 코드가 아니라 **기계 상태**(부하·발열)였다. 루프 순서 차이는
6% 뿐이었다. **그래서 상한은 종단 측정으로만 정한다.** 재현 안 되는 마이크로벤치는 상한이 아니라 그날의 기분이다.

### 화면 상한 — 실측 (2026-08-08 · 인스턴싱)

**실제로 그리면서** 쟀다. 팔 링크마다 `InstancedMesh` 하나 → **draw call 이 N 과 무관하게 11**
로 고정된다. 1280×720 · dpr 1 · 그림자 없음.

| N | 8 | 32 | 64 | **96** | 128 |
|---|---|---|---|---|---|
| 물리+렌더 fps | 61.6 | 61.2 | 61.3 | **60.4** | 56.2 |
| 렌더만 (프레임비용) | — | 1.75ms | 1.50ms | — | 3.77ms |
| 물리+렌더 (프레임비용) | 2.52ms | 4.49ms | 10.25ms | 16.17ms | 21.94ms |

→ **96대까지 60fps · 128대에서 56fps.** 4회 반복 — 96대는 매번 60fps 를 유지했고,
128대는 50.0/54.7/56.2/58.7 로 ±8% 안에서 흔들렸다.

**세 가지가 예상과 달랐다:**

1. **병목은 렌더가 아니라 물리다** — 128대에서 21.94ms 중 렌더는 **3.77ms(17%)**. 다음에 손댈
   곳은 메시 경량화가 아니라 물리(멀티스레드 빌드 또는 충돌 형상 캡슐화)다.
2. **인스턴싱의 fps 이득은 작다** — draw call 1408→11(128배)인데 프레임 비용은 7% 뿐(GPU 가
   병목이 아니다). **그래도 인스턴싱으로 간다** — 값은 약한 GPU·모바일과 씬그래프 크기다.
3. **진짜 하드 상한은 fps 가 아니라 메모리다** — `MjData` 를 **148개**까지만 만들 수 있고
   그 다음은 `Could not allocate memory` 로 죽는다. 화면 상한(96)보다 메모리 상한(148)이
   가까이 있으므로, N 을 키우려면 **fps 를 보기 전에 힙부터** 본다.

⚠ 프레임당 스텝을 `round(8.33) = 8` 로 잡아 시뮬이 실시간의 **0.96배**로 돈다. 실제 구현에서는
누산기로 나머지를 흘려야 한다 — 안 그러면 "실시간" 이라 적힌 화면이 4% 느리다.

⚠ **N=1 의 편차가 1.8배다** — 맥의 열·다른 탭이 그대로 들어온다. **한 번 잰 값을 상한으로
쓰지 않는다**(위 표는 3회 중앙값). 옛 "단일 스레드라 4~9대" 는 틀렸다 — 실측이 4배 높았다.

**재현은 이제 코드다** — `Sim/scene/build-scene.mjs`(장면) · `Sim/runner/batch.mjs`(실행).

### S1 — 데이터 수집

S0 에 이벤트 스키마와 회차 비교를 더한다. "어느 조건에서 몇 번 박았나" 가 표로 나온다.

- 천장: 여전히 학습 없음. 데이터는 **쌓이기만** 하고 정책을 만들지 않는다

### S2 — 정책 학습 · **여기서 갈린다**

PRD 가 이미 갈라 놓았다. 착수 전에 어느 쪽인지 문장으로 적는다.

| | PRD 판정 | 근거 |
|---|---|---|
| **모방학습** — 사람 시연을 정책이 배워 재현 | **범위 안** | 「가르치는 방법에 시연 학습이 들어온다」(D47). F10 의 `학습된 정책` 이 이 자리다 |
| **보상 설계 RL** — 스스로 더 나은 동작을 찾음 | **범위 밖** | 「최적해를 찾지 않는다」·「로봇이 스스로 목표를 세우는 것은 안 한다」 |

**범위 밖 쪽을 하려면 PRD 를 먼저 고친다.** 계약만 고쳐서 열지 않는다 — PRD 가 범위의
정본이기 때문이다(`docs/ref/README.md`).

⚠ S2 는 `vision-imitation.md` §4 사다리 2.5(서보 스트리밍)를 **선행으로 요구한다.**
`MoveJ` 로는 정책을 실행할 수 없다(§3.5). 시뮬 안에서만 도는 정책은 그 게이트를 안 타지만,
**실기로 내리는 순간 탄다.**

## 증식 — 무엇을 흔드나

```jsonc
{ "slotName": "집기시연",          // 승인된 슬롯 이름만 참조 — 단계를 복사하지 않는다
                                  // (PROGRAM-CONTRACT §모양 이 좌표를 안 베끼는 것과 같은 이유)
  "n": 6,                          // 인스턴스 수. S0 진입 조건 3 이 잰 상한 이하
  "seed": 20260808,                // 없으면 같은 화면이 두 번 안 나온다 — 재현이 안 되면 계측도 아니다
  "jitter": {                      // **없는 축은 안 흔든다.** 기본은 전부 0
    "startJointDeg": [-2, 2],      // 시작 자세 (도)
    "payloadKg": [0.4, 0.8],       // 실기 설정값 0.6 (config.yaml settings) 둘레
    "objectXyMm": [-50, 50]        // 작업물 자리 — 물체를 놓는 S1 부터
  },
  "speedPct": 10 }                 // 시뮬은 상한이 없지만 **실기와 비교하려면 같은 값**이어야 한다
```

**지터에 관절 한계·작업영역을 안 넣는다.** 그건 흔드는 값이 아니라 판정하는 값이다.

⚠ **증식한 궤적을 정책 학습 데이터로 쓸 때의 함정이 하나 뒤집힌다.**
`vision-imitation.md` §5 는 *"관절 좌표만 옮겨 학습 데이터를 불리지 않는다 — 옮긴 관절값에
맞는 카메라 영상이 없다"* 고 적었다. 이건 **실물 녹화를 후처리로 옮길 때** 참이고, 시뮬은
렌더러가 있으니 짝이 맞는 영상이 같이 나온다. **대신 새 함정이 그 자리에 온다 — sim-to-real
gap**(시뮬에서 배운 정책이 실물 조명·마찰·질감에서 무너지는 것). §5 를 지우지 말고 조건을
붙인다.

## 제한구역 · 충돌 · 파손

| 무엇 | 어디서 오나 | 지어내지 않는 것 |
|---|---|---|
| 로봇 형상·관절 한계 | `Shared/assets/FAIRINO_FR5/fairino5_v6.urdf` (`<collision>` 7링크 전부 있음) | 엔진이 메시를 **볼록껍질로 근사**한다 — 오목한 틈은 실물보다 관대하다 |
| 제한구역 | `FR5/bridge/config.yaml` `workspace.boxes`·`walls` | 여기에 새 상자를 만들지 않는다 (불변식 4) |
| 카트·거치대·바닥 | `Shared/data/workcell.js` · `Shared/view3d/workspace.js` | `workcell.js` 가 값을 안 적기로 한 것은 여기서도 안 적는다 |
| **받침·작업물** | `Shared/data/props.js` (`FIXTURE`·`ROUND`) | 치수·자리를 장면 스크립트에 적지 않는다 — 소품은 교체된다 |
| 단위 | URDF·엔진은 **m·rad**, 우리 저장은 **mm·°** | 변환은 `Shared/data/units/units.js` **한 곳** (하드 룰 5) |

### 받침·작업물은 **충돌체이지 구역이 아니다** (2026-08-13 등재 · 실기 담당자 결정)

받침을 `config.yaml` 의 `workspace.boxes` 에 넣지 않는다. 저기 넣으면 **실기 게이트가 같이
바뀌는데**(`safety.py` 가 같은 파일을 읽는다) 넣을 이유가 없다 — 산술로 확인했다: 작업대
금지바닥 −388.9 위에서 받침 86.5 · 총알 77 을 세우면 파지점이 그 위 **약 115mm** 라
지금 게이트로 **이미 열려 있다**. 불변식 4(「시뮬이 구역을 새로 정의하지 않는다」)도 같은 쪽이다.

- **구역은 게이트가 아는 것만**이다. 소품은 **부딪히는 물체**로만 장면에 선다 — 바닥·툴
  충돌체와 같은 자격이다
- ⛔ **소품이 늘면 `wantGeomCount` 가 따라 오른다.** 되읽기 검사가 개수로 재므로, 안 올리면
  「빠뜨렸다」로 죽는다. 그게 맞는 동작이다 (`build-scene.mjs` §verify)
- ⚠ **안 잰 값은 `null` 로 둔다.** 받침 발자국이 그랬듯 지어낸 치수는 다음 세션에 실측으로
  읽힌다(`WORKPIECE_MESH` 가 그렇게 됐다). **`null` 이면 장면이 그 소품을 안 세운다** —
  조용히 0 으로 세우면 크기 0 짜리 물체가 장면에 산다

### 파지는 **기하까지만** 잰다 (2026-08-12 등재)

**쥐는 힘은 시뮬의 몫이 아니다.** 실기에서 **완전닫음이면 무엇이든 꽉 잡힌다**가 확인됐고
(실기 담당자 · 2026-08-12), 그래서 마찰계수를 지어낼 이유가 사라졌다. 시뮬이 답하는 것은 하나다.

> 집게 끝이 물건의 높이 띠 안에 들어왔나, 그리고 집게 사이에 물건이 있나

이건 형상과 충돌만으로 답이 나오므로 **계측이다.** 반대로 미끄러짐·유지력·운반 중 낙하는
마찰과 접촉 강성이 필요하고 그 값에 출처가 없다 — 넣으면 위 `demoOnly` 와 같은 연출이 된다.
**그 판정은 실기 그리퍼 게이트가 한다** (힘 상한 · `gripperFault` · `API-CONTRACT.md` §그리퍼).

⛔ **손가락은 URDF 에 관절이 없다.** `grip` 칸이 물리를 안 타는 것은 지금도 그대로다 —
위 규약은 「닫힌 뒤 잡혔나」가 아니라 **「닫기 전에 자리가 맞나」**를 재는 것이다.

### 「망가진다」 는 물리가 아니라 규칙이다

물리 엔진에 파손 모델은 없다. 부수려면 **우리가 판정 규칙을 쓴다** — 그리고 그 임계값에
출처가 없으면 그것은 계측이 아니라 연출이다.

```jsonc
"damage": { "contactForceN": 150,   // 출처 없으면 아래 demoOnly 가 true 여야 한다
            "demoOnly": true }       // true 면 화면이 "연출" 이라고 **글자로** 말한다
```

**`demoOnly: false` 로 내리려면 임계값에 출처·날짜·방법을 붙인다** — `workcell.js` 의
`src()` 규약 그대로다. 실물 FR5 를 부숴서 재지 않을 것이므로, 현실적인 출처는 벤더 사양의
정격 하중·충돌 감지 임계(`config.yaml settings.collisionLevel`)뿐이고 그것은 **파손이 아니라
정지 임계**다. 그 차이를 화면 문장이 지운다면 그건 계약 위반이다.

## 데이터 — 무엇을 걷나

이벤트는 **한 줄에 하나**, 회차·인스턴스가 붙는다. `run` 과 이름을 겹치지 않게 `simRun` 이다.

```jsonc
{ "simRunId": "…", "batchId": "…", "instance": 3, "tMs": 4820,
  "kind": "contact" | "zoneViolation" | "jointLimit" | "cycleDone" | "damage",
  "detail": { "zone": "작업대", "penetrationMm": 12.4, "forceN": 38.1 },
  "stamp": { "slotName": "집기시연", "seed": 20260808, "speedPct": 10,
             "engineVersion": "…", "sceneBuiltFrom": "config.yaml@<해시>" } }
```

### `contact` 와 `zoneViolation` 을 한 수로 합치지 않는다 (2026-08-18 등재)

**둘은 다른 것을 말한다.** `zoneViolation` 은 판정기가 낸 것이라 여유 부호와 대조되고,
`contact` 는 물리가 낸 것이라 **구역이 아닌 충돌체**(받침·작업물 · 위 §받침)까지 포함한다.
그래서 `summary.csv` 는 `violations`(구역위반) 와 `contacts`(접촉) 를 **따로** 싣고,
`batch.json` 도 `zoneViolations`·`contacts` 를 따로 스탬프한다.

⛔ **합치면 게이트가 거짓말을 한다.** 2026-08-18 실측 — 완주 0/8 회차의 `violations` 열
(42·40·107·45)이 **인스턴스별 접촉 수와 한 자리까지 같았고**, 게이트 「여유 부호와 판정이
일치한다」가 여유 **+75.7mm** 인 행을 「위반 42」로 읽어 붉었다. 그 상태에서는 **진짜
구역위반이 나도 접촉에 묻혀 안 보인다** — 그 게이트가 막으려던 사고가 바로 그것이다.

⚠ **완주 0 의 원인이 둘로 갈린다.** ①구역이 손끝 자리를 덮었다(최소여유 음수) ②구역이
아닌 충돌체에 막혔다(여유 양수 · 접촉만 남음). 화면과 게이트가 둘을 **글자로 가른다**.

- **`stamp` 는 D74 ④ 가 `run` 에 요구한 것과 같은 이유로 필수다** — 조건이 다른 회차가
  나란히 비교되는 것을 막는다. `sceneBuiltFrom` 은 게이트 값이 바뀐 뒤의 회차와
  그 전의 회차를 섞지 않게 한다
- 저장 자리는 S1 에서 정한다. `~/fr5-data/` 가 아니다 — 그 폴더는 실기의 정본이고,
  시뮬 산출이 섞이면 다음 세션이 어느 쪽 숫자인지 못 가린다
- **`docs/evidence/` 에 시뮬 결과를 넣지 않는다** (불변식 5)

## 화면 — 개체를 그리지 말고 **분포를 그린다** (2026-08-11 등재)

N=96 에서 인스턴스마다 선 하나를 그으면 검은 뭉치다. **그래서 화면 규약이 데이터 규약과 함께
산다** — 나중에 정하면 차트마다 집계 코드가 따로 생긴다. 인스턴스마다 선 → **분위수 밴드**,
이벤트 목록 → **밀도 띠**, 인스턴스마다 막대 → **정렬된 표**(최소여유 오름차순 위 N행).
**예외는 이상치뿐이다** — 위반한 인스턴스만 밴드 위에 개체 선으로 승격한다. 나머지는 익명이다.

⛔ **밴드는 실제 분산을 그대로 그린다 — 납작하면 납작하게.** 세로 축을 좁혀 부풀리지 않는다.
납작함 자체가 「조건이 아직 안 갈렸다」는 정보다. 레퍼런스 그림이 이걸 어겼다(캡션 0.3% ·
밴드 13% 폭) — **그림은 배치 참고이고 숫자의 정본이 아니다.**

**예외 하나 — 조작 화면의 시뮬 탭은 개체 하나를 그린다** (2026-09-06 등재 · `docs/ref/rnd/SIM-TAB-CONVERGE-LOOP-2026-09-06.md`).
그 탭은 분포가 아니라 **입력 하나(거치대 자리)에 대한 판정**을 답한다 — 닿나(IK) · 부딪히나(브라우저 무조코 · 칸 사이를 5° 표본한 **길** ·
장면은 위 `/sim/scene` 을 `datasource` 로 받아 정차 자리 터틀봇·바구니·든 거치대를 합성) · 게이트 통과하나(랩 · ARM 뒤). 셋은 **따로** 말한다 —
하나로 뭉개면 집에서 늘 빨강이다. 장면이 없으면 접촉 층만 「못 잼」이다. 분포(N벌)는 여전히 관제화면 몫이고, 이 탭의 판정은 불변식 5 그대로
**실기 근거가 아니다**(그려진 상판 = 게이트 안전선 기준이라고 화면이 말한다).

⛔ **시뮬 탭도 `Shared/data/datasource/` 경계로 읽는다.** 화면이 파일 경로·`fetch` 를 직접
알면 칸 1(`GOAL-dash-datasource`)이 세운 「화면이 데이터 출처를 모르게」가 시뮬에서만 깨진다.

**드릴다운은 0층 결정 → 1층 집계 → 2층 조건 셀 → 3층 인스턴스(3D)다.** **3D 는 마지막 층에서만** —
96대가 동시에 도는 화면은 보는 화면이지 읽는 화면이 아니다. **0층이 없으면 근거가 아니라 그림이다.**

**점군은 세 자리뿐** — ①스윕 볼륨(손끝 궤적을 3D 점으로 · 제한구역 안의 점만 빨강)
②조건 공간(인스턴스 1개 = 점 1개) ③여유 밴드 위 산점. **2D 차트에는 안 넣는다.** 기법은
`~/jason/tailtree` 의 DNA 뷰에서 가져오되(내장 재질만 · 크기 3버킷 Points · 밝기는 정점색×강도)
**미학은 안 가져온다** — 검은 배경·글로우는 밝은 테마와 충돌한다. 3D 카드 **안쪽만** 어둡게 둔다.

**사전 집계를 파일에 굽는다** — `Sim/out/<batchId>/agg.json` (2026-08-11 신설). 브라우저가
매번 접으면 96개이 안 돈다. 담는 것 — **0층 결정**(`verdict`) · 여유 **분위수 밴드**(진행률 칸) ·
사이클·최소여유의 다섯 분위수 · **칸별 소요시간** · **이벤트 밀도 띠** · **최소여유 위 10행**.

- **밴드의 세로축은 여유(mm)다** — 사이클타임은 인스턴스당 스칼라라 밴드가 아니라 분위수다
- ⛔ **밴드의 가로축은 벽시계가 아니라 진행률(0~100%)이다** (2026-08-12 변경). 속도를 흔들면
  사이클이 2.8배로 갈리는데 벽시계로 묶으면 같은 칸에 「막 출발한 것」과 「가장 붙은 것」이
  함께 든다 — 실측 칸별 90% 폭 **107.8mm → 5.4mm**(같은 회차·축만 교체). 진행률은 계획이
  아니라 **실제 칸 소요시간**으로 내고, **벌마다 격자에 한 점씩 리샘플한다**(안 그러면 느린
  벌이 표본을 더 내 밴드가 기운다). 칸마다 벽시계 중앙값(`tMs`)을 같이 실어 시간을 안 잃는다
- **상관과 효과 크기를 같이 낸다** — 실측에서 설명력 0.971 인 축이 여유를 **0.03mm** 움직였다.
  상관만 굵게 쓰면 안 건드려도 될 축을 건드리러 간다. **0층 결정 문장은 효과로 적는다**
- ⚠ **안 난 이벤트 종류도 0 행으로 남긴다.** 행이 사라지면 「없다」와 「안 쟀다」가 같아 보인다
- ⚠ **완주 못 한 인스턴스는 `cycleMsMissing` 으로 센다** — 조용히 빠지면 화면이 「96개 중앙값」
  이라 말하면서 실제로는 93개를 쓴다

**회차마다 판정 규칙 지문을 박는다** — `batch.json` 의 `judge.fingerprint` (2026-08-12 신설).
게이트가 손끝 → 툴 → 팔로 넓어진 날 그 전에 구운 회차가 화면에 그대로 떠 있었다(19:42 · 20:59).
장면 지문만으로는 안 잡힌다 — **판정이 바뀌면 같은 물리에서 다른 숫자가 난다.** 지문이 다른
회차는 **비교하지 않는다.** 목록은 **새 것부터** 준다(이름순은 없어진 슬롯을 첫 화면에 세운다).

⚠ **화면이 없는 능력을 자랑하지 않는다.** 「최적화」·`policy`·`성공률` 은 우리가 안 하기로
했거나(D74) S0 에 없거나(정책) 못 재는 것(물체 없음)이다 — 라벨로도 쓰지 않는다.

**자리는 Dashboard 새 탭 `시뮬`** 이다. `생산성 비교` 탭에 얹지 않는다 — 그쪽은 팀원 지표
몫이라 섞으면 그 데이터가 도착하는 날 둘을 다시 뜯는다.
