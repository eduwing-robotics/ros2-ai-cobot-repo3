## 왜 이 서버가 필요한가

터틀봇 실험은 지금 터미널·SSH 전유물이라 회전율이 낮다. 팀원 전원이 **URL 하나**로
켜고·몰고·매핑하고·기록을 보게 하려면, FR5 와 같은 구조 — **로봇의 유일한 관문 서버** —
가 터틀봇 쪽에도 필요하다.

```
TurtleBot3 Burger (tb3_2 · 1호기는 파이 고장)
  라즈베리파이 안에서 전부 돈다 — bringup · 슬롯 스크립트 · tb-bridge :5056   ← 이 문서가 정의하는 것
      ↕ HTTP + WebSocket (브리지가 웹 빌드도 정적 서빙)
  팀원 폰·노트북 브라우저 — http://192.168.30.15:5056 하나
```

⚠ **2026-08-18 정정 — 브리지는 우분투 PC 가 아니라 파이 안에서 돈다.** DDS 가 파이 밖으로
안 나가 망 변수가 통째로 사라진다(옛 그림의 「우분투 PC」와 `turtlebot.local` 은 폐기).
상주 배선(`start-bridge.sh`·systemd 유닛 2개)의 정본 사본은 `TurtleBot/deploy/` 에 있다.

- ~~무거운 것은 전부 PC 에서 돈다~~ — **뒤집혔다 (2026-08-18).** 파이가 브리지까지 감당하고,
  대신 **DDS 가 망을 안 탄다**. 무게보다 「망 변수 0」이 컸다 (`evidence/2026-08-18/tb-pipeline-test.md`)
- **Vercel 에 올리지 않는다.** https 페이지는 LAN 의 ws:// 에 못 붙고(혼합 콘텐츠),
  로봇 제어를 인터넷에 노출하지 않는다. 배포는 `bash scripts/deploy/tb-pi.sh` (맥 빌드 → 파이 rsync → 재시작)
- WiFi·포트가 바뀌면 `TurtleBot/bridge/config.yaml` 값 하나만 바뀐다. 코드에 IP·포트를 박지 않는다
- **포트는 5056 이다 — FR5 브리지와 같은 PC 라 번호로 가른다** (D80 · 2026-08-06).
  "형제·무의존" 은 코드 의존을 말한 것이라 포트까지 갈라 두지 않았고, 그래서 tb-bridge 가
  아예 못 떴다. **기동 스크립트는 `config.yaml` 의 `port` 를 읽는다** — 여기가 정본이다.
  `vite.config.js` 의 dev 프록시만 사본이고 `check/consts.sh` 가 둘의 일치를 잡는다
- FR5 `bridge/` 와는 **형제·무의존** — 로봇마다 관문 하나, 서로 호출하지 않는다
- **API 는 브라우저 외 클라이언트에도 열려 있다** (팀원 스크립트·curl — 의도된 설계).
  신원 증명은 하지 않는다 — LAN·팀 신뢰 전제. 이 한계는 수용 리스크로 명시한다

## 단위와 좌표

바깥면은 전부 **밀리미터(mm)·도(°)·mm/s·°/s**다 (`CODING-CONVENTIONS.md` §2).
ROS 의 미터·라디안 변환은 **`ros_adapter/` 경계 한 곳**에서만 한다.
pose 는 `{ xMm, yMm, thetaDeg }` — **활성 맵이 있으면 맵 원점 기준(AMCL), 없으면 odom
원점(브링업한 그 자리) 기준**이다 (2026-08-18 명시 — 작업대 주행은 SLAM 없이 odom 만 쓴다).
odom 기준은 드리프트가 누적된다 — 절대 위치로 믿으려면 출발점 고정 의식 + §지오펜스의
드리프트 실측이 전제다. 맵→실험실 변환은 §미래 접점 ③.

**이름 규칙은 공통이다** — 슬롯·맵 이름과 robot id 는 `[a-z0-9-_]` 만. 경로 문자는 어디서든
거부된다 (이름이 곧 파일 경로가 되기 때문이다).

## 상태 (서버 → 클라이언트) — WebSocket `/ws/state`

접속한 전원이 같은 것을 받는다. **매 틱 전체 스냅샷**이라 재접속하면 그대로 복구된다.
주기 100ms 목표 (팔과 달리 33ms 가 필요 없다 — 버거 최고 속도 220mm/s 에서 100ms 는
22mm 다. 실측 후 갱신한다).

```jsonc
{
  "t": 1785329668.42,               // 서버 시각 (초)
  "adapter": "mock",                // mock | real — 화면에 출처 배지 (SR_24 원칙)
  "mocked": ["mapping", "maps", "liveMap", "rosbag"],   // 아래 §목업 목록
  "robots": {
    "tb3_1": {
      "connected": true,            // 판정: 오도메트리 2초 무수신 → false + cmd_vel 0 시도
      "poseAgeSec": 0.1,            // 마지막 pose 수신 후 경과 — 얼어붙은 값 구분용
      "mode": "idle",               // idle | slot | teleop | mapping — 전이는 §모드 전이
      "nav": null,                  // null | starting | running | error — Nav2/SLAM 프로세스 생사
      "pose": { "xMm": 1200, "yMm": 340, "thetaDeg": 90 },   // 기준은 §단위와 좌표 (맵 원점 또는 odom 원점)
      "imuYawDeg": 88.4,            // IMU 가 **필터로 만든** 방향. ⛔ 못 믿는다 (아래 §두 번째 눈)
      "imuYawIntDeg": 91.2,         // **자이로 원본 적분** — 필터를 우회한 값 · 없으면 null
      "velocity": { "linearMmS": 0, "angularDegS": 0 },
      "batteryPct": 87,             // turtlebot3_node 가 주는 값. 못 읽으면 null
      "batteryV": 11.08,            // **실측 전압** — 판정은 이걸로 한다 (아래 §배터리)
      "activeMap": "lab-0801",      // 활성 맵 슬롯 (없으면 null)
      "activeSlot": null,           // 실행 중 스크립트 슬롯 (없으면 null)
      "activeRunId": null,          // 진행 중 run (없으면 null)
      "owner": null                 // 조종권 보유자 (없으면 null)
    },
    "tb3_2": { /* 같은 모양 */ }
  }
}
```

### 두 번째 눈 — `imuYawDeg` (2026-08-20 신설)

`pose.thetaDeg` 는 **바퀴만 보고 만든 값**이다 — `/{ns}/odom` 을 내는 것이 `diff_drive_controller`
이고 그 컨트롤러는 IMU 를 안 쓴다. **엔코더는 헛도는 바퀴와 도는 바퀴를 구분하지 못한다.**

⭐ **왜 필요한지가 실측으로 났다 (2026-08-20)** — 텔레옵으로 코스 한 바퀴(267초)를 돌고 출발점에
돌아왔는데, **odom 은 428mm 떨어져 있다고 말했고 글로벌캠은 3.8px(≈4mm)라고 말했다.** 같은 프레임의
고정 태그가 0.07px 이라 카메라 탓이 아니다. 직진은 완벽했고(842mm 가는 동안 y 0.5mm) **큰 회전 4번이
회전당 ~107mm 씩 쌓았다.** 미끄럼 방지 매트를 깐 뒤에도 그렇다. 드리프트 예산 50mm 의 **8.6배**다.

그래서 `/{ns}/imu` 를 어댑터가 구독해 **상태에 같이 싣는다.** 슬롯 안에서만 보던 값을
**모든 주행**(텔레옵 포함)에서 보이게 하는 것이 이 필드의 전부다.

- ⛔ **raw 다 — `IMU_SCALE` 을 안 곱한 값이다.** IMU 는 회전을 **13% 크게** 읽는다(2026-08-19 실측
  제자리 회전 2회에서 비율 0.885 재현). 보정은 **쓰는 쪽**이 한다(`slots/run-path.py` 가 그렇게 한다).
  어댑터가 미리 곱해 내보내면 **스케일 자체가 틀렸을 때 그것을 볼 방법이 사라진다**
- ⛔ **`thetaDeg` 와 절대값을 빼서 비교하지 않는다** — 두 값은 원점이 다르다(IMU 는 자기 기동 시각
  기준). **누적 변화량**끼리 비교한다. 한 번에 빼면 180° 를 넘는 순간 부호가 뒤집힌다
- **2초 넘게 안 오면 `null`** — `poseAgeSec` 과 같은 규칙이다. 늙은 값을 두 번째 눈으로 쓰면
  「대조했다」는 거짓이 된다
- ⚠ **이 필드는 판정에 쓰지 않는다.** 재기만 한다.

⛔ **2026-08-20 — `imuYawDeg` 는 못 믿는 값으로 판정됐다 (D142).** 제자리 180° 회전을 **2회 재현**해
쟀다:

| 실제 회전 | `imuYawDeg` 가 말한 값 | 어긋남 |
|---|---|---|
| 90° (08-19) | 103° | **+13% 과다** |
| 180° (08-20 · 2회) | 166° | **−10% 부족** |

⭐ **각도에 따라 부호가 뒤집힌다** — 그래서 `IMU_SCALE` 같은 **스케일 상수로는 원리적으로 못 고친다.**
엔코더(183.74°)가 사람 눈·글로벌캠과 맞았다. **원인은 우리 쪽이 아니다** — OpenCR 펌웨어가
**지자기를 쓰지 않고** Madgwick 상보 필터로 orientation 을 만든다(ROBOTIS 문서). 지자기가 없으면
yaw 는 관측 불가능한 상태라 필터가 짐작으로 끌고 간다. 업스트림에 같은 증상이 미해결로 열려 있다.

### `imuYawIntDeg` — 자이로 원본을 적분한 값 (2026-08-20 신설)

`Imu` 메시지의 **`angular_velocity.z`(자이로 원본 rad/s)를 직접 적분**한다. 위 필터를 통째로 우회한다.

- 자이로 적분의 약점은 **바이어스 누적** 하나인데, 실측이 **0.001°/s** 다(정지 30초에 0.015°).
  12초 회전이면 **0.012°** — 오차 예산 밖이다. 이 로봇에서는 조건이 좋다
- **1초 넘게 IMU 가 끊기면 그 구간은 버린다** — 없는 회전을 지어내느니 모르는 채로 둔다
- 20Hz 발행이라 직사각형 적분으로 충분하다 (사다리꼴과의 차이가 예산 밖)
- ⛔ **검증했고 기각됐다 (2026-08-20 같은 날)** — 필터를 우회했는데 **결과가 같았다**:
  180° 에서 Madgwick 164.95 대 자이로원본 **165.39**(0.44° 차이). 이어 90° 를 재니 비율이 뒤집혔다 —
  **90°에서 1.104 · 180°에서 0.899**. **각도 의존이라 어떤 상수로도 못 고친다.**
  ⛔ **두 필드 모두 각도 판정에 쓰지 않는다.** 그래도 **지우지 않는다** — 매트 밖·빠른 회전처럼
  바퀴가 실제로 미끄러지는 조건에서 다시 볼 값이다. `slots/run-path.py` 의 슬립 검사는
  **로그만 남기고 멈추지 않는다**(`SLIP_ENFORCE=False`)
- ✅ **각도의 정본은 엔코더(`pose.thetaDeg`)다** — 180° 세 번에서 183.74·183.74·184.04 로 재현됐고
  사람 눈과 글로벌캠이 지지했다. 미끄럼 방지 매트 위에서는 바퀴가 미끄러지지 않는다

### 배터리 — 전압이 정본이다 (2026-08-19 신설)

`/{ns}/battery_state` 를 구독한다. **판정 기준은 `%` 가 아니라 전압**이다 — 3셀 리포는 부하가
걸리면 순간 전압이 주저앉고, OpenCR 은 그 순간값으로 모터를 끊는다. `%` 는 참고값이다.

| 전압 | 뜻 | 화면 |
|---|---|---|
| ≥ 11.5V | 정상 | 그대로 |
| 11.0 ~ 11.5V | **주의** — 부하가 걸리면 모터가 끊길 수 있다 | 노란 배지 |
| < 11.0V | **위험** — TurtleBot3 저전압 경고선. 충전·교체 | 붉은 배지 + 문구 |

- 근거: 만충 12.6V · 공칭 11.1V · TurtleBot3 기본 저전압 경고 **11.0V**.
  실측 — 08-18 `11.71V`(죽기 직전) · `12.42V`(새 배터리) · 08-19 `11.08V`(**조종이 안 되던 그때**)
- ⚠ **못 읽으면 `null` 이고, null 을 「괜찮다」로 읽지 않는다** — 화면은 `—` 로 그린다
- ponytail — 전압→잔량 곡선은 넣지 않는다. `%` 는 로봇이 주는 값을 그대로 싣고,
  사람이 보는 판정은 위 세 칸이면 충분하다. 정밀 잔량이 필요해지면 그때 곡선을 연다

### 목업 목록 — `mocked` (2026-08-19 신설)

**`adapter` 는 어댑터 하나만 가리킨다.** `adapter:real` 인데도 지도·매핑·rosbag 은 흉내였고,
화면 어디에도 그 말이 없었다 — 매핑을 「저장」하면 목록에 맵이 생기고 활성화하면 `nav:running`
이 떠서, 잰 적 없는 것이 잰 것처럼 보였다 (전수조사 2026-08-19). 그래서 **브리지가 자기 입으로
어디가 흉내인지 말한다.**

| 값 | 지금 실체 | 빠지는 조건 |
|---|---|---|
| `mapping` | SLAM 을 안 띄운다. `nav` 만 starting→running 으로 바꾼다 | 실제 slam_toolbox 기동 |
| `maps` | 저장이 `# mock map — 이름` 한 줄을 쓴다. pgm 없음 | `map_saver_cli` 배선 |
| `liveMap` | `live.png` 는 궤적 주변을 밝힌 그림이다 (`map_image.py`) | OccupancyGrid 구독 |
| `rosbag` | 경로 문자열만 run 에 넣는다 | `ros2 bag record` 프로세스 |

- **목록은 구현되면 줄어든다** — 빈 배열이면 전부 진짜다. 화면은 이 배열 하나로 배지를 그린다
- 어댑터와 **독립**이다. `adapter:real` 이어도 여기 있는 것은 흉내다
- 웹 자산인 **배경 지형**(`src/data/mapGeometry.js` 의 가상 12×8m 실험실)은 브리지가 모르므로
  이 목록에 없다 — 그 표기는 화면이 자기 책임으로 한다

## 명령 (클라이언트 → 서버) — 같은 WebSocket

```jsonc
{ "cmd": "hello",  "who": "kim" }              // 접속 직후 1회 — 세션에 신원을 묶는다
{ "cmd": "teleop", "robot": "tb3_1", "linearMmS": 100, "angularDegS": 30 }
{ "cmd": "estop",  "robot": "tb3_1" }          // robot 생략 시 전체. 항상 통과
```

- **`hello` 가 없는 세션의 명령은 `estop` 빼고 전부 거부**된다. owner 검사는 세션 신원으로 한다
- 슬롯 시작/정지·매핑·조종권은 REST 다. WS 명령은 **연속 스트림이 필요한 teleop** 과
  **지연이 치명적인 estop** 둘뿐이다

### 모드 전이 (로봇별 독립)

```
            ┌─────── estop · stop (어디서나) ────────┐
            ▼                                        │
  idle ──슬롯 start──▶ slot      idle ──mapping start──▶ mapping
  idle ──teleop 명령──▶ teleop   (teleop 은 명령이 곧 진입 — 별도 start 없음)
```

- **slot·teleop·mapping 시작은 idle 에서만.** mode 가 다른데 시작·teleop 명령이 오면
  거부 + 사유 응답 — 한 로봇에 cmd_vel 이 두 곳에서 겹치는 일을 계약이 막는다
- **예외 — mapping 중 teleop 은 수락한다 (mode 는 mapping 유지).** 맵은 로봇을 몰아야
  그려진다. 이때 cmd_vel 의 주인은 조이스틱 하나뿐이라 겹침이 없다 (2026-07-31 구현 대조)
- teleop 은 워치독 500ms 무신호면 정지하고, teleop 모드였다면 idle 로 돌아간다
- `estop` → 즉시 정지 + 슬롯 프로세스 종료 + **mode=idle. owner 는 유지된다**
  (estop 이 조종권 탈취 수단이 되면 안 된다). 별도 해제 절차 없음 — owner 가 즉시 재시작한다
- 명령·모드는 로봇별 독립이다. `estop` 만 robot 생략 시 전체에 걸린다

### 안전 규칙 (서버가 강제한다 — 클라이언트를 믿지 않는다)

| 규칙 | 값 |
|---|---|
| teleop 속도 상한 | 기본 **\|150\|mm/s · \|60\|°/s** (절대값 기준 — 음수는 후진·역회전) |
| teleop 워치독 | **500ms** 무신호 → 즉시 정지 (WiFi 순단 대비) |
| 값 검증 | 숫자가 아니거나 필드가 빠지면 거부. 상한 초과는 자르지 않고 **거부 + 사유** |
| `estop` | 신원·조종권·상한 무관 즉시 — 스팸으로 인한 실험 중단은 수용 리스크 |
| **프로세스 종료 시 정지 보장** | 슬롯이 어떤 이유로든 죽으면(정상·SIGKILL 불문) **브리지가 즉시 cmd_vel 0 발행** |
| 연결 손실 | 오도메트리 2초 무수신 → connected:false + cmd_vel 0 시도 |
| 슬롯 시작·teleop | 해당 로봇 **조종권 보유자만** |
| 열람 | 누구나 — 상태·맵·로그·기록은 조종권 없이 보인다 |

### 지오펜스 — 작업대 위 주행의 낙하 방지 경계 (2026-08-18 신설 · **2026-08-19 구현**)

작업대 3판(800×500 ㄱ자 · 바닥에서 약 950mm) 위를 달린다. **버거는 모서리를 스스로 못
본다** — 클리프 센서가 없고 라이다 평면은 판 위 ~170mm 라 모서리가 안 잡힌다 (감사
2026-08-18). 그래서 경계 판정은 전부 브리지 몫이고, **물리 턱이 계약 밖의 최후선**이다
(소프트웨어가 어떤 상태여도 턱은 서 있다 — 턱 없이 이 절만 믿지 않는다).

**경계 값은 `config.yaml` 의 로봇별 `geofence` 에 산다** — 코드에 좌표를 박지 않는다 (D29).

```yaml
geofence:
  frame: odom          # 기록용 — 브리지는 pose 를 그대로 쓴다 (§단위와 좌표)
  inset_mm: 163        # 여유선 — 판 가장자리에서 안쪽으로. 임시값 근거는 아래
  polygon_mm:          # 판 가장자리 (mm · 3점 이상 · 감김 방향 무관 · 자기교차 금지)
    - [-400, -250]
    - [ 400, -250]
    - [ 400,  250]
    - [-400,  250]
```

- **다각형 하나로 적는다 — 사각형은 점 4개짜리 특수형이다.** 판이 ㄱ자라 사각형으로는 못
  적는다. 볼록·오목을 한 코드로 판정한다(광선 교차 + 변까지 최단거리 · `bridge/geofence.py`)
- **기준 프레임은 pose 와 같다** (§단위와 좌표 — 맵 없으면 odom 원점). odom 기준이므로
  **출발점 고정 의식**(표시 지점에서 브링업)이 운용 전제다
- **판정 주체는 브리지 하나.** 10Hz 로 pose 를 보고 여유선 밖이면 ① cmd_vel 0 발행
  ② 실행 중 슬롯 종료 ③ 이동 명령 거부 + 사유 (조용히 막지 않는다 — 사유는 항상 화면에 닿는다)
- **정지는 언제나 통과한다** — `estop` 과 `linear=angular=0` 은 지오펜스가 막지 않는다.
  막으면 밖으로 나간 로봇을 세울 수단이 사라진다
- **탈출 주행은 만들지 않는다.** 여유선 밖에서는 **어느 방향이든 거부**다 — 드리프트한 odom 으로
  「안쪽 방향」을 계산했다가 그 계산이 틀리면 그게 낙하다. **사람이 들어서 다시 놓는다**
  (ponytail — 천장: 손이 닿는 작업대에서만 성립. 바닥 주행에 쓰려면 이 규칙을 다시 연다)
- **fail-closed**: 켜진 로봇의 pose 가 없거나(`poseAgeSec > 2s`) 경계 설정이 깨져 있으면 —
  통과가 아니라 정지다. **설정이 깨져도 브리지는 뜬다** — 그 로봇만 영구 거부 상태로 두고
  기동 로그에 사유를 남긴다 (브리지가 안 뜨면 estop 도 못 보낸다)
- 상태 스냅샷에 얹는다 — 화면(여유선 표시·경고)이 이 값 하나로 그린다. 미설정 로봇은 `null`

```jsonc
"geofence": null | {
  "inside": true,     // 여유선 안인가
  "marginMm": 42,     // 여유선까지 남은 거리 — 밖이면 음수, 판정 불가면 null
  "reason": null      // 막힌 사유. D114 — 사유가 화면에 못 닿으면 그 게이트는 없는 것과 같다
}
```

- **`insetMm` 기본값은 드리프트 실측(출발점 복귀 킬실험) 뒤에 확정한다** — 실측 전 임시값은
  회전 반경 113mm + 드리프트 예산 50mm = **163mm**. 실측이 예산을 넘으면 글로벌캠 태그
  보정(§미래 접점 ⑥ 후보)을 열고, 이 절에 외부 pose 주입 계약을 그때 추가한다
- **`polygon_mm` 은 아직 어느 로봇에도 없다** — 판을 odom 기준으로 안 재서다. 재기 전까지
  `geofence` 키를 비워 두고(=`null`), **상판 위 주행은 하지 않는다**. 바닥 리허설만 한다

## 조종권 — 로봇별 (FR5 규칙 미러: 명령 주인은 한 명)

```
POST /api/owner/claim   { "robot": "tb3_1", "who": "kim" }   → 비어 있으면 부여, 아니면 409
POST /api/owner/release { "robot": "tb3_1", "who": "kim" }   → 현재 owner 와 일치할 때만. 아니면 409
```

- tb3_1 과 tb3_2 의 조종권은 독립 — 두 명이 로봇 하나씩 몬다
- **자동 해제**: owner 의 `hello` 세션이 끊기면 **10초 후 release** — 브라우저를 닫아도
  조종권이 영원히 잠기지 않는다 (teleop 정지는 워치독이 500ms 에 이미 처리)
- REST 응답이 정본이고 `/ws/state` 의 owner 반영은 다음 틱이다

## 스크립트 슬롯 — 팀원의 파이썬이 꽂히는 곳

`TurtleBot/bridge/slots/*.py` 를 스캔한 것이 목록이다. 파일을 넣으면 슬롯이 생긴다.

```
GET  /api/slots                       → [{ "name": "patrol", "description": "..." }]
POST /api/slots/{name}/start          { "robot": "tb3_1", "who": "kim", "params": {} }
                                      → 202 { "runId": "..." }  (spawn 성공만 뜻한다 —
                                        이후 생사는 상태·로그로 본다)
POST /api/robots/{robot}/stop         실행 중 슬롯 정지 (SIGTERM → 5s → SIGKILL)
```

### 슬롯 계약 (팀원용 — `bridge/slots/README.md` 에 같은 내용)

- 파일 첫 줄 docstring 한 줄이 목록의 `description` 이 된다
- 브리지가 **별도 프로세스로 실행**한다. env 로 받는다: `TB_ROBOT`(네임스페이스) ·
  `TB_MAP`(활성 맵 yaml 경로 — **맵 없이 시작하면 빈 값**. 맵 필수인 스크립트는 스스로
  검사하고 메시지를 내고 종료한다) · `TB_PARAMS`(JSON, **4KB 상한**)
- **stdout 에 쓰면 그대로 로그 화면에 흐른다** (한 줄 = 한 로그)
- **SIGTERM 을 받으면 로봇을 세우고 종료한다.** 5초 안에 안 죽으면 SIGKILL.
  어느 경로든 **종료 직후 브리지가 cmd_vel 0 을 발행**한다 — 죽은 스크립트에게
  정지 책임을 맡기지 않는다
- 종료와 동시에 run 이 마감된다: exit 0 → `completed` · `/stop` → `stopped` ·
  estop → `estop` · 그 외(비정상 exit·SIGKILL) → `error`

## 원점 재설정 — 「여기가 (0,0,0)」 (2026-08-19 신설)

```
POST /api/robots/{robot}/reset-odom     { "who": "kim" }   → ok | 거부 + 사유
```

odom 원점은 **브링업한 그 자리**다. 그래서 출발 자리를 옮기거나 로봇을 손으로 들면 저장한
경로가 통째로 어긋난다 — 그걸 되돌리려고 **재부팅**을 했는데(2026-08-19), 로봇이 그 일을 하는
서비스를 이미 갖고 있었다: `/{ns}/reset_odometry` (`std_srvs/srv/Trigger`).

- **조종권 보유자만** 부를 수 있고 **`mode`가 `idle`일 때만** 받는다 — 달리는 중에 좌표계를
  갈아치우면 실행 중 슬롯이 엉뚱한 곳으로 간다
- ⚠ **저장된 경로는 그대로 두고 기준만 바뀐다.** 그러니 **홈 표시 위에 정확히** 놓고 눌러야
  한다. 어긋난 채 누르면 그만큼 전부 어긋난다 (위치도 **방향도**)
- 재부팅과 다른 점 — 브링업·브리지가 안 죽으므로 **조종권·기록·연결이 유지**된다.
  같은 점 — 이전 좌표계로 잰 값은 전부 무효다
- ponytail — 「원점을 임의 좌표로 옮기기」는 안 만든다. 지금 필요한 건 **지금 자세를 0으로**
  하나뿐이고, 임의 오프셋이 필요해지는 날은 판 좌표계(`tableToOdom`)가 먼저 온다

## 경로 — 움직임을 저장하고 다시 실행하는 형식 (2026-08-19 결정·구현)

상판 주행은 SLAM 을 안 쓴다(D134). 그래서 「어디로 가라」를 담는 그릇이 맵이 아니라 **경로**다.

- **저장 단위는 웨이포인트 목록이다.** 시간-속도 녹음을 그대로 재생하는 방식(open-loop)은
  **비채택** — 한 번 성공한 재생이 다음엔 드리프트만큼 밀리고, 밀린 만큼이 950mm 낙하다
- **좌표는 판 좌표계(`frame: "table"`)로 적는다.** odom 원점은 브링업할 때마다 달라지고,
  드리프트가 예산을 넘으면 글로벌캠 태그 보정으로 갈아탄다 — 그때 **저장해 둔 경로가 살아남는
  유일한 방법**이 판 기준이다. odom↔판 변환은 브리지 한 곳 (맵의 `mapToLab` 과 같은 구조)
- **실행기는 슬롯 하나다** — `slots/run-path.py` 가 `TB_PARAMS={"path":"<name>"}` 를 받아
  순서대로 몬다. 경로마다 `.py` 를 만들지 않는다 — 값은 데이터에 산다 (D29)
- ⭐ **회전은 두 눈으로 본다 (2026-08-19 신설)** — 엔코더는 **헛도는 바퀴와 도는 바퀴를 구분하지
  못한다.** 그날 제자리 180° 회전이 미끄러졌는데 기록은 `completed` 였고 로봇은 엉뚱한 방향으로
  419mm 를 갔다 (**낭떠러지 쪽**). 그래서 실행기가 회전마다 **엔코더 누적 vs IMU 누적**을 대조하고
  **20° 이상 갈리면 멈추고 사유를 남긴다.** ⚠ **IMU 는 회전을 13% 크게 읽는다** — 제자리 회전
  시험 2회에서 엔코더 −91:IMU −103, −92:−104 로 비율 0.885 가 재현됐고 **눈으로 본 실제는 92°**
  였다(엔코더가 맞다). 그래서 실행기가 IMU 값에 `IMU_SCALE=0.885` 를 먼저 곱한다 —
  안 곱하면 90° 만 돌아도 거짓 경보가 난다. 회전 속도도 45→20°/s 로 낮췄다 — 제자리 회전이
  가장 잘 미끄러지는 동작이다. IMU 가 안 오면 검사 없이 가되 **로그로 말한다**(조용히 넘어가지 않는다)

```jsonc
// bridge/data/paths/<name>.json
{
  "name": "belt-to-cell",
  "frame": "table",                 // 판 좌표계. odom 원점 기준으로 적지 않는다
  "tableToOdom": null,              // { xMm, yMm, thetaDeg } — 실행 시점에 브리지가 채운다
  "points": [
    { "xMm": 120, "yMm": 0, "thetaDeg": 0, "arriveMm": 30, "arriveDeg": 10, "dwellSec": 1 }
  ],
  "createdFrom": "2026-08-19-1432-tb3_2-teleop",   // run id 또는 "hand"
  "savedAt": 1787000000.0
}
```

```
GET  /api/paths                     → [{ name, points: n, frame, savedAt }]
GET  /api/paths/{name}              전체
PUT  /api/paths/{name}              저장·덮어쓰기 (본문 64KB 상한 · 이름 규칙은 §단위와 좌표)
POST /api/paths/{name}/append-here  { "robot": "tb3_2" }  → **지금 그 자리**를 점 하나로 덧붙인다
POST /api/paths/{name}/pop          마지막 점 하나 되돌리기
POST /api/paths/{name}/from-run     { "runId": "..." }  → run 궤적(1Hz)을 경로로 승격
DELETE /api/paths/{name}
```

**`append-here` 가 기본 만들기 방법이다 (2026-08-19 정정).** 처음엔 「몰고 나서 궤적을 승격」을
기본으로 적었는데 실제로는 안 된다 — **텔레옵 주행은 run 을 안 만들어 궤적이 한 점도 안 남고**
(run 은 슬롯 시작에서만 생긴다), 승격은 150mm 이상 벌어진 점만 남겨 **정확한 자리를 찾느라 한
미세조정이 통째로 솎인다**. 정차 지점은 「지나간 궤적」이 아니라 **「마지막에 멈춘 그 자세」**다.

- **`thetaDeg` 를 항상 채운다** — 작업대를 향해 서야 적재가 되므로 정차점에 방향은 필수다.
  반대로 `from-run` 은 마지막 점에만 방향을 넣는다 (궤적엔 「어디를 보고 섰나」가 없다)
- **fail-closed** — pose 가 없거나 `poseAgeSec > 2s` 면 거부한다. 늙은 자리를 점으로 굳히면
  그 경로는 영원히 틀린다
- 경로가 없으면 새로 만든다. `frame` 은 **odom** — 바닥 주행은 판 좌표계가 없다

- **`dwellSec`** — 그 점에 닿아 방향까지 맞춘 뒤 **멈춰 있는 시간**(초 · 기본 0 · 상한 60).
  적재·파지처럼 사람이나 팔이 일할 틈이 필요할 때 쓴다. 멈춤 중에도 `cmd_vel 0` 이 나가고
  지오펜스·estop 은 그대로 산다
- 만드는 법 둘 — ① teleop 으로 몰고 그 run 의 1Hz 궤적을 **승격**(`from-run`) ② 화면에서
  판 위에 점 찍기. **①이 먼저다** — 기록은 이미 있고(§실험 기록), 화면은 아직 없다
- **지오펜스가 선행 조건이다.** 경로 실행은 여유선 안에서만 되고, 판정은 §지오펜스가 한다 —
  경로 쪽은 자기가 안전하다고 믿지 않는다. 지오펜스 값이 없으면 **상판 위 실행 금지**
- 경로 실행도 슬롯이므로 run 이 생긴다 — 계획(`points`)과 실제 궤적(`/runs/{id}/path`)이
  같은 기록 안에서 대조된다. 드리프트 실측이 이 대조로 닫힌다

## 맵 슬롯과 매핑

```
GET   /api/maps                       → [{ "name": "lab-0801", "mapToLab": {...}, "savedAt": ... }]
POST  /api/maps/{name}/activate       { "robot": "tb3_1" }  → 202. 지도·AMCL 재기동은
                                        비동기 — 완료는 상태의 nav 필드(starting→running)로 본다
PATCH /api/maps/{name}                { "mapToLab": { "xMm":0, "yMm":0, "thetaDeg":0 } }
GET   /api/maps/live.png?robot=tb3_1  현재 점유격자 PNG (매핑 중엔 1s 폴링으로 그려진다)
POST  /api/mapping/start              { "robot": "tb3_1", "who": "kim" }  → 202. SLAM 기동
                                      (owner 검사가 필요한 REST 는 body 의 who 로 신원을 싣는다 —
                                       WS 의 hello 와 같은 신뢰 전제)
POST  /api/mapping/save               { "robot": "tb3_1", "name": "lab-0801" }  → 맵 슬롯 등록
POST  /api/mapping/stop               { "robot": "tb3_1" }   저장 없이 종료
```

- 맵 슬롯 = `bridge/data/maps/<name>.yaml + .pgm + .meta.json`
- `.meta.json` 의 `mapToLab { xMm, yMm, thetaDeg }` 은 저장 시 0 — 측정 후 PATCH 로 넣는다.
  측정 절차는 실기(P4)에서 정한다. §미래 접점 ③
- 맵은 아직 0개다. 목록이 비어도 화면이 깨지지 않는다 — 매핑 탭이 첫 안내를 맡는다
- **매핑은 명시적 save/stop 까지 유지된다.** 시작한 사람이 이탈해도 SLAM 은 돈다 —
  mode=mapping 이 전원에게 보이므로, 조종권을 잡은 사람이 정리(stop)할 수 있다

## 로그 — WebSocket `/ws/logs`

```jsonc
{ "t": 1785329668.42, "robot": "tb3_1", "source": "slot", "level": "info", "line": "..." }
// source: slot(스크립트 stdout) | nav(Nav2·SLAM 프로세스) | rosout | bridge(관문 자신)
```

서버는 최근 500줄을 버퍼링해 새 접속에 먼저 준다 — 새로고침해도 맥락이 남는다.
폭주 상한: 로봇·소스당 100줄/s 초과분은 버리고 `dropped` 카운트를 로그로 남긴다.

## 실험 기록 — run

슬롯 시작마다 자동 생성된다. 확장은 `metrics` 자유 필드로 한다 — 스키마 개정 없이.

```jsonc
{
  "id": "2026-08-01-1432-tb3_1-patrol",
  "robot": "tb3_1", "mapSlot": "lab-0801", "scriptSlot": "patrol", "params": {},
  "layoutId": null,                // 맵 실험이면 맵 id — Dashboard 비교의 연결 고리
  "startedAt": 1785329668.42, "endedAt": null,
  "result": null,                  // completed | stopped | estop | error — 판정은 §슬롯 계약
  "note": "",                      // 사람이 나중에 붙이는 메모
  "metrics": {},                   // 자유 — 생산성 실험이면 아래 규칙
  "bagPath": null                  // rosbag 녹화 시 경로
}
```

```
GET   /api/runs?robot=&slot=&limit=   목록 (최신순)
GET   /api/runs/{id}
GET   /api/runs/{id}/path             → [{ "tSec": 0.0, "xMm": ..., "yMm": ..., "thetaDeg": ... }]
PATCH /api/runs/{id}                  { "note", "metrics" }  얕은 병합 · 본문 64KB 상한
POST  /api/record/start|stop          { "robot": "tb3_1" }   rosbag 토글 → 활성 run 에 bagPath
```

- **주행 궤적**: 브리지가 run 진행 중 pose 를 1Hz 로 샘플해 저장한다 — rosbag 없이도
  경로 조회·맵 배치가 된다. run 종료 시 `travelMm`(궤적 적분)를 metrics 에 자동 기입
- **생산성 실험이면** `metrics` 에 FR5 지표 계약(`API-CONTRACT.md` §생산성 지표)의
  **전체 객체** — `{ source, cycles, durationSec, metrics{throughputPerHour, cycleTimeSec, ...},
  series[{tSec,event,station}] }` — 를 그대로 담는다. `layoutId` 는 run 최상위에 있다.
  그래야 Dashboard 비교 화면이 변환 없이 먹는다. `series[].event` 는 `pick·place·arrive·depart`
- **브리지 재시작 시**: endedAt=null 인 run 은 result:"error"(사유 bridge-restart)로 마감된다.
  슬롯·rosbag 프로세스는 브리지의 자식이라 함께 죽는다 — 고아가 남지 않는다
- 자동 삭제는 하지 않는다(실험 데이터). 단 **디스크 여유가 임계 미만이면 record/start 를
  거부**하고 사유를 응답한다 (`config.yaml` 임계값)
- 저장은 `bridge/data/runs/*.json` — 저장소가 바뀌어도(`Database/` 확정 시) 이 계약은 그대로다

## 미래 접점 — 계약은 지금, 구현은 나중에

1. **FR5 협업** — "AMR 도착 → 팔 픽" 같은 시나리오는 **슬롯 스크립트가 두 관문(tb-bridge ·
   FR5 bridge)의 클라이언트**가 되어 조율한다. 관문끼리 직접 호출 금지 — 각자 자기 로봇의
   안전만 지킨다. TB 쪽은 스크립트가 rclpy 로 Nav2 goal·도착 판정을 직접 하고, FR5 쪽은
   WS 명령(moveJ·gripper)과 `/ws/state` 의 `motionQueueLength` 로 완료를 판정한다 —
   두 계약만으로 성립함을 감사에서 의사코드로 확인했다 (evidence 2026-07-31)
2. **지표 어휘** — 위 §실험 기록의 생산성 규칙. 겉모양까지 FR5 계약과 맞춘다
3. **좌표 원점** — 실험실 바닥 고정점(mm·도)이 전 도메인 기준(SR_23). SLAM 맵은 원점이
   맵마다 다르므로 `mapToLab` 변환값을 맵 메타에 두고 PATCH 로 넣는다. 이 값 하나로
   주행 경로↔맵 배치, AR 오버레이, 맵 `waypointsMm`→goal 변환이 전부 풀린다.
   변환은 브리지 경계 한 곳
4. **쓰기는 화면 하나 — FR5 조작 화면이다** (2026-09-05 · D182 · 이전: 「터틀봇 웹앱 하나」).
   터틀봇 웹앱은 퇴역했다 — 제일 큰 칸이 목업 지형 위 점 하나였고, 그 값은 FR5 조작의
   3D 트윈이 이미 실측으로 그린다(자세·자취·되감기 · 2026-08-28). 주행 탭(로봇 카드·배터리·
   조종권·WASD·경로·슬롯·E-STOP)이 FR5 조작의 **「터틀봇」 탭**으로 옮겨 갔다.
   AR·Dashboard 는 그대로 **읽기 전용** — `GET`·`/ws/state` 만 읽어 AMR 위치·경로를 겹친다.
   예정 경로가 필요해지면 `GET /api/robots/{id}/plan` 을 쓴다 (이름만 예약)

   ⭐ **`GET` 은 어느 출처에서든 읽는다** (2026-08-28) — 소비자들은 **다른 주소에서 서빙되는
   화면**이라 브라우저가 「다른 출처」로 보고 막는다. 웹소켓은 그 규칙을 안 탄다.
   ⛔ **`POST`·`PUT`·`PATCH`·`DELETE` 는 FR5 조작 화면의 출처에서만 받는다** — 브리지가
   **사설망 호스트(192.168/10/172.16~31 · localhost · `.local`)의 `:5055`**(FR5 브리지가 서빙) 와 dev/게이트
   `:5176` 만 연다(`main.py` §CORS · `TB_WRITE_ORIGIN_RE`). 포트만 보던 첫 판은 바깥 사이트가 :5055 로 뜨면
   뚫렸다(감사 2026-09-05) — 호스트까지 본다. Origin 없는 요청(curl·슬롯 스크립트)은 브라우저가 아니라
   이 울타리 밖이다 — 그쪽은 §조종권(who)이 막는다. WS `hello` 는 토큰을 검증하지 않는다(LAN·팀 신뢰 전제 ·
   `owner.py`) — 이름만 같으면 조종권을 흉내낼 수 있다. 팀 밖과 망을 나누는 날 여기가 첫 구멍이다.
   하드룰 4(명령 주인은 한 명)를 지키는 것은 **출처가 아니라 §조종권**(hello 세션 바인딩 ·
   로봇별 owner)이다 — 출처 제한은 「아무 페이지나 몰 수 있다」를 막는 두 번째 울타리일 뿐이다.
   자격증명은 안 싣는다.
   ⛔ **STOP 하나가 둘 다 세운다** — FR5 조작 화면의 STOP 은 팔 `stop` 과 터틀봇 `estop`(연결된
   로봇 전부)을 같이 보낸다. 멈추는 방향이라 하드룰 3 안이다. 팔이 움직이는 동안 터틀봇을
   못 몰게 하는 §상호 배제는 **브리지가** 한다(GAP P1 · 구현 대기) — 화면은 그 사유를 보여줄 뿐이다.

5. **Vision** — 터틀봇 쪽 비전이 범위에 들어오는 날 FR5 와 같은 `POST /proposal` 규약
