# API-CONTRACT — 브리지 계약

분류: **SSOT**. FR5 브리지·웹·AR가 동시에 작업하려면 이 파일이 유일한 합의점이다.
**여기를 먼저 고치고 코드를 짠다.** 코드가 앞서면 다른 두 사람이 깨진다.

**구현 소유자는 `FR5/bridge/`다.** 루트 범용 `Backend/`는 두지 않는다. `Dashboard/`는
이 계약의 읽기 전용 요약 소비자이며 로봇 명령을 보내지 않는다.

## 목차

10개 절. **`##` 절과 이 목록은 같아야 한다** — `docs-weight.sh` 가 잰다.

- 왜 이 서버가 필요한가
- 상태값 (서버 → 클라이언트)
- 로봇 프로필과 읽기 전용 사전검증
- 명령 (클라이언트 → 서버)
- 조종권
- 이동 지점 (P3 Teach)

- 예상 경로 (AR·3D가 쓴다)
- 여기에 없는 것 — 어느 문서가 정본인가
- 바꿀 때

## 왜 이 서버가 필요한가

우리 유니티 코드(`FairinoBridgeClient.cs`)는 이미 `http://127.0.0.1:5055`로
`POST /connect`, `GET /state`, `GET /version`, `POST /disconnect`를 **호출하고 있다.**
받는 쪽이 없을 뿐이다. 그 자리를 채우면 유니티·브라우저·폰이 같은 하나를 본다.

```
FR5 컨트롤러 :8080
      ↕ 공식 파이썬 SDK
  FR5/bridge :5055  ← 이 문서가 정의하는 것
      ↕ REST + WebSocket
  FR5 웹 · 폰(AR) · Dashboard 요약
```

### 정적 서빙 — 브리지가 화면과 보정값도 낸다 (2026-08-08 등재)

여태 코드에만 있고 계약에 없었다. 마운트 순서가 곧 계약이라 여기 적는다 — **아래에서 위로
덮이지 않게, 좁은 경로가 먼저다.**

| 경로 | 내는 것 | 언제 읽나 |
|---|---|---|
| `/config/<이름>.json` | `Shared/data/config/` 를 **디스크에서 그대로** | **요청할 때마다** |
| `/sim/scene/<robotId>.xml` | `Sim/out/scene/` 의 구운 MJCF 장면을 **디스크에서 그대로** (2026-09-06 · `SIM-TAB-CONVERGE-LOOP` phase 0). **산출물이라 없을 수 있다** — 그러면 404 이고, 화면은 접촉 층을 「못 잼」으로 내린다(결측=차단 · 거짓 초록 금지). 관제화면 dev 서버의 `/sim/` 통로와 같은 파일이다 | **요청할 때마다** |
| `/ar/…` | `AR/dist` (라이브 셀·겹쳐보기) | 빌드 시점 |
| `/…` | `FR5/dist` (조작 화면) | 빌드 시점 |

**`/config` 가 내는 것 여섯** — `robot-base-in-tag.json` 빼고 전부 스크립트가 만들고 **손으로 안 고친다.**

| 파일 | 만드는 것 | 모양 |
|---|---|---|
| `global-cam.json` | `intrinsics.py` · `extrinsics.py` | `intrinsics` · `labToCam` · `verified` |
| `phone-cam.json` | `phone_intrinsics.py` | `intrinsics{widthPx · heightPx · fx=fy · cx=widthPx/2 · cy=heightPx/2 · dist:[0,0,0,0,0] · rmsPx · shots}` · `source{kind:"tag-layout-corners" · model:"centered-square-zero-distortion" · tagIds · capturedAt · layout · coverageX · coverageY · focalSubsetSpread · subsetRmsMax}`. 움직이는 폰이라 `labToCam`은 저장하지 않는다. Vercel 검출 실험은 배포 스크립트가 이 파일 한 장을 `/config/phone-cam.json`으로 복사한 배포 시점 스냅샷을 쓰고, 브리지·dev는 위의 디스크 정본을 요청 때마다 읽는다 |
| `global-cam-drift.json` | `watch-calib.py` (1Hz) | `t`(epoch 초) · `rmsPx`(못 쟀으면 `null`) · `maxPx` · `tags` · `reason` · `basis` |

| `scene-anchors.json` | **브리지 상주**(`anchors.py` · 2초) · 손 1회는 `anchor-pose.py` | `anchors{id: labMm · yawDeg · errPx · shot · t(epoch 초)}` — 태그가 정한 가상 소품 자리 (D135). **원자적으로 쓴다** — 쓰는 도중을 scp·화면이 집으면 찢어진 판이 나간다 (08-19 실사고) |

### 앵커 상주는 **브리지 안**에서 돈다 (2026-08-27 · D146)

`scene-anchors.json` 의 **쓰기 주인은 하나**다(D138). 그 하나를 **브리지 프로세스 안**으로
옮겼다 — 받침 추적(`fixture.py` · D131)과 같은 자리, 같은 이유다.

⛔ **사이드카로 세우지 않는다.** 윈도우 sshd 는 세션이 끊기면 자식을 거둬간다 — 옆 프로세스로
세우면 **조용히 죽고**, 파일은 마지막 값에 얼어붙은 채 화면은 초록으로 남는다. 2026-08-27 에
실제로 그 상태였다: 앵커가 **7일 낡은 기준샷**으로 서 있는데 HUD 는 `calib 0.51px · drift 1.3px`
로 전부 초록이었고, 컨베이어 둘이 **844mm·727mm** 어긋난 자리에 그려지고 있었다.

브리지 안에 두면 **생사가 하나**다 — 브리지가 죽으면 화면이 통째로 안 떠서 아무도 안 속는다.

- **미러(scp)가 필요 없다.** 호스트에서 도니 파일이 이미 그 자리에 있고 `/config` 가 그대로 낸다
- **캘리브를 따라간다** — `Chain(conf_url=…/config/global-cam.json)` 이 매 판 `refresh()` 로
  기준샷을 대조해 갈아탄다. 호스트가 스스로 재정합해도(`watch-calib --auto`) 앵커가 따라온다
- ⛔ **비전이 브리지를 죽이지 않는다** — daemon 스레드 · 루프가 예외를 통째로 먹는다 ·
  `cv2` 는 **함수 안에서 늦게 임포트**한다(없는 기계에서 브리지가 통째로 안 뜨는 것을 막는다)
- **주소를 안 주면 안 돈다** = 기능을 안 켠 것이다. 고장이 아니다(`FR5_CAM_HOST` 하나로 켠다)

⚠ **안전 경로가 아니다.** 게이트가 읽을 값은 여전히 `fixture.py` 가 낸다 — 이 상주는
**이야기 레이어**(가상 소품 자리)까지다.

**`robot-base-in-tag.json` 만 손으로 쓴다** (2026-08-10 신설). 나머지 넷은 스크립트 산출물이다.
`labToCam` 은 태그까지만 안다 — **로봇이 그 안 어디 있는지는 아무도 안 말하고 있었다.**
그래서 실측값이 2026-08-07 부터 evidence 문서에만 글자로 있었고 코드에는 0건이었다.

- **`extrinsics.py` 산출물에 끼워 넣지 않는다.** `global-cam.json` 은 생성물이라 다시 풀 때마다
  덮인다 — 손으로 잰 값을 거기 두면 조용히 사라진다. 그래서 **파일을 가른다**
- **`source` 와 `measuredAt` 이 필수다.** 이 값만 사람이 쓰므로, 출처가 없으면 다음 세션이
  어디서 왔는지 못 찾는다 (툴 0 의 `Z 135mm` 가 정확히 그 사고다)
- ⛔ **카트를 밀면 이 값은 안 변한다** — 로봇이 그 카트에 볼트로 붙어 있다. 바뀌는 것은
  바닥↔태그뿐이다 (`LAYOUT-METRICS-CONTRACT.md` §원점은 하나가 아니다). **로봇을 카트에서
  떼거나 다시 앉히면** 그때 다시 잰다
- 파생 `tcpYawFromJ1Deg` 는 **관절각에서 바로 방위를 얻는 지름길**이다 — `TCP 방위 = j1 + 7.8°`

**`global-cam-host.json` 은 주소를 박는 게 아니라 「지금 찾은 곳」이다** (2026-08-10 신설).
폰은 DHCP 라 IP 가 바뀌고, 실제로 그 때문에 `.10` 을 보던 감시가 **47시간 조용히 죽었다.**
감시기가 어차피 폰을 찾아야 하므로 **찾은 결과를 화면도 쓰게** 한 것이다 — 새 탐색 로직을
화면에 또 만들지 않는다 (하드 룰 5 와 같은 뜻).

- **사람이 준 주소가 이긴다.** 화면의 우선순위는 `?cam=` → `localStorage` → **이 파일**이다.
  이 파일은 **아무도 안 정했을 때의 기본값**이지 덮어쓰는 값이 아니다
- **없으면 404 고 그때는 카메라 칸이 안 뜬다** — 아래 §없으면 404 그대로. 주소를 아무도
  모르는 상태는 "고장"이 아니라 "안 켠 것"이다
- ⚠ **이 값을 정합의 근거로 쓰지 않는다.** 어느 폰이냐만 말하고, 그 폰이 제자리인지는
  `global-cam-drift.json` 이 말한다

⚠ **`t` 없이 `rmsPx` 만 읽으면 안 된다.** 감시기가 죽으면 파일이 **마지막 초록값으로
얼어붙고**, 나이를 안 보면 화면이 영원히 「괜찮다」고 말한다 — 이 판에서 제일 위험한 고장이다.
읽는 쪽이 `ageMs` 를 붙이고 **9초를 넘으면 「멎었다」**로 판정한다 (`Shared/data/camera/state.js`).
`t` 는 쓴 쪽 시계라 **랜 안 NTP 동기를 전제한다**(§카메라 `clock` 과 같은 전제).

**`/config` 만 빌드를 안 거친다.** 나머지 둘은 번들이라 빌드한 순간의 내용이 굳는다.

- **보정값을 번들에 넣지 않는다** (2026-08-08 · 이 절이 생긴 이유). `global-cam.json` 을
  `import.meta.glob({eager:true})` 로 읽던 동안 **페이지는 빌드 때 베낀 숫자를 외우고 있었다** —
  카메라를 다시 거치해도 화면은 몰랐고, 빌드본이 **X 로 531mm 어긋난 채** 그럴듯하게 겹쳤다.
  캘리브레이션은 사람이 재빌드해야 반영되는 값이면 안 된다
- **없으면 404 다 — 그것이 정상이다.** 이 파일들은 `scripts/map/*.py` 의 산출물이라
  캘리브레이션 전에는 없다. 읽는 쪽은 404 를 "보정 없음"으로 읽고 **"정상"으로 읽지 않는다**
  (제1원칙 · 판정은 `Shared/data/camera/state.js` 한 곳). 읽기 전용이고 쓰기는 없다
- **캐시하지 않는다** (`cache: 'no-store'`) — 여기서 굳으면 번들에 넣은 것과 같아진다
- dev(`vite`)도 **같은 주소로 같은 파일**을 낸다. 주소가 갈리면 dev 에서만 통과한다

## 상태값 (서버 → 클라이언트)

WebSocket `/ws/state`로 브로드캐스트. 접속한 전원이 같은 것을 받는다.
**주기는 33ms 를 목표로 하고 실제로는 27Hz 남짓 나온다** — 유니티 실측값이다
(`unity/unity-bridge-protocol.md` §5). 이전 판의 "초당 30회"는 낙관값이었다.

**필드 목록을 늘렸다** (2026-07-30, D20). 이전 판은 8개였고 실기에서 실제로 쓰이는 것의
절반이 빠져 있었다 — `enabled`(서보) · `inDragTeach` · `safetyStop` · `collisionDetected` ·
`mainErrorCode`/`subErrorCode` 가 없으면 **안전 판정을 할 수 없다**.
근거는 유니티가 실기에서 읽던 필드 목록이다 (`unity/unity-bridge-protocol.md`).

```jsonc
{
  "t": 1785329668.42,            // 서버 시각 (초, 소수)
  "robotId": "fr5-lab-a",       // IP가 아니라 우리 시스템의 로봇 프로필 ID
  "connected": true,
  "enabled": false,              // 서보 on/off ← 없으면 안전 게이트를 못 만든다
  "mode": 0,                     // 0=auto 1=manual **2=드래그 티칭** (실측 2026-08-10 · D106)
  "jointsDeg": [0,0,0,0,0,0],    // 6축 관절 (도)
  "tcpMmDeg":  [0,0,0,0,0,0],    // 손끝 x,y,z(mm) + rx,ry,rz(도) — mm·도가 섞여 이름에 둘 다 적는다
  "motionQueueLength": 0,        // 큐에 남은 동작 수
  "motionTarget": null,          // 마지막으로 **보낸** 이동 목표 — 아래 §이동 목표. 보낸 적 없으면 null (D196)
  "safety": {
    "code": 0,
    "emergencyStop": false,      // 비상정지
    "safetyStop": false,         // 안전정지 (별 신호다)
    "collisionDetected": false,
    "inDragTeach": false,        // 드래그 티칭 중이면 명령을 보내지 않는다
    "mainErrorCode": 0, "subErrorCode": 0, "errorText": null, "errorResettable": null  // → `FAULT-CODES.md`
  },
  "coord": { "toolId": 0, "userId": 0 },
  "coordDefs": {                 // 아래 §좌표계 정의. 못 읽으면 해당 키가 null
    "tool": [0, 0, 135, 0, 0, 0],       // 활성 툴 — 플랜지 기준 [x,y,z,rx,ry,rz]
    "user": [0, 0, 0, 0, 0, 0],         // 활성 사용자 — **베이스 기준**
    "missing": []                        // 못 읽은 키 이름 (정직하게 남긴다)
  },
  "sampleMs": 33,                // 서버가 실제로 쓰는 폴링 주기
  "gripper": { "pct": 70, "fault": false, "motionDone": true, "active": true },
  "owner": "kim",                // 조종권 보유자 (없으면 null)
  "phase": "OBSERVE_ONLY",      // 연결 상태기계 (FR5-IMPLEMENTATION-PLAN §안전 상태) — 클라이언트가 이걸 보고 조작 UI를 잠근다
  "failReason": null,            // FAIL_CLOSED 일 때만 사유 문자열
  "appliedSettings": null        // 아래 §로봇 안전 설정. arm 전에는 null
}
```

### 이동 목표 — 「어디로 가는 중인가」를 스트림이 말한다 (2026-09-07 · D196)

`jointsDeg` 는 **지금** 자세다. 이동 중에 화면(폰 XR 고스트 · 트윈)이 **목표**를 그리려면 브리지가 보낸 목표를
같이 내야 한다 — 전에는 `commands.motion` 이 컨트롤러에 넘기고 버렸다. 모든 이동(조그 · `moveJ` · 지점 · 슬롯 `step` ·
`/follow/step`)이 그 한 곳을 지나므로 기록 지점도 한 곳이다.

```jsonc
"motionTarget": {
  "jointsDeg": [0,0,0,0,0,0],   // 게이트를 **지나 컨트롤러에 보낸** 목표 관절각(도). 거부된 목표는 여기 안 온다
  "via": "jog",                 // jog | moveJ — 어느 창구가 만든 목표인가 (지점·슬롯·추종은 moveJ 로 적힌다)
  "speedPct": 10,
  "queuedAt": 1785329668.42,    // 보낸 서버 시각
  "doneAt": null                // 정착 대기(§이동 정착)가 끝난 서버 시각. **null 이면 아직 가는 중**
}
```

- **화면 규약** — `doneAt` 이 `null` 인 동안만 목표를 **반투명 고스트**로 그린다(불투명 = 실기 · 반투명 = 계획 · D195).
  끝난 목표는 지금 자세와 같으니 그리지 않는다.
- 마지막 목표는 **지우지 않는다** — 「마지막으로 어디로 보냈나」가 장부다. 연결을 끊으면 세션과 함께 사라진다.
- `stop` 은 목표를 바꾸지 않는다 — 멈춘 자리는 `jointsDeg` 가 말하고, 목표는 「가려던 곳」으로 남는다. `doneAt` 은 정착 대기가
  끝나면 찍히므로 stop 뒤에도 찍힌다 — **`doneAt` 은 도착이 아니라 「기다리기를 끝냈다」다.** 도착은 `jointsDeg` 와 대조한다.

### 공동 시각화 고스트 — 구현됨 · 로컬 검증 단계 (D227)

대시보드가 화면에 고른 **계획 고스트**를 글로벌카메라와 다른 사람의 폰 답사 화면이 같이 본다.
현재 `/ws/state` 의 `motionTarget` 은 이미 보낸 이동 목표만 말하므로, 되감기·추종 시뮬·자세
미리보기는 다른 기기로 전달되지 않는다. 화면마다 우선순위를 다시 구현하지 않고 **대시보드가
최종 선택한 한 벌**만 브리지에 보낸다.

게시 경계는 로봇 명령 WebSocket과 분리한 `/ws/visualization` 이다. 이 소켓의 메시지는
`handle_cmd`·명령 큐·SDK에 절대 들어가지 않는다. 구현은 `FR5/bridge/visualization.py`와
`Shared/data/visualization/ghost.js`에 있으며, 아직 실기 배포 확인 전이다.

```jsonc
// 대시보드 → /ws/visualization (활성 중 최소 1Hz, 최대 10Hz)
{
  "type": "ghost",
  "robotId": "fr5-lab-a",
  "kind": "preview",             // preview | replay | simulation
  "jointsDeg": [0,0,0,0,0,0],
  "gripperPct": 70,               // 모르면 null
  "seq": 42,
  "who": "kim",
  "token": "<현재 조종권 토큰>"
}

// 구현 뒤 /ws/state 에 추가되는 서버 스탬프 필드
"visualGhost": {
  "robotId": "fr5-lab-a",
  "kind": "preview",
  "jointsDeg": [0,0,0,0,0,0],
  "gripperPct": 70,
  "seq": 42,
  "operator": "kim",
  "publishedAt": 1785329668.42,
  "expiresAt": 1785329670.42
}
```

- **게시자는 한 명이다.** 현재 조종권과 맞는 대시보드 연결만 게시한다. 폰과 글로벌카메라 화면은
  읽기 전용이다. 두 번째 게시자는 기존 연결이 닫히거나 만료되기 전에는 거부 사유를 받는다.
- **2초 임대다.** 게시 소켓이 닫히거나 `expiresAt` 을 넘으면 서버가 즉시 `null` 로 만든다.
  마지막 고스트를 멈춘 사실처럼 붙들어 두지 않는다.
- **소비 우선순위는 한 줄이다.** 진행 중 `motionTarget` → 유효한 `visualGhost` → 숨김.
  실제로 보낸 목표를 화면 전용 미리보기가 덮지 못한다.
- `visualGhost` 는 동작 승인·안전 판정·실기 기록의 근거가 아니며 서버 재시작 뒤 복구하지 않는다.
- 첫 슬라이스는 로봇 관절과 그리퍼만 보낸다. 들고 있는 물체·궤적·작업영역은 소비자가 생긴 뒤
  계약을 확장한다.

### 로봇 안전 설정 — 주인은 브리지다 (2026-08-04 · D53)

우리 안전 게이트(조건 4·5·25)는 **컨트롤러가 설정돼 있어야** 값을 준다. 충돌 감지는 기본으로
켜져 있지 않고 기본 민감도는 사람 접촉에 반응하지 않는다 (`SAFETY-RULES.md` §설정이 전제다).
그래서 **ARM 할 때마다 브리지가 넣는다** — 펜던트에서 누가 바꿔도 우리 값으로 돌아온다.

robot profile(`config.yaml`)에 `settings` 블록을 둔다:

```yaml
settings:
  payloadKg: 0.6          # 말단 하중 — 그리퍼 PGE A-100-40 실측 사양
  cogMm: [0, 0, 60]       # 무게중심 (근사 — 자동 인식은 나중)
  installPos: 0           # 0=바닥 1=측면 2=천장
  collisionMode: 0        # 0=등급(1~10) 1=퍼센트
  collisionLevel: [5,5,5,5,5,5]   # 작을수록 민감 — **실기 실측으로 확정한다**
  collisionStrategy: 2    # 2=에러 후 정지
  # 충돌 감지 **후** 어떻게 서느냐. SDK 기본값을 상속하지 않고 우리가 적는다 (아래)
  collisionSafeTimeMs: 1000        # 1000~2000
  collisionSafeDistanceMm: 100     # 1~150
  collisionSafeVelMmS: 250         # 50~250
  collisionSafetyMargin: [10,10,10,10,10,10]   # 1~10
  toolCoordId: 0          # 0=툴 없음(플랜지). 캘리브레이션 전까지 0 — 아래 주의
```

⚠ `collisionSafe*` 4개는 SDK 기본인자라 **안 적으면 벤더가 고른다** — 그 기본값 중 셋이
각 범위의 가장 느슨한 끝이다. 지금 값은 기본값과 같지만 **박아서 같다.** 범위·조일 후보·
왜 아직 안 조였는지는 `SAFETY-RULES.md` §기본인자는 "안전한 기본" 이 아니다.

`/state.appliedSettings` 모양:

```jsonc
{
  "appliedAt": 1785329668.42,   // 브리지가 넣은 시각
  "sent": { "payloadKg": 0.6, "collisionLevel": [5,5,5,5,5,5], … },   // 넣은 값 그대로
  "readback": { "payloadKg": 0.6, "cogMm": [0,0,60], "toolCoord": […] },  // 되읽은 값
  "unverifiable": ["collisionLevel", "collisionStrategy", "collisionMode", "installPos",
                   "powerLimitW", "collisionSafeTimeMs", "collisionSafeDistanceMm",
                   "collisionSafeVelMmS", "collisionSafetyMargin"],
  "mismatch": []                 // 되읽기와 다른 항목 — 비어 있지 않으면 arm 거부
}
```

- **`/arm` 시퀀스에 단계가 늘었다**: 서보 ON → **설정 적용 → 되읽기 대조** →
  샘플주기 → ExitDragTeach → 자동 모드. 되읽을 수 있는 값이 다르면 **arm 을 거부**한다
- **되읽기가 없는 항목은 `unverifiable` 로 정직하게 노출한다.** "확인했다"가 아니라
  "넣었다"이다. 화면도 그렇게 표시한다
- `appliedSettings` 가 없으면 모션이 나가지 않는다 (조건 26)
- ⚠ **`toolCoordId: 0` 은 매뉴얼상 "툴 없음(플랜지 기준)"** 이지만 툴 0 에 이미
  `[0,0,135,0,0,0]` 이 들어 있다 (2026-08-04). 그 **135 는 실물 실측(플랜지→핑거 끝)과 일치**
  한다 (2026-08-05 · `STACK.md` §안전 설정 API). 남은 건 정확도가 아니라 **기준점**이다 —
  135 는 핑거 **끝**, 파지 지점은 ≈122.5mm. 지금은 관절값 + `MoveJ` 재생이라 동작은 안 바뀐다.
  좌표 기반 이동을 도입하기 전에 어느 쪽을 TCP 로 둘지 정한다 (별도 골)

`phase` 는 `DISCONNECTED → PREFLIGHT → OBSERVE_ONLY → OWNER_HELD → ARMED → EXECUTING`
+ `FAIL_CLOSED` 다 (2026-07-31, D40). 미연결이면 `robotId: null · connected: false ·
phase: "DISCONNECTED"` 스냅샷을 같은 스키마로 보낸다 — 클라이언트가 빈 응답을 따로 처리하지 않는다.
`POST /connect` 응답은 `{ ok, phase, reasons: [] }` 이며 preflight 실패는 `ok: false` +
사유 목록으로 fail-closed 한다.

**이름은 우리 규칙을 따른다** (`CODING-CONVENTIONS.md`) — 안전 관련을 `safety` 아래로 묶고
좌표계 id 를 `coord` 로 묶었다. 유니티는 이걸 플랫으로 뒀지만 우리 클라이언트는 우리 것이다.
`tcpMmDeg` 만 유니티 이름을 가져왔다 — **mm 과 도가 섞인 배열이라 그 이름이 더 정확하다.**

**단위 규칙** — 이 계약의 바깥면은 전부 **도(°)와 밀리미터(mm)**다.
라디안·미터 변환은 서버 안쪽과 3D 화면 안쪽에서만 한다.

## 로봇 프로필과 읽기 전용 사전검증

같은 FR5라도 다른 개체가 배정될 수 있으므로 IP를 로봇 정체성으로 쓰지 않는다.

```text
GET  /robots              → [{ robotId, name, model, endpoint, lastObserved, sceneId }]   # sceneId = borrowFrom ?? robotId — 구운 장면·픽스처 이름 (2026-09-06)
POST /connect             { "robotId": "fr5-lab-a", "observeOnly": true }
GET  /version             → { robotId, controller, servo, end, sdk, web, observedAt }
POST /disconnect
```

- `endpoint`는 서버 설정이며 브라우저가 임의 IP를 전달하지 않는다.
- 기본 연결은 `observeOnly=true`다. 이때 허용되는 SDK 호출은 connect/version/read-state/disconnect뿐이다.
- 모델·6축 배열·필수 안전 필드·허용 펌웨어가 맞지 않으면 연결은 보여주되 명령 상태로 승격하지 않는다.
- 프로필에 비밀번호를 저장하지 않는다. 포트 라벨이 아니라 ARP/TCP와 SDK 응답으로 실제 경로를 확인한다.

### 작업영역 — 조건 12 의 카테시안 절반 (2026-08-05 · D73)

관절 한계만으로는 **손끝이 작업대를 뚫는 것을 못 막는다.** 컨트롤러의 위치 안전망은
FR-HMI 전용 펜던트를 전제하므로 빌릴 수 없다 (`SAFETY-RULES.md` §FR-HMI) — 우리 소프트리밋이
유일한 방어선이다. 값은 **로봇이 직접 짚어** 얻는다 (`runbook/WORKCELL-MEASURE.md`).

프로필 **최상위**에 둔다. `settings` 는 *로봇에 넣는 값*이고(D53) 이것은 *우리 게이트가
쓰는 값*이라 섞으면 `appliedSettings` 되읽기 대조에 끼어든다.

```yaml
workspace:
  frame: {toolId: 1, userId: 1}     # 이 좌표계에서만 참이다
  measuredAt: "2026-08-08"          # 낡으면 화면이 그렇게 말한다
  boxes:                            # 뚫으면 안 되는 상판들 — 사각기둥
    - {name: 카트 상판, xMm: [-16.1, 842.0], yMm: [-798.2, -210.9], topZMm: -345.8, marginMm: 10}
  walls:                            # **유한 선분** — 788mm 짜리 판도 담긴다
    - {name: 옆벽, aMm: [x1, y1], bMm: [x2, y2], marginMm: 100}
```

- 판정은 **손끝**으로 한다. 목표 관절을 **로봇 자신의 `GetForwardKin`** 으로 바꾼다 — DH 를 우리가 다시 적지 않고 툴·사용자 좌표계가 저절로 맞는다
- **상판은 평면이 아니라 사각 기둥이다** — `x·y` 가 안일 때만 높이를 건다. 바깥에서는 더 내려가도 된다
- **벽은 무한 평면이 아니라 선분이다** (2026-08-08 일반화). 손끝과 선분의 **거리**가 `marginMm` 보다 가까우면 거부한다. 숫자 하나(`wallYmm`)로는 **비스듬한 벽도 유한한 판도** 못 담았다 — 카트를 돌리자 그 값이 통째로 거짓이 됐다
- **여러 개를 둘 수 있다.** 작업대가 하나 더 생기면 `boxes` 에 줄 하나다
- **`frame` 이 지금 좌표계와 다르면 거부한다.** 같은 숫자가 다른 자리를 가리킨다
- 손끝을 못 구하면 **차단**한다 (제1원칙: 결측=차단)
- **없으면 판정하지 않는다** — `/state.workspace` 가 `null` 로 노출돼 꺼진 것이 보인다
- ⚠ **천장 — 손끝만 본다.** 팔꿈치·상완은 판정 밖이라 벽 여유를 크게 잡는다

### 움직이는 장애물 — 비전이 **자리만** 준다 (2026-08-13 · D130)

받침(거치대)은 **자주 옮겨진다**(현장 확인 2026-08-13). 프로필에 박으면 옮길 때마다 사람이
고쳐야 하고, 안 고치면 게이트가 **빈 자리를 막고 진짜 받침은 안 막는다.** 둘째가 위험하다.

작업대와 갈리는 이유 하나 — **받침에는 태그가 붙어 있다**(`tags.json` `fixtureTags`).
고정물은 로봇이 짚는 게 맞고, 움직이는 물건은 자기 자리를 스스로 말할 수 있다.

```jsonc
// Shared/data/config/fixture-pose.json — scripts/map/fixture-pose.py 산출
{ "centerMm": [383.2, -1084.4, -355.6],   // **user1** — 프로필 boxes 와 같은 프레임
  "halfMm": 95, "heightMm": 86.5,
  "seenAt": 1786…, "checkedAt": 1786…, "basis": "tags-…jpg",
  "staleReason": "태그를 못 본다 — …" }        // 못 볼 때만 붙는다
```

`/state.workspace.boxes` 에 **`source` 가 붙는다** — `"profile"`(사람이 잰 값) 또는
`"vision"`(위 파일). 화면이 그걸로 색을 가른다. 없으면 `"profile"` 로 읽는다.

**⛔ 못 박는 것 다섯 — 이 조항의 전부는 「비전이 보호를 줄이지 못한다」이다**

1. **추가와 이동만 한다. 삭제는 없다.** 태그를 못 보면 **마지막 자리를 그대로 두고**
   `staleReason` 만 붙인다. 지우면 막던 것이 안 막히고, 그건 제한을 **푸는** 방향이다 —
   사람이 태그를 가리는 일이 잦다 (실측 2026-08-13: 하루에 4→3→1장)
2. **크기와 높이는 비전이 정하지 않는다.** `halfMm`·`heightMm` 는 **상수**다. 태그는 옆면에
   세워 붙어 있어 윗면 높이를 말해 주지 못하고, 크기는 실물보다 **크게** 잡는다(넓게 막는 쪽)
3. **프레임이 다르면 안 쓴다.** `user1` 을 못 받으면(로봇 미연결) 파일을 **안 만든다** —
   프레임을 모르면 틀린 자리를 막는다 (제1원칙)
4. **자세가 튀면 버린다.** 사람이 1초에 옮길 수 있는 거리를 넘으면 그건 이동이 아니라
   **한 프레임 잘못 푼 것**이다 (`fixture-pose.py` `JUMP_MM`)
5. **이것은 명령이 아니라 경계다.** `VISION-CONTRACT.md` §못 박는 것("비전은 명령을 만들지
   않는다. 제안을 만든다")은 그대로다 — 비전이 여는 것은 **막는 상자 하나**뿐이고,
   허용목록에 이름이 늘지 않는다. 승인 절차도 그대로다

⚠ **정확도의 천장** — 카메라 사슬은 핑거로 짚은 값과 **23.0mm** 에서 맞았다
(`evidence/2026-08-12/fixture-tag-chain.md`). `halfMm 95` 가 그 오차를 삼키도록 잡은 값이다.
**이 상자로 파지 좌표를 정하지 않는다** — 그건 여전히 로봇이 짚는다.

### 터틀봇도 **움직이는 장애물**이다 (2026-09-03)

```jsonc
{ "name": "터틀봇", "source": "vision", "xMm": [...], "yMm": [...], "topZMm": ...,
  "staleReason": "터틀봇을 못 본다 — …" }        // 못 볼 때만 (상자는 남는다)
```

⚠ **이 상자는 «이동 경로»가 아니다** — 한 순간의 자리다. 쓸고 지나가는 부피는 아래가 맡는다.

### 상호 배제 — **둘이 동시에 움직이지 않는다** (2026-09-03)

이동 경로를 부피로 모델링하지 않는다. **겹칠 수 있는 둘을 동시에 안 움직이게** 하는 쪽이 훨씬
싸고 안전하다. 시나리오가 이미 그 모양이다(`AMR_DROP.dwellSec` = 팔이 싣는 동안 터틀봇이 선다).

- **팔은 터틀봇이 움직이는 동안 명령을 거부한다.** 판정은 터틀봇이 스스로 말하는 `velocity`
  (이미 `ws://<tb>/ws/state` 로 받고 있다 · 관전 전용이라 명령은 여전히 안 보낸다).
- **fail-closed 는 «켰을 때만»** — `FR5_TB_HOST` 가 없으면 기능을 안 켠 것이라 안 막는다.
  ⛔ **주소를 줬는데 못 읽으면 막는다** — 「움직이는지 모른다」는 「안 움직인다」가 아니다.
- ⛔ **반대 방향(팔이 터틀봇을 세우는 것)은 안 한다** — 명령 주인은 한 명이다(하드 룰 4).

#### 조건 27 — 위 규칙을 게이트로 (2026-09-07 · D191 · 코드 0줄이던 것을 닫는다)

`SAFETY-RULES.md` §조건 27. 판정 재료는 브리지가 이미 받는 `ws://<tb>/ws/state` 의
`robots.<id>.velocity { linearMmS, angularDegS }` 와 `poseAgeSec` 다 (`amr.py` 독자 — 명령은 여전히 안 보낸다).

| 상태 | 판정 | 화면 문구 |
|---|---|---|
| 주소 없음 (`FR5_TB_HOST` 가 **빈 문자열**이거나, 변수 없고 `tb-host.json` 도 없음) | **안 막는다** — 기능을 안 켠 것. 게이트·터틀봇 없는 랩 날은 `FR5_TB_HOST=` 로 끈다 | — |
| 주소 있음 · `\|linearMmS\| > 5` 또는 `\|angularDegS\| > 3` (데드밴드 · 주차 odom 잡음 ~0.5 위) | 거부 | 「터틀봇이 움직이는 중입니다 — 멈추면 다시 누르세요 (조건 27)」 |
| 주소 있음 · 상태 나이 > 2s 또는 독자 `note` 있음 | 거부 | 「터틀봇 상태를 못 읽습니다 — 움직이는지 모른다 (조건 27)」 |

- 조그 · `moveJ` · 지점 이동 · 슬롯 `step` · `/follow/step` · 그리퍼 **전부** 이 조건을 지난다 — `commands.motion`·`gripper` 한 곳에서
- `/state.amr` 로 노출한다: `{ "host", "velocity", "ageSec", "moving": true|false|null, "note" }` — `null` 은 「모른다」다
- `stop` 은 예외다 (제3원칙)


### 터틀봇 자리는 **두 출처**로 온다 — 바퀴가 잇고 태그가 고친다 (2026-08-31 · D158)

추종의 표적(터틀봇)을 **글로벌캠 태그 하나로만** 보던 것을 둘로 늘린다. 이유는 실측이다 —
서 있는 로봇인데도 태그가 잡히는 프레임이 **45초에 2회(7%)** 뿐이었다(2026-08-31 · 태그 84mm
가 라이다 위라 화소가 모자란다 · 정합을 0.46px 로 고친 뒤에도 그대로였다).

| 출처 | 얼마나 자주 | 무엇이 강한가 | 무엇이 약한가 |
|---|---|---|---|
| **태그** (글로벌캠) | 7% | **절대 위치.** 밀리지 않는다 | 거의 안 보인다 |
| **바퀴** (터틀봇 odom) | 100% (`poseAgeSec 0.0`) | 끊기지 않는다 · **요각까지 준다** | 시간이 갈수록 **밀린다** |

⭐ **약점이 정확히 서로를 메운다.** 바퀴로 잇고, 태그가 보일 때마다 눈금을 고친다.
그러면 태그가 7% 여도 된다 — 태그의 일이 **실시간 추적이 아니라 눈금 교정**이 되기 때문이다.

- **브리지가 터틀봇에 붙는다** — `ws://<tb>/ws/state` 를 **받기만** 한다(`FR5_TB_HOST` 하나로
  켠다 · 안 주면 안 돈다 = 기능을 안 켠 것이다). 앵커 상주와 **같은 자리, 같은 이유**로
  브리지 프로세스 안이다(위 §앵커 상주 · D131·D146)
- ⛔ **명령은 안 보낸다.** 조종권은 터틀봇 화면이 가진다 — 여기는 읽기 전용이다(하드 룰 4)
- **맞춘 좌표계는 파일로 남는다** — `Shared/data/config/amr-frame.json`(`odom → lab` · **브리지가 만드는 산출물**이라 레포엔 없다 · gitignore).
  브리지가 죽어도 눈금이 안 사라진다. 쓰기 주인은 브리지 하나다

#### `/state.follow.target` 이 **출처를 말한다**

```
target: {
  user1Mm, labMm, yawDeg,
  source: "tag" | "odom",     // 이 숫자가 어디서 왔나
  ageS,                        // 그 출처의 나이
  correctedAgoS,               // 태그가 마지막으로 눈금을 고친 지 몇 초 (source=odom 일 때)
  fit: { n, rmsMm, yawDeg, fittedAt } | null
}
```

⛔ **`source` 없이 좌표만 내지 않는다.** 「이름은 맞는데 값이 틀린」 사고(D155)의 재발 방지다 —
숫자가 같은 모양이어도 **어디서 왔는지에 따라 믿을 범위가 다르다.**

⛔ **실기를 움직일 때(단계 3)는 `source: "odom"` 만으로 안 된다.** 태그가 최근에 고쳐 준
적이 있어야 한다(`correctedAgoS` 상한 · 프로필 값). 바퀴는 헛돌아도 **태연히 틀린 값을 낸다** —
2026-08-19 에 사람이 몰던 터틀봇이 제자리인데 odom 은 **428mm 밖**이라고 했다.
지금 단계 2(시뮬·미리보기)에서는 그 상한을 안 건다 — **팔이 안 움직이기 때문**이다.

### 좌표계 정의 — 숫자만으로는 어디인지 모른다 (2026-08-07 · D87)

`coord` 는 **몇 번을 쓰는지**만 말하고 **그게 어디인지**는 말하지 않는다. 실제로 `user1` 이
베이스에서 `(−401.8, +497.3, +342.1)` 떨어져 있어 로봇이 자기 밑의 판을 `(305, −516)` 으로
보고했고, 하루를 잃었다 (`evidence/2026-08-07/workcell-remeasure.md`).

```
GET /state → coordDefs: { tool: [...6]|null, user: [...6]|null, missing: [이름] }
```

- **읽기 전용.** `GetCurToolCoord` · `GetActualWObjNum` → `GetWObjCoordWithID` 를 그대로 싣는다
- **`user` 는 베이스 기준**이다. 이게 있어야 화면이 `workspace` 를 제자리에 그린다
- 못 읽은 키는 `null` + 이름을 `missing` 에 — 0 으로 채워 아는 척하지 않는다
- ⛔ **바꾸는 명령은 만들지 않는다.** 좌표계를 바꾸면 위 `workspace` 가 통째로 거짓이 되고
  게이트가 엉뚱한 자리를 지킨다. **바꾼 뒤 다시 재는 것까지가 한 절차**다 — 버튼이 아니다

## 명령 (클라이언트 → 서버)

WebSocket 같은 연결로 올린다. **조종권을 가진 클라이언트의 명령만 실행한다.**
신원은 TB 와 같은 hello 바인딩이다 (2026-07-31, D41) — `stop` 만 hello 없이도 받는다.

```jsonc
{ "cmd": "hello",   "who": "kim", "token": "…" }   // 이 연결의 신원. 명령 전 1회 (토큰은 §조종권)
{ "cmd": "jog",     "joint": 2, "deltaDeg": 1.0 }
{ "cmd": "moveJ",   "jointsDeg": [0,0,0,0,0,0], "speedPct": 10 }
{ "cmd": "gripper", "pct": 30 }         // 아래 §그리퍼. open:true/false 는 별칭
{ "cmd": "gripperActivate" }
{ "cmd": "mode",    "manual": true }    // 아래 §모드 전환. 로봇을 움직이지 않는다
{ "cmd": "stop" }                       // 조종권·신원 없어도 항상 받는다. 아래 §정지
```

### 정지는 소켓 하나에 걸지 않는다 (2026-08-10 신설)

`SAFETY-RULES.md` §제3원칙 「도착까지가 규약이다」의 계약 쪽 절반이다. **판정은 이미 옳았고
전송이 비어 있었다** — WS 하나에만 걸려 있어 ①앞 명령이 처리되는 동안 밀리고 ②그 소켓이
막히면 정지 수단이 사라졌다.

```text
POST /stop   { }   → { ok }        // 본문 없음. 조종권·신원·phase 를 묻지 않는다
```

- **새 명령이 아니다 — 같은 `stop` 의 두 번째 전송로다.** 허용목록(§명령 승격)은 그대로
  다섯이며 여기에 이름이 늘지 않는다. 격리는 구조가 보증한다 (감사 P1)
- **인자를 받지 않는다.** `who`·`token`·대상 관절을 요구하는 순간 그게 정지를 막는 조건이 된다
- **서버는 WS 수신을 직렬화하지 않는다** — `stop` 은 받은 자리에서 처리하고 나머지를 큐에 넣는다.
  이동 중 `stop` 이 이동이 끝난 뒤 실행되면 계약 위반이다
- **화면은 둘 다 쏘고 실패를 표시한다.** WS 와 `POST /stop` 을 함께 보내고, 둘 다 실패하면
  버튼이 **실패를 사람에게 보여준다.** 반환값을 버리면 "눌렀는데 안 섰다" 가 숨는다
- **멱등이다** — 이미 서 있어도 `ok` 다. 중복 호출이 사고가 되지 않아야 둘 다 쏠 수 있다

### 모드 전환 — 펜던트에게 조작을 넘긴다 (D72)

`ARM` 이 `SetMode(0)` 을 부르므로 한 번 ARM 하면 펜던트가 잠기고, `DISARM` 은 안 되돌린다.
`mode` 가 그 되돌리기다. 왜 이 모양인지는 **D72** 에 있다.

- 로봇을 움직이지 않는다 — 권한만 넘긴다. 조종권자만 · 모션 큐 0 · 신선도 게이트
- **`ARMED` 에서도 받는다** — 드래그는 서보가 켜져 있어야 되므로 DISARM 을 선행으로
  걸면 잠금을 못 푼다. 하드 룰 4 는 `check_motion` 의 `mode != 0` 이 지킨다
- ⚠ **드래그 티칭은 웹에서 켜지 않는다** — 팔을 푸는 것은 펜던트의 3위치 인에이블
  스위치다 (`SAFETY-RULES.md` §FR-HMI). `inDragTeach` 는 **읽기만** 한다
- **`mode` 는 셋이다 — 2 가 드래그다** (실측 2026-08-10 · D106). `{ "cmd": "mode" }` 는
  0↔1 만 오간다. **2 로 가는 길은 이 계약에 없다** — 그래서 위 ⚠ 가 구조로 성립한다.
  ⚠ **`mode` 와 `inDragTeach` 는 원자적으로 안 바뀐다**(전환 순간 6표본 관측). 안전 판정은
  `mode` 가 아니라 **`inDragTeach` 하나로** 한다 (조건 25). `mode == 2` 를 게이트 조건으로
  쓰면 전환 구간에 구멍이 생긴다. 근거 `evidence/2026-08-10/drag-teach-kill.md`

### 명령 승격 — ARMED (2026-07-31, D41)

observe-only 연결은 명령을 받지 않는다. 승격은 별도 REST 한 번이며 **서버가 SAFETY-RULES 의
게이트를 전부 통과시켜야** `phase: ARMED` 가 된다. 실행 순서는
**서보 on → 안전 설정 적용·되읽기 대조(2026-08-04 신설, 위 §로봇 안전 설정) →
SetRealtimeStateSamplePeriod(33) → ExitDragTeach → SetMode(0)** 이다.
설정을 넣지 못했거나 되읽기가 어긋나면 **거기서 멈추고 arm 을 거부**한다.

```text
POST /arm     { "who": "kim", "token": "…", "confirm": "현장확인" }   → { ok, phase, reasons }
POST /disarm  { "who": "kim", "token": "…" }                        → 서보 내리고 OBSERVE_ONLY 로
```

- `confirm: "현장확인"` 리터럴이 없으면 거부 — 현장에 사람이 있음을 클라이언트가 명시한다
- 조종권 보유자만 arm 할 수 있고, 조종권을 잃으면 서버가 disarm 한다.
  **arm 시퀀스가 끝나는 순간에도 조종권을 다시 확인한다** — 시퀀스는 수 초가 걸려 그 사이
  자동 해제가 돌 수 있고, 그러면 주인 없는 ARMED 가 남는다 (2026-08-03 감사 P0, 수리됨)
- jog/moveJ/gripper 는 `ARMED` 에서만, 매 명령마다 안전 게이트를 다시 통과해야 실행된다
- **실기에 닿는 명령은 허용목록으로 고정한다** — `jog`·`moveJ`·`gripper`·`mode`·`stop`·**`speed`**
  여섯뿐이고, 그중 **로봇을 움직이는 것은 앞의 셋**이다 (`mode` 는 권한만 넘긴다 · `stop` 은
  세운다 · `speed` 는 **배수만 바꾼다**). 재생·시뮬·모방학습 재현은 이 목록에 새 이름을 더하지
  않는 한 하드웨어에 닿을 수 없다. 격리를 주석이 아니라 구조가 보증한다 (감사 P1)

### 에이전트가 명령 주인이 될 때 — **기록이 거짓말하지 않는 것이 전부다** (2026-08-27 · D152)

2026-08-27 에 에이전트(Claude)가 처음으로 실기를 움직였다 — 손목 J6 를 −90°(조그 5°×18).
그전까지 이 계약은 **누가 명령하는가**를 「사람」으로 가정하고 쓰였다. 가정을 명시로 바꾼다.

⭐ **막는 것은 「기계가 명령하는 것」이 아니라 「기계가 사람인 척하는 것」이다.**
`who` 가 그 경계다 — 에이전트는 **자기 이름으로** 조종권을 잡고 arm 한다. 로그에
`ARMED who=claude` 로 남으면 감사가 「이건 기계가 올렸다」를 나중에 가릴 수 있다.
⛔ **사람 이름을 빌려 쓰지 않는다.** 그 순간 이 계약의 모든 방어선이 뜻을 잃는다.

#### `confirm: "현장확인"` 은 **에이전트가 스스로 못 만든다**

이 리터럴의 뜻은 *"현장에 사람이 있다"* 이고, 그건 **에이전트가 관측할 수 없는 사실**이다.
그래서 에이전트가 쓸 수 있는 경우는 하나뿐이다 — **사람이 이번 세션에서 명시로 지시했고,
에이전트는 그 지시를 전달할 뿐**일 때.

| 되는 것 | ⛔ 안 되는 것 |
|---|---|
| 사람이 *"네가 해봐 / 진행해"* 라고 한 뒤 그 세션에서 arm | 사람 지시 없이 arm |
| `who` 를 **에이전트 이름**으로 | 사람 이름·빈 이름으로 |
| 예약·크론·재시작 훅에서 **arm 금지** | 사람이 자리에 없을 때 arm |

⚠ **지시는 세션을 넘지 않는다.** 어제의 승인으로 오늘 arm 하지 않는다 — 사람이 그 자리에
있는지가 매번 달라지기 때문이다. 이 계약이 지키려는 것은 권한이 아니라 **그 사실**이다.

#### 에이전트가 지켜야 하는 것 넷

1. **게이트에 먼저 태운다** — `safety.check_workspace` 로 목표를 미리 판정하고, 거부면 안 보낸다.
   보내 놓고 거부를 받는 것과 다르다: 사람이 「왜 안 가지」를 로봇 앞에서 겪지 않는다
2. **제일 작은 동작을 고른다** — 08-27 에 팔을 옮기는 대신 **손목만** 돌렸다(TCP 불변).
   같은 목적을 이루는 두 경로가 있으면 **TCP 가 덜 움직이는 쪽**이다
3. **상한을 안 넘긴다** — 조그 1회 **5°**. 큰 회전은 **쪼갠다**(그날 18회). 상한을 올리지 않는다
4. **끝나면 놓는다** — `disarm` → `owner/release`. 문서 작업·측정 대기 동안 ARMED 로 두지 않는다

#### ✅ 비전이 낸 자리로 가는 길이 **생겼다** (2026-09-04 · D165)

`POST /follow/step` 이 그 창구다 (`VISION-CONTRACT.md` §한 번만 간다). 아래 문단은 그 창구가
없던 때의 기록으로 남긴다 — **왜 조그를 18번 쪼갰는지**가 거기 적혀 있고, 그 이유가
사라졌다는 사실이 이 계약에서 제일 중요한 변화이기 때문이다.

✅ **`POST /proposal`(§제안)은 2026-09-07 저녁 열렸다** — 아래 §제안 요약. `follow/step` 은 **추종 표적 하나**로
좁힌 길이라 임의 좌표를 받지 않는다 — 좌표를 본문으로 받는 순간 게이트 밖의 자리를
누구나 밀어 넣을 수 있고, 그건 §제안이 사람 승인을 요구하는 이유 그대로다.

#### 그전까지 없던 것 — 비전이 낸 자리로 가는 길 (2026-08-27 기록)

`POST /points` 는 **지금 자세만** 저장하고 `goto` 는 **저장된 지점만** 간다. 임의 목표는
WS `moveJ`·`jog` 뿐이다. 즉 **「검출이 낸 좌표로 간다」가 계약에 없다** — 그 자리는
`VISION-CONTRACT.md` §제안(`POST /proposal`)이고 **2026-09-07 저녁에 열렸다**(사다리 7).

#### 제안 요약 — 구현된 모양 (2026-09-07 · 정본은 `VISION-CONTRACT.md` §제안)

```text
POST /proposal   { kind, source, label, jointsDeg[6], targetPose?{tcpMmDeg} }
                 → { ok, proposalId, verdict: needsHumanConfirm | rejected, reason, reasons[], expiresAt, speedPct }
GET  /proposals  → { proposals: [...] }            대기 중(수명 90초 안)만
POST /proposal/{id}/approve { who, token }         조종권 + ARMED + 수명 안 → `moveJ` 로 번역(경로 훑기 · 속도 상한 10%) · 응답은 도착 뒤
POST /proposal/{id}/reject  { who, token }
```

- **판정만 한다.** 제안은 `/ik` 와 같은 함수(`cmds.motion(dry_run)`)로 경로를 훑어 통과/거부만 낸다 — 팔은 안 움직인다.
- **승인이 실행이다.** 승인은 조종권(`owner_gate`)·ARMED·수명(90초)을 보고 같은 게이트(조건 1~27)를 **처음부터 다시** 탄다. 한 제안은 한 번만 실행되고 재시작이면 전부 사라진다.
- **`auto` 는 안 열었다.** 전부 `needsHumanConfirm` — 화면(시뮬 탭 ③)에선 고스트를 본 사람이 누르는 「실기」 버튼이 승인이다.
- **제한 실행 S0~S3만 열었다(2026-09-10).** 사람이 마지막 단계·현장확인을 고정하고
  `자동 작업 시작`을 누르면 S2의 관측·재중심 제안을 같은 승인 범위에서 직렬 실행하고,
  S3 계획이 끝나는 즉시 HOLD한다. `auto` verdict나 새 엔드포인트는 없으며, S4 집기·그리퍼·
  터틀봇 명령은 0건이어야 한다. 새 runId·상한 불변·재접속 뒤 자동 재개 금지의 정본은
  `VISION-CONTRACT.md` §제한 실행 S0~S3과 `plan/AUTOMATIC-SEQUENCE-STAGE-GATES.md`다.
- **왜 열었나.** WS `moveJ` 5° 상한 때문에 손목 반 바퀴가 5° 조각 38개(5분)였다(실기 2026-09-07 15:58). 경로를 훑는 창구는 정착 상한 60초(D94 · 10% 에서 172°)만 있어 189° 가 2번(약 70초)이 된다. 화면 조각은 `motion-chunks.BIG_CHUNK_DEG=120`.
- `jointsDeg` 를 받는 이유 — 화면이 `/ik` 에 **직전 칸의 해**를 참조로 넘겨 푼 해를 그대로 보내야 가지가 안 갈린다(§/ik 2026-09-06). `targetPose` 는 기록용이다.

08-27 에 에이전트가 조그를 18번 쪼갠 것이 그 구멍의 증거다. 목표는 계산으로 나왔는데
**보낼 창구가 없어서** 사람이 가르친 자리로만 갈 수 있었다.

### `speed` — 전역 속도 오버라이드 (2026-08-12 · 여섯 번째 명령)

```jsonc
{ "cmd": "speed", "pct": 30 }        // **10~30** 정수. 0 도 1~9 도 거부한다
```

**왜 여섯 번째를 열었나** — 이 값이 `0` 이면 **외부 이동이 전부 거부된다**(`code=172`
"Motion Speed Cannot Be 0"). 2026-08-12 에 그걸로 반나절을 태웠는데 **화면에 그 값이 보이지도,
고칠 수도 없었다**. 원인이 화면 밖에 있으면 다음에도 못 본다.

- **조종권 필요 · `ARMED` 는 불필요** — 배수는 ARM 전에 정하는 것이 자연스럽고, 이동이 아니다
- **상한 `30`.** 그 이상은 **펜던트에서 사람이** 한다. 이 값은 `vel`(우리 상한 10%)에 곱해지는
  배수라, 화면에서 크게 올릴 수 있으면 상한 10% 의 의미가 사라진다
- **하한 `10`. `0` 도 `1~9` 도 거부한다.** ⛔ **위험은 내리는 쪽이다** — `0` 은 이동을 전부
  막지만(`172`) **`1~9` 는 더 나쁘다**: 이동은 되면서 몇 배 느려지는데 대기 계산이 따라가지
  않으면 응답이 「도착」인데 로봇은 아직 간다(겹침 · D89). 처음에 하한 1 로 열었다가
  「누르면 겹침을 만드는 버튼」임을 깨닫고 올렸다
- ⛔ **이동 대기가 이 값에 비례한다 — 늘리기만 하고 절대 줄이지 않는다**
  (`commands.settle_factor`). 기준선 `30%`(현재 확보값)보다 **낮으면 비례로 늘리고**,
  **높아도 줄이지 않는다** — 기준선이 **가정**이라(28.9°/s 를 잰 날의 오버라이드가 기록에 없다)
  줄이는 방향으로 틀리면 그게 곧 겹침이다. 틀려도 손해가 **「느림」쪽으로만** 나게 둔다.
  **`모름` 이면 허용 하한(10%)을 가정해 3배로 기다린다** — 그래서 조작대에서 값을 한 번
  눌러 주는 것이 대기를 짧게 만드는 길이다
- ⛔ **되읽기가 없다.** SDK 에 `SetSpeed` 만 있고 **getter 도 구조체 필드도 없다.** 그래서
  `/state` 는 **우리가 마지막에 보낸 값**을 `speedOverridePct` 로 싣고, **`source: "sent"`** 를
  붙인다. 화면은 그것을 **실측이 아니라고 표시해야 한다** — 펜던트에서 누가 바꾸면 우리 값은
  거짓이 된다. **거짓 확신을 주는 것이 값을 안 보여주는 것보다 나쁘다**
- ⚠ **이 값을 바꾸면 이동 대기 계산이 흔들린다** — `JOINT_DEG_S_AT_FULL`(28.9°/s)은 특정
  오버라이드에서 잰 값이다. 바꾼 뒤에는 다시 재야 하고, 재기 전에는 대기가 짧아 겹칠 수 있다
  (`Shared/data/workcell.js` §각속도 · D89)
- `POST /disconnect { "who", "token" }` — 주인이 있으면 주인만 끊는다. 남의 실행을 아무나 중단시키는
  것도 사고다 (감사 P1, 수리됨). 주인이 없으면 누구나 끊을 수 있다

### 그리퍼 (P3 · 실물 PGE A-100-40 · 대환 · 말단 1번 포트)

```jsonc
{ "cmd": "gripper", "pct": 30 }      // 0~100. open:true/false 는 pct 의 별칭으로 남긴다
{ "cmd": "gripperActivate" }         // 활성화(ActGripper). 손가락이 실제로 움직인다 — 사람이 누른다
```

`gripperActivate` 를 **ARM 시퀀스에 넣지 않는다** (2026-08-04 · D65). 활성화는 원점을 잡는
**물리 동작**이라, 서보를 올리는 것과 같은 순간에 손가락까지 움직이면 사람이 예상하지 못한다.
조종권자가 화면에서 따로 누른다.

- **관절이 아니다** — 5°·URDF 한계·모션큐 게이트는 걸지 않고, 그리퍼 전용 게이트를 탄다:
  조종권 · ARMED · 상태 신선도 · `gripperFault` 없음 · 힘 상한. 관절 게이트를 그대로
  복붙하면 통과할 수 없거나 엉뚱한 값으로 판정한다 (감사 P1)
- ~~지령 pct 와 읽기 pct 는 방향이 반대다~~ → **모드 문제였다. 변환은 없다** (2026-08-04).
  유니티 실기 기록: `before auto mode + DAHUAN: 0% → position=96 · after auto mode: 0% → 0`
  (`unity/unity-bridge-protocol.md` §6). 8/3 스모크는 브리지를 끄고 **수동 모드**에서 쟀다.
  우리 ARM 은 `Mode(0)` 자동이라 실측이 곧다 — `지령 30·70·100 → 읽기 30·70·100`.
  **그래서 `pct` 한 벌만 싣는다.** 두 벌의 숫자도, 변환표도, `calibrated` 깃발도 없앴다 —
  없는 문제를 위한 구조를 남기지 않는다
- **읽기는 명령 직후가 아니라 약 5초 뒤에 수렴한다** (유니티 실측). 즉시 판정하면 오판한다 —
  이동 중 값으로 결론을 내리지 않는다 (8/3 의 "방향 반대" 가 그 실수였다)
- ⚠ **`maxtime` 은 `vel` 에서 유도한다 (상수 금지).** `vel 30% + maxtime 3000ms` 로 보냈다가 정상 이동이 상한과 겹쳐 컨트롤러가 `8/1 Gripper Movement timeout` 을 **래치**했다 — 전원 재투입이 필요했다 (2026-08-04 실측)
- `gripper_maxtime_ms(vel)` = 행정(**115**/vel 초) × 여유 3배 → `vel 30 → **11500ms**`. SDK 상한 30000ms 라 **속도 하한은 11.5%** 이고, 그 아래는 자르지 않고 **거부**한다.
  ⚠ **행정 상수가 1.0 → 1.15 로 정정됐다** (2026-08-11 10Hz 실측 · `vel 30` 전 행정 닫기 3.54s · 열기 3.68s). 옛 값이면 대기가 3.333초라 **0.21~0.35초 짧아** `wait=True` 인 `grip` 칸이 **손가락이 움직이는 중에** 다음 칸으로 넘어갔다. 하한 10% → 11.5% 는 그 결과이고, 코드에서 **유도값**이라 손으로 안 적는다. ⚠ 속도 한 점(30%)에서만 쟀다 — 선형 가정은 미검증
- ⛔ **파지 성공은 `pct` 로 판정한다. `motionDone`·`fault` 로 판정하지 않는다** (2026-08-11 킬실험).
  같은 목표 `0` 에 도달값이 **빈 손 `0` · 탄 `24` · 펜 `27`** 로 갈리는데 `motionDone` 은 **셋 다
  `true`**, `fault` 는 **셋 다 `false`** 였다. 완료 신호가 **성공 여부를 말하지 않는다.**
  규칙 — **`|pct − 목표| ≤ ε` 면 도달, 남으면 그만큼이 물체다.**
  `pct × 0.4mm` 가 벌어짐이고(총 행정 40mm), 탄 `24` → **9.60mm** 가 5.56×45 케이스 지름
  규격과 같다 — **손이 「무엇을 물었나」를 스스로 말한다**(비전 결과의 교차검증선).
- ✅ **`maxtime` 을 계속 세지 않는다 — 속도·힘의 화면 노출을 막던 선행이 해소됐다** (같은 실험).
  막힌 닫기 **2.91~3.12s** 가 자유 닫기 **3.54s** 보다 **짧다.** 래치도 지연도 없었다.
  그리고 **force 30% 로 5.56 탄을 물고 사람이 당겨도 11.38초간 `pct` 변화 0**이었다.
  ⚠ 단 **힘 하한·변형 한계는 아직 안 쟀다** — 올리려면 `SAFETY-RULES.md` §그리퍼 힘 상한대로
  실물로 재서 등재한다 (GAP 100행 OPEN 유지).
- ⚠ **함정 둘 — 읽은 값을 그대로 믿지 않는다** (2026-08-11 실측 · 8구간 전부):
  ① **이동 시작 시 한 샘플이 `pct = 0` 으로 온다.** **열기 시작에서도** 0 이다(실제로는 100 에서
  출발한다). `pct == 0` 을 「닫혔다」로 읽으면 **모든 이동 시작에서 참**이 된다. 기전 미확인
  ② **`motionDone` 이 최종 도달보다 0.12~0.25초 먼저 뜬다**(`32→27` · `95→100` · `3→0`).
  **done 을 본 순간의 `pct` 를 쓰지 않는다** — 펜에서 done 시점 32 vs 실제 27 로 **2mm** 차다
  근거 — `evidence/2026-08-11/grip-kill-experiment.md`
- `state.gripper` 는 `{ pct, fault, motionDone, active }` 를 싣는다.
  못 읽으면 `missing` 에 올려 fail-closed 로 넘긴다
- ✅ **필드 순서 문제는 `GetGripperMotionDone` 을 안 써서 없앴다** (2026-08-04 · D65).
  그 xmlrpc 는 **자리로 구분하는 튜플**이라 `[fault, status]` 가 뒤집혀도 알아챌 방법이 없다
  (실측 `[1, 0]`). 대신 20004 실시간 구조체의 **이름 붙은 필드**를 읽는다 —
  `gripper_motiondone` · `gripper_fault` · `gripper_active` · `gripper_position`.
  이름으로 오는 값은 순서가 섞이지 않는다. xmlrpc 왕복도 사라진다
- `active` 는 **비트마스크**다 — `gripper_active` 의 bit N 이 그리퍼 N번. 우리 것은 1번 포트
- 프로필에 그리퍼 정체(`company: 4` 대환 · `device: 0` · 포트 1)를 등재하고 preflight 가
  대조한다 — 다른 그리퍼가 달린 개체에서 같은 지점을 재생하면 파지 폭이 달라진다

## 조종권

```
POST /owner/claim   { "who": "kim" }              → { ok, owner, token }  아니면 409
POST /owner/release { "who": "kim", "token": … }  → 반납
```

조종권이 없는 사람은 **화면을 볼 수는 있지만 움직임 명령은 거부된다.**
지난 프로젝트에서 화면 두 개가 동시에 명령을 보내 충돌한 적이 있어 이 규칙은 어차피 필요하다.

### 이름이 아니라 토큰이 조종권을 증명한다 (2026-08-04 · D55)

**이름만으로는 안 된다.** 조종권자 이름은 `/state` 로 전원에게 브로드캐스트되므로,
화면만 보면 남의 이름으로 `hello` 를 보내 그 사람의 조종권으로 명령을 낼 수 있었다
(감사 P0). 그리퍼가 붙으면 사람 손과 접촉할 일이 늘어 위험도가 오른다.

- `claim` 이 **1회용 토큰**을 발급한다. 조종권을 요구하는 모든 호출이 이 토큰을 싣는다 —
  `hello` · `/arm` · `/disarm` · `/owner/release` · `/disconnect`(주인이 있을 때)
- **`stop` 은 그대로 신원 없이 통과한다** (제3원칙). 정지를 막는 조건은 만들지 않는다
- 토큰은 반납·자동 해제 때 폐기된다. 다시 잡으면 새 토큰이다
- 클라이언트가 조종권 거부(`조종권이 없다`·`owner 불일치`)를 받으면 저장한 토큰을
  즉시 폐기하고 **다시 잡기**를 열어야 한다. 만료된 토큰을 "내 것"으로 표시해 복구 버튼을
  숨기면 안 된다. 보유 중에도 사람이 누르는 **다시 잡기** 경로는 남긴다. 자동 claim 하거나
  토큰 검사를 생략하지 않는다
- **로그인이 아니다** (D41 유지) — 사람을 인증하는 게 아니라 **세션을 묶는** 것이다.
  누구나 조종권을 잡을 수 있고, 잡은 뒤에는 그 세션만 명령할 수 있다
- 이름(`who`)은 **화면 표시용**으로 계속 쓴다 — 누가 잡고 있는지 팀이 봐야 한다

## 이동 지점 (P3 Teach)

```
GET    /points            → [{ ...아래 스키마 }]
POST   /points            { "who": "kim", "name": "P1" }   // 값은 서버가 현재 상태에서 찍는다
DELETE /points/{name}     { "who": "kim" }                  // 참조 슬롯이 있으면 409
POST   /points/{name}/goto { "who": …, "token": …, "speedPct": 10 }  // 1~10, 없으면 10. ARMED 필요 · 아래 §경로 검사
```

**쓰기는 조종권자만.** 읽기는 누구나 (D44 · 감사 P1). 클라이언트가 좌표를 올리지 않는
이유는 화면이 보낸 값과 실제 자세가 다를 수 있어서다 — **캡처의 정본은 서버가 읽은 상태**다.

```jsonc
{ "name": "P1",
  "jointsDeg": [...], "tcpMmDeg": [...],
  "gripperPct": 62,                 // 캡처 순간 실측 개폐 (없으면 null — 감사 P0)
  "toolId": 0, "userId": 0,         // 캡처 당시 좌표계
  "capturedRobotId": "fr5-lab-a",   // 개체 귀속 — 다른 개체에서 재생하면 경고
  "capturedAt": "2026-08-03T…" }
```

- **캡처도 신선도 게이트를 탄다** — `lastStateAt` 이 0.5초보다 낡으면 거부한다. 캐시된 값을 굳히면 그 오차가 이후 모든 실행에 실린다 (감사 P2)
- **같은 이름이면 덮어쓴다(재교시).** 그 지점을 쓰는 승인 슬롯은 풀리고 응답 `unapproved` 에 실린다 — `PROGRAM-CONTRACT.md` §재교시
- **지점은 하드 삭제하지 않는다.** 참조하는 슬롯이 있으면 보관(archive)만 — 승인된
  리비전이 깨진 참조를 가리키면 실행 시점에야 드러난다 (감사 P1)
- **좌표계가 다르면 실행을 막는다** — 지점의 `toolId`/`userId` 가 현재 세션과 다르면
  슬롯 승인·실행에서 fail-closed. 그리퍼 장착 전(tool0) 지점을 장착 후에 재생하면
  TCP 오프셋만큼 어긋나 파지 실패가 아니라 충돌이 된다 (감사 P0)

### 지점 이동은 경로를 먼저 훑는다 (2026-08-05 · D75)

`goto` 는 **`moveJ` 로 번역**된다 — 허용목록에 새 이름을 더하지 않는다. 다만 조그용
**5° 상한(`JOINT_DELTA_CAP_DEG`)을 그대로 태우면 5° 밖의 지점은 영원히 못 간다.**
그 상한의 진짜 이유는 **경로가 검사되지 않는 것**이므로, 상한을 빼는 대신 **경로를 검사한다.**

1. 현재 자세 → 목표를 **관절 공간에서 5° 간격으로 보간**한다 (`MoveJ` 가 실제로 가는 길)
2. 표본마다 `GetForwardKin` 으로 손끝 위치를 구해 **작업영역 게이트를 전부 통과**시킨다
3. 하나라도 막히면 **보내지 않고** 몇 번째 표본이 왜 막혔는지 돌려준다
4. 전부 통과하면 `moveJ` **한 번**으로 매끄럽게 간다

- 나머지 게이트(신선도·서보·auto·모션큐·드리프트·URDF 한계)는 **그대로**다. **속도만 `speedPct` 로 고른다** — 1~10, 없으면 10. 상한(10%)은 서버가 지키고 넘으면 거부다 (하드 룰 3). 처음 만든 지점을 처음 눌러 볼 때 천천히 가려는 것이다
- 표본은 움직이기 **전에** 구한다 — 이동 중 xmlrpc 를 두드리지 않는다 (그리퍼 폴링 사고 계열)
- 작업영역이 없는 프로필이면 경로 검사도 없다. **그때는 지점 이동을 열지 않는다** —
  검사할 수단이 없는데 상한만 푸는 것이 제일 위험하다
- ⚠ **여전히 손끝만 본다.** 팔꿈치·상완은 경로에서도 판정 밖이다 (D73 천장 그대로)

### 손끝 자리 → 관절각 (`POST /ik` · 2026-08-13 · D131)

**로봇을 움직이지 않는다.** 「저 자리로 갈 수 있나」와 「가는 길이 게이트를 통과하나」 둘만
답한다. 비전이 낸 자리를 **보내기 전에** 판정하는 것이 목적이고, `/proposal` 승인이 `moveJ` 로
번역될 때 쓰는 것과 **같은 경로**다 (`VISION-CONTRACT.md` §제안 — 비전 전용 실행문을 만들지
않는다). PRD §범위 밖의 「역기구학」은 **비전 제안에 한해** 열려 있다 (D131).

```
POST /ik  { "tcpMmDeg": [x, y, z, rx, ry, rz], "refJointsDeg"?: [j1..j6] }
  →
  { "jointsDeg": [j1..j6] | null,
    "reachable": true | false,
    "reason": null | "해가 없다 — 도달 밖이거나 그 자세가 불가능하다",
    "gate": { "ok": true|false, "reasons": [...] } }
```

- **조종권도 ARMED 도 요구하지 않는다.** 컨트롤러에 묻기만 하므로 관측 상태에서 답한다
- **해는 참조 자세에 가장 가까운 것으로 고른다** (`GetInverseKinRef`). 같은 손끝 자리를 여러
  관절 조합이 만들고, 참조가 없으면 **팔이 통째로 뒤집힌 해**가 나와 경로 검사가 헛돈다.
  참조는 `refJointsDeg`(6개 · 도)가 있으면 그것, 없으면 **지금 자세**다. 여러 칸을 잇는 화면(시뮬 탭 9칸·관측 칸)은
  **직전 칸의 해**를 참조로 넘긴다 — 전부 지금 자세를 참조하면 칸마다 가지가 갈려 관절이 165° 를 오가는 칸이
  생긴다(실측 2026-09-06: 관측 칸 셋이 각 57초). `gate` 는 참조와 무관하게 **지금 자세에서 그 해까지**를 검사한다
- `gate` 는 **§지점 이동의 경로 검사를 그대로 태운 결과**다 (D75) — 관절 공간 5° 보간 ·
  표본마다 `GetForwardKin` · 작업영역 판정. **새 판정을 만들지 않는다**
- ⚠ **통과해도 움직이지 않는다.** 실행은 `goto` 와 `proposal/approve` 가 한다.
  이 엔드포인트가 실행까지 하면 「미리보기」라는 말이 거짓이 된다 (§제안 못 박는 것 1번과 같은 이유)
- **mock 어댑터는 URDF 수치 IK 로 답한다** (2026-09-06 · `docs/archive/GRILL-conveyor-twin-progresslog-2026-09-06.md` #5) — 컨트롤러가
  없는 집에서 시뮬 탭이 같은 화면·같은 경로로 돌게 하려는 것이다. FK 는 `safety.link_poses_mm` 위에 플랜지 99mm ·
  툴 · user 원점을 얹은 것(실기 `fkSamples` 와 1.3mm · 0.005°), IK 는 참조 자세에서 가장 가까운 가지를
  수치로 푼다(허용 0.5mm · 0.06°). **그림용이다** — 실기 근거로 옮겨 적지 않는다. 얼린 좌표계는 프로필 `fixture:` 가
  가리키는 로봇 것을 빌린다(`fr5-mock-lab` → `fr5-lab-a`); 없으면 base·툴 없음이다

### 손목 스캔 (`POST /scan` · 2026-09-07 · D192)

**로봇을 움직이지 않는다.** 지금 손끝 자세에서 손목 뎁스 한 판을 받아 **표적 하나의 자리·요각**을 user1 로 낸다.
2단 조준의 「정밀」 칸이고, 풀이는 `scripts/robot/carrier-find.py`(`depth-probe.py` 위) **한 곳**을 브리지가 부른다 — 두 번째 사본을 만들지 않는다.

```
POST /scan  { "target": "carrier" | "basketFloor" | "carrierInBasket" }
  →
  { "ok": true|false,
    "view": { "target", "rzDeg", "tcpMmDeg": [...], "camMm": [...], "user1Mm": [x,y,z], "yawDeg": θ|null,
              "bulletsUser1Mm": [[x,y], ...], "bulletSource": "rgb-aligned"|"depth"|null, "bulletWhy": string|null,
              "targetPx": [u,v]|null, "bulletsPx": [[u,v], ...],
              "frame": { "url": "/scan/frame/<id>", "widthPx", "heightPx", "capturedAt" }|null,
              "blob": { "kind": "raised"|"sunken", "areaPx", "sizeMm": [a,b], "heightMm", "longAxisDeg" },
              "source": "depth" | "mock", "t": … } | null,
    "reasons": [ … ] }

GET /scan/frame/<id>  →  image/jpeg | 404
```

- `frame`은 **검출에 실제로 쓴 9장 중앙값 컬러 정지화면**이다. `targetPx`·`bulletsPx`는 그 화면의 화소계와 같다.
  손목 카메라 HUD는 이 세 값을 같이 쓰고, 계속 바뀌는 `/api/camera/preview` 위에 예전 화소 좌표를 얹지 않는다.
  브리지는 메모리에 최근 4장만 두며 밀려난 id는 404다. 목업·컬러를 안 쓰는 표적은 `frame:null`이다.
- 프레임은 JSON에 base64로 싣지 않는다. `/scan` 응답이 단계 장부(`/runs` 한 줄 64KB)에 그대로 들어가므로,
  이미지를 문자열로 넣으면 장부 상한을 쉽게 넘는다.

| 표적 | 무엇을 찾나 | 어떻게 |
|---|---|---|
| `carrier` | 판 위 거치대 | 주 평면(판) 위로 **솟은** 덩어리 · 발자국 69×85 ±15% · 높이 55 ±15 |
| `basketFloor` | 빈 바구니 바닥 | 주 평면(터틀봇 윗판·테두리 150) 아래로 **파인** 덩어리 · 110×120 ±15% · 깊이 = `AMR_BASKET.innerHMm` ±15 (발판 뒤 35 · 2026-09-07) |

  90° 모호(110 vs 120)는 부르는 쪽이 odom 요각 사전값으로 가른다
- 결측=차단: 깊이 없음 · 평면 못 맞춤 · 후보 0 · 후보 2개 이상 크기 안 → 전부 `ok:false` + 사유. **큰 쪽을 고르지 않는다**
- **mock 어댑터**(뎁스 호스트 없음)는 `source:"mock"` 으로 답한다 — 부르는 쪽이 `truth: {user1Mm, yawDeg}` 를 주면 거기에 **툴 프레임 고정 편향**
  `DEPTH_MOCK_BIAS_MM`(기본 `[12, −8, 0]`)을 지금 rz 로 돌려 더한다. 그래서 거울 쌍(rz±90)의 평균이 진값으로 돌아오는 것을 **집에서 게이트가 확인**한다.
  `truth` 가 없으면 `ok:false` — 지어내지 않는다. 목업은 `atTcpMmDeg`(6) 를 주면 **그 자세에서 본 것처럼** 답한다(목업 팔을 실제로 안 돌리고 거울 쌍을
  집에서 돌리려는 것) — **실기는 무시한다**: 실기는 언제나 지금 손끝 자세다
- `carrier`의 총알 xy는 `/api/camera/rgbd/frame`의 **동기화된 컬러와 컬러 화소계로 정렬된 깊이**에서
  분홍 거치대 내부 황동 연결 성분을 찾고, 묶음 manifest의 컬러 내부 파라미터로 역투영한 뒤
  `colorToDepth` 외부 파라미터로 기존 hand-eye가 기대하는 깊이 렌즈 좌표로 바꾼다. 정렬 묶음·분홍 ROI·후보가
  없으면 `bulletsUser1Mm:[]`와 사유를 내며, 빈 배열은 총알 부재 증거가 아니다(D206)
- 조종권·ARMED 불필요(관측). 뎁스 호스트는 `FR5_DEPTH_HOST`(기본 `127.0.0.1:5058` · `/api/camera/rgbd/frame` · `/api/camera/depth/frame` · `/api/camera/info`)

### 단계 기록 (`/runs` · 2026-09-07 · D191)

**버튼 한 번 = 기록 한 줄.** 화면이 조준·풀기·실행의 각 칸을 지날 때 무엇을 보고(원값) 무엇으로 풀었고(해·접촉) 실기가 어디 갔나(readback·게이트 사유)를
브리지가 `<data_dir>/runs/<runId>.jsonl`(`config.yaml data_dir` · 기본 `~/fr5-data` · 검증은 `FR5_DATA_DIR`)에 **덧붙여 쓰기만** 한다. 해석·판정은 안 한다 — 나중에 「그때 왜 틀렸나」를 되짚는 장부다.

```
POST /runs            { "runId"?: "20260907-101500", "line": { … } }  → { ok, runId, n }   (runId 없으면 새로 만든다 · 누구나)
GET  /runs                                                          → [ { runId, n, t0, t1 } ]
GET  /runs/{runId}                                                  → { runId, lines: [ … ] }
```

`line` 의 모양(화면이 채운다 · 없는 칸은 `null`): `{ t, phase, step, aim: { coarse, views, fused, target }, solved: { jointsDeg, gate, contacts },
sent: { cmd, speedPct } , readback: { jointsDeg, tcpMmDeg }, gate: { ok, reasons }, photo }`. 브리지는 `t`·`runId` 만 채우고 나머지는 **그대로** 적는다.
크기 상한 한 줄 64KB · 파일은 지우지 않는다(evidence 로 옮기는 것은 사람).

## 궤적 녹화 (Teach · 2026-08-05 · D74)

**로봇을 움직이지 않는다.** 20004 상태 스트림을 타임라인으로 적기만 하므로 §명령의 허용목록과
무관하다 — 여기에 재생을 끼워 넣지 않는다. 실기 재생은 슬롯의 승인 관문(사다리 3)을 탄다.

```
POST /trajectories/start  { who, token, name, purpose }  → 녹화 시작 (조종권 · ARMED 불필요)
POST /trajectories/stop   { who, token }                 → 저장하고 요약 반환
GET  /trajectories                                       → 목록 (누구나)
```

```jsonc
{ "name": "demo-01",
  "source": "demo",                 // demo | postproc | policy — F10 이 이 필드로 셋을 가른다
  "purpose": "measure",             // measure(조건 차단) | collect(일부러 랜덤화)
  "fps": 30, "durationSec": 12.4,   // 고정 주기. 실제 간격이 흔들리면 재표본해 이 값에 맞춘다
  "startPose": { "jointsDeg": [...], "name": "home-a" },
  "endReason": "done",              // done | timeout | gateRefused | estop | collision | disconnect
  "dropped": 0,                     // 결손 프레임 수
  "stamp": { "robotId": "fr5-lab-a", "toolId": 1, "userId": 1,
             "firmware": "…", "speedCapPct": 10, "gripperForcePct": 30,
             "workspaceRev": "2026-08-05",
             "gripperConfig": { "config": [0, [1, 4, 0, 0]] } },   // 활성화 때 읽은 **원본**. 활성화 전이면 null
  "frames": [{ "tSec": 0.0, "jointsDeg": [...], "tcpMmDeg": [...], "gripperPct": 62 }] }
```

- **`stamp` 는 잰 조건이다** — 이게 없으면 속도 상한 10% 로 잰 것과 30% 로 잰 것을 나란히
  놓게 되고 "A 가 B 보다 몇 % 빠르다" 가 거짓말이 된다 (D74)
- **`gripperConfig` 는 해석하지 않고 원본을 싣는다** — `GetGripperConfig` 는 `company`·`device`
  에 +1 보정이 섞여 있고 우리 실측(`4·0`)과 유니티 기록(`2·4`)이 갈렸다. 파싱해서 저장하면
  그 해석이 틀렸을 때 원본이 남지 않는다. 소급해 못 채우는 값이라 그대로 남긴다 (D46·D81)
- **`measure` 인데 `stamp` 가 다르거나 `dropped > 0` 이거나 `endReason != done` 이면
  비교에서 제외**하고 화면이 그 이유를 말한다. 조용히 빼면 표가 왜 비었는지 모른다
- 최대 지속·최대 프레임에 **상한**을 둔다. 무한 기록은 디스크와 메모리 둘 다 먹는다
- 단위는 하드 룰 5 그대로 **밀리미터·도(°)** 다. 외부 포맷(라디안)을 여기 들이지 않는다 —
  필요하면 변환기를 한 곳에 만든다
- 저장은 `~/fr5-data/trajectories/` (D45 — 배포 트리 밖)
