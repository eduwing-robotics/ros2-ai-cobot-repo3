# 좌표계 — 숫자가 어디 기준인지 적는 한 곳

정본: 이 문서 + `Shared/data/frames.js`. 둘은 **같은 표**를 가리킨다 (문서가 뜻, 모듈이 값).

## 제1원칙 — 번호는 정의가 아니다

> `coord` 는 **몇 번을 쓰는지**만 말하고 **그게 어디인지**는 말하지 않는다.
> (`API-CONTRACT.md` §좌표계 정의 · D87)

이 한 줄을 안 지켜서 이 저장소는 **여섯 번** 다쳤다. 전부 계산이 아니라 **라벨**이 틀렸다.
다섯 번째는 **이 SSOT 를 세우면서** 냈다 — 그래서 손으로 맞추는 대신 `scripts/check/frames.sh` 가 지킨다.

| 언제 | 무엇 | 대가 |
|---|---|---|
| 2026-08-07 (D87) | `/state.tcpMmDeg` 를 base 로 읽음 — 실제 `user1` | 없는 받침 186mm 를 만들어냄 · **하루** |
| 2026-08-08 | 벽 `seenZMm` 만 환산에서 빠짐 | 벽이 **342mm** 낮게 섬 |
| 2026-08-28 | `AMR_HOME` 을 base 로 읽음 — 실제 `user1` | 터틀봇이 판 밑 **342.1mm** 허공 |
| 2026-08-28 | odom 축이 홈 요각을 따라가는 걸 빠뜨림 | 터틀봇 **전진이 반대**로 그려짐 |
| 2026-08-28 | 이 표의 `base→lab` 이 실은 `user1→lab` 이었다 — **SSOT 안에서 낸 사고** | `lab` 변환 전부가 **725.1mm** 어긋남 (감사가 잡음) |
| 2026-08-28 | **`lab` 이라는 이름이 두 좌표계를 가리켰다** — 글로벌캠 것과 배치안 것 | 태그 검출 계산이 「태그가 카메라보다 높다」는 헛답을 냄 · 두 프레임을 섞음 |

**그래서 값에는 반드시 프레임 이름이 붙는다.** 이름 없는 좌표는 이 저장소에서 데이터가 아니다.

## 규약 넷 (D87 이 남긴 방어선)

1. **번호 ≠ 정의.** 번호(`toolId`/`userId`)는 정의(`coordDefs`)와 **따로** 싣는다
2. **읽기 전용.** 좌표계를 바꾸는 명령은 만들지 않는다 —
   *"바꾼 뒤 다시 재는 것까지가 한 절차다 — 버튼이 아니다"*
3. **fail-closed.** 못 옮기면 **`null`** 이고, 부르는 쪽은 **안 그린다.**
   회전 0.5° 초과도 `null`. 반쯤 맞는 자리는 없는 것보다 나쁘다
4. **노출 최소.** 화면 스위치는 `base_link`·`user1`·`tcp` 셋뿐 —
   *"목록이 열 개가 되면 아무도 안 쓴다"* (`SHARED-CORE.md` §프레임 축)

| `tcp` | 손끝 = **플랜지 +135mm**(핑거 끝) | 접근축 +Z | 실기 `tl_cur_pos` · D108 |
| `lab` | 실험실 바닥 (평면도 원점) | Z-up · mm | `presets.js` realmap |
| `camLab` | ⛔ **글로벌캠이 쓰는 `lab`** — 태그0 · **카트 덱 평면**. 이름이 같고 자리가 다르다 | z 는 덱 위가 + · mm | `marker_follow.py` · `scene-anchors.json` |
| `table` | 작업대 상판 (터틀봇이 달리는 면) | **원점 미정의** | 상자 자리만 `FR5/bridge/config.yaml` |
| `odom` | **터틀봇이 브링업한 자리** = 홈. **축이 그때 바라본 쪽을 따라간다** | mm·° | 터틀봇 브리지 |
| `map` | SLAM 맵 원점 (맵마다 다름) | mm·° | TB 브리지 · **미사용**(D134) |

⚠ **`base` 와 `user1` 은 축이 같고 회전이 0이다.** 그래서 값이 전부 **「떨어진 거리」**에 있다
(실측 725.1mm). 회전이 0.5° 를 넘는 순간 규약 3이 걸려 아무것도 안 그려진다 — **그게 신호다.**

## 변환 — 지금 무엇을 알고 무엇을 모르나

`kind` 가 곧 신뢰도다. **`unknown` 구간을 지나는 변환은 `null` 이다.**

| 잇는 것 | kind | 값·출처 |
|---|---|---|
| `user1` → `base` | **live** | `coordDefs.user` (실기가 매 상태마다 준다). 실측 `(−401.8, +497.3, +342.1)` · 회전 0 |
| `tcp` → `base` | ❌ **unknown** | 실기가 매 틱 주지만 **6-DOF** 라 이 표의 평면 yaw 모델로는 못 적는다 — 필요해지면 **모델부터 늘린다.** ⚠ 툴 1 에 Z 135 가 들어 있다 — **툴 0 을 쓰면 게이트가 거짓** |
| `table` → `user1` | ❌ **unknown** | 판 상자 **자리**는 실측이지만(`config.yaml` · 로봇이 짚음) **판 좌표계 원점을 아무도 정의 안 했다.** TB 경로의 `tableToOdom` 이 셋 다 `null` — 정의하는 날 여기가 `measured` 가 된다 |
| `user1` → `lab` | **derived** | `+(1516.1, 2798.2, 1345.8)` · 회전 0. 같은 작업대를 `config.yaml`(user1)·`presets realmap`(lab) 두 프레임으로 잰 값의 차. z 는 바닥까지 — 검산: 상판 user1 −380.9 + 1345.8 = **964.9** ≈ presets `hMm 965`. ⛔ **`base` 가 아니다** — 2026-08-28 감사에서 라벨을 정정했다(다섯 번째 사고) |
| `odom` → `lab` | **fitted (브리지 안)** | `Shared/data/config/amr-frame.json` — 태그가 보인 순간의 **(odom, lab) 쌍**을 모아 푼 평면 강체변환(3-DOF). 쌍이 모자라거나 잔차가 크면 **안 쓴다**(fail-closed). 여기서 `lab → user1` 은 기존 사슬(`fixture.lab_to_user1`)을 그대로 탄다 — 환산은 한 곳이다(하드 룰 5) |
| `odom` → `user1` | **measured + assumed** | 자리 = `AMR_HOME` (줄자 2026-08-28) · **회전 = `AMR_HOME.yawDeg` 180°** (「벽을 등지고」에서 유도, 각도기 아님) |
| `camLab` → `base` | ❌ **unknown** | z 오프셋 **−3.7**(카트 덱)은 유도됐다 — 검산: 작업대 상판이 `camLab` 에서 −35 로 나온다는 기록과 base 계산 −38.8−(−3.7)=−35.1 이 맞는다. **막는 것은 태그0 의 base x·y 가 미측정**인 것 |
| `map` → `lab` | ❌ **unknown** | `mapToLab` 미측정. `GAP-MATRIX` 「이번 트랙 최대 관문」. SLAM 미사용이라 지금은 안 쓴다 |
| `tag` → `base` | ❌ **unknown** | `robot-base-in-tag.json` 은 있으나 yaw 재측정 대기 (`anchor-pose.py` 주석) — **낡은 값을 믿지 않는다** |
| `camera` → `tcp` | ❌ **unknown** | handeye (`handeye-probe.py`). 위와 같은 이유로 6-DOF |

### `odom → lab` 은 **재지 않고 맞춘다** (2026-08-31 · D158)

`AMR_HOME` 의 요각 180° 는 **각도기로 잰 값이 아니다**(「벽을 등지고 주차」에서 유도). 그
가정이 2026-08-28 의 **x +58 · y +59mm** 어긋남의 후보 하나였고, 크기가 비슷하고 부호가
반대라 회전 성분이 의심됐다. 줄자로 가르려 했지만 **더 싼 길이 있었다.**

터틀봇 태그가 보이는 순간에는 **같은 시각의 두 좌표가 동시에** 있다 — 바퀴가 말하는
`odom` 자리와 카메라가 푼 `lab` 자리. 그 쌍을 모으면 변환이 **풀린다.**

```
p_lab = R(fit.yawDeg) · p_odom + (fit.txMm, fit.tyMm)
```

- **쌍이 적으면 안 쓴다** — `n` 하한과 잔차 상한을 넘어야 채택한다. 못 넘으면 `AMR_HOME` 로
  떨어지고, **그 사실을 `source` 로 말한다**(조용히 갈아타지 않는다)
- **쌍은 로봇이 움직여야 모인다** — 한자리에 서 있으면 회전이 안 풀린다(같은 점만 쌓인다).
  그래서 `fit` 은 **주행 중에** 좋아진다
- ⛔ **이것이 `AMR_HOME` 을 대체하지 않는다.** `AMR_HOME` 은 「홈이 어디냐」이고 이건
  「odom 축이 어떻게 돌아 있냐」다. 서로 다른 질문이라 둘 다 남는다

### ⚠ `odom` 은 축까지 돈다 — 자리만 더하면 안 된다

터틀봇 odom 은 **브링업 순간의 자세**를 원점·기준축으로 잡는다. 홈에서 로봇이 작업대2 를
보고 서므로 **odom `+x` = `user1` `−x`** 다. 자리만 더하고 회전을 빼먹으면 **전진이 반대로**
그려진다 (2026-08-28 에 그랬다).

```
p_user1 = R(AMR_HOME.yawDeg) · p_odom + (AMR_HOME.x, AMR_HOME.y)
```

## 쓰는 법

```js
import { toFrame } from '@fr5/shared/data/frames.js';

// 터틀봇이 지금 로봇 베이스 기준 어디인가
const p = toFrame({ xMm, yMm, zMm: 0 }, 'odom', 'base', { user1: coordDefs.user });
if (!p) return;          // 규약 3 — 못 옮기면 안 그린다
```

- **live 프레임은 값을 넘겨야 한다.** `user1` 은 실기가 주는 값이라 모듈이 지어내지 않는다
- 경로는 모듈이 찾는다. 중간에 `unknown` 이 하나라도 있으면 `null`
- **여기 없는 변환을 화면 코드에서 새로 만들지 않는다.** 만들면 다섯 번째 사고다

## 안 하는 것

- **좌표계를 바꾸는 API** (규약 2)
- **`unknown` 을 0 으로 채우기** — 모르는 것을 안다고 적는 순간 게이트가 거짓말한다
- **프레임을 화면에 열 개 노출** (규약 4)
