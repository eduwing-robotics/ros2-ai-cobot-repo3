# FEATURE-SPEC — 기능 명세

> `PRD.md`의 F1~F9를 ID·우선순위·의존으로 정밀화한다. 새 기능은 팀 회의에서 확정 후 등록한다.
> 갱신 2026-07-30 — 목표 확정으로 **F7~F9 추가**. 우선순위를 목표 기준으로 다시 매겼다.

## 우선순위

- **P0**: 성공 판정에 직접 걸린다. 없으면 "배치 A가 B보다 몇 % 낫다"를 못 말한다.
- **P1**: 보강. P0가 다 된 뒤.

## 의존 규칙

- **F7이 F8·F9의 앞이다.** 맵 모델이 없으면 측정할 대상도, 겹칠 대상도 없다
- **F8은 팀원 알고리즘을 기다리지 않는다.** 목업 두 개로 화면을 완성하고, 실물 수치는
  `Shared/data/datasource/` 파일 하나를 바꿔 끼운다 (`ARCHITECTURE.md` §확장성)
- F9는 F7의 모델과 F4의 정합을 둘 다 쓴다
- F2는 F1의 상태 스트림에, F3는 F1·F2에, F5·F6은 F1에 의존한다

## 무엇부터

**F7 → F9 → F8 순이다. 셋 다 서버 없이, 팀원 코드 없이 갈 수 있다.**

1. **F7** — 공용 맵 모델만 있으면 된다
2. **F9** — F4가 이미 되므로, 맵을 읽어 바닥에 그리는 것만 더한다
3. **F8** — 목업으로 만든다. 필수 필드는 처리량과 평균 시퀀스타임 둘뿐이다
4. F1~F3·F5 — `FR5/bridge/`가 있어야 한다. 지금은 문서성 골격뿐이다

우리 몫은 시각화이므로 **P0 셋(F7·F8·F9)이 팀원 일정과 무관하게 끝난다.**
팀원과 합의해야 하는 것은 **"한 시퀀스가 무엇인가" 하나**다 — 그게 어긋나면 비교 자체가
무의미해진다 (`API-CONTRACT.md` §팀원과 맞춰야 할 것).
