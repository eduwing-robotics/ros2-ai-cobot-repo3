# IP 글로벌카메라 + 폰 답사 디지털트윈

> 상태: **공장 외형/벨트·공유 고스트·글로벌 화면 로컬 구현 · 실카메라/폰 정합 전** (D227~D230 · 2026-09-11)

## 목표

FR5 대시보드에서 현재 보이는 계획 고스트를 두 사람이 동시에 본다.

- 조작자는 고정 IP 글로벌카메라 영상에서 셀 전체를 본다.
- 현장 관찰자는 휴대폰 카메라의 답사 화면 안에서 같은 고스트를 실물 FR5 위치에 본다.
- 맥 내장카메라는 태그를 볼 수 없으므로 이 정합 사슬에 넣지 않는다.
- 두 화면은 읽기 전용 시각화이며 이 기능에서 로봇 명령은 만들지 않는다.

구조도: [`artifacts/ip-global-walk-architecture.html`](../../../artifacts/ip-global-walk-architecture.html)

## 한 장면, 두 시점

| 항목 | 고정 IP 글로벌카메라 | 휴대폰 답사 AR |
|---|---|---|
| 관찰자 | 조작자·감독자 | 현장 보행자 |
| 배경 | IP Webcam MJPEG | 휴대폰 WebXR 카메라 |
| 카메라 자세 | `global-cam.json`의 고정 외부 파라미터 | 기존 태그 3장 이상 → 첫 XR viewer pose → 앵커 |
| 세션 중 추적 | 고정이므로 없음, 태그로 드리프트 감시 | ARCore SLAM과 XR anchor |
| 기본 가상층 | 파란 FR5 고스트·계획 설비·안전 윤곽 | 파란 FR5 고스트·선택한 계획 설비 |
| 실재 물체 | 영상으로 보고 3D 색 모델은 숨김 | 영상으로 보고 3D 색 모델은 숨김 |
| 태그 역할 | 캘리브레이션·드리프트 감시 | 시작할 때 좌표 인계, 이후 기본 숨김 |

글로벌카메라와 답사는 서로의 영상을 전달하지 않는다. **같은 lab 좌표와 같은 상태를 각자의
카메라에서 다시 투영**한다. 거울 두 개가 같은 사람을 다른 방향에서 보는 것과 같다.

## 좌표 정합

### 글로벌카메라

이미 있는 경로를 그대로 쓴다.

```text
lab 좌표 ── global-cam.json(labToCam) ── IP 영상 화소
```

카메라는 삼각대에 고정한다. `0·1·2·4` 태그는 기존처럼 캘리브레이션과 드리프트 감시에 쓰며,
화면은 정합이 무효면 고스트와 깊이 가림을 함께 숨긴다.

### 휴대폰 답사

WebXR 이미지 추적은 다시 쓰지 않는다. D222~D226에서 검증한 직접 검출을 시작 전 좌표 인계에만 쓴다.

```text
1. 일반 카메라에서 기존 태그 3장 이상을 1~2초 검출
2. phone-cam.json + 태그 모서리로 태그면→폰 카메라 자세 계산
3. 일반 카메라 스트림 해제
4. 폰을 그대로 든 채 WebXR 시작
5. 첫 XR viewer pose와 직전 태그 자세를 결합해 lab 정렬 root 생성
6. XR anchor에 root를 붙이고 이후에는 ARCore가 추적
```

검출과 XR이 같은 카메라 장치를 동시에 소유하지 않는다. 3번과 4번 사이에 폰이 움직이면 정합은
무효다. 성공 안내가 뜰 때까지 화면은 고스트를 그리지 않는다.

### 컨베이어 태그

태그는 장식물이 아니라 좌표계 장비다.

- 기존 `0·1·2·4`의 상대 배치가 바뀌지 않을 때만 한 세트로 쓴다.
- 컨베이어가 태그와 함께 움직이면 그 태그는 **컨베이어 자세**를 말할 뿐 lab 원점이 될 수 없다.
- 정합 중에는 가상 설비·고스트·안내판이 태그 사각형을 덮지 않는다.
- 폰은 3장 미만이면 자세를 추측하지 않고 시작을 막는다.
- 글로벌카메라의 기존 4장 드리프트 관문은 낮추지 않는다.

## 고스트 상태의 주인

각 화면이 대시보드의 우선순위를 흉내 내면 언젠가 서로 다른 팔을 그린다. 대시보드가
`보여 주기로 최종 선택한 한 벌`만 게시하고 브리지가 짧게 보관한다. 계약은
[`API-CONTRACT.md`](../contract/API-CONTRACT.md) §공동 시각화 고스트가 정본이다.

소비자는 모두 같은 순서를 쓴다.

1. `motionTarget.doneAt == null`인 실제 전송 목표
2. 만료되지 않은 `visualGhost`
3. 숨김

게시 연결이 끊기거나 2초가 지나면 `visualGhost`는 사라진다. 마지막 프레임을 사실처럼 남기지 않는다.
폰은 `/ws/state`를 받기만 하며 조종권·이동·정지 UI를 넣지 않는다.

## 현장 렌더 규칙

현재 답사 화면처럼 전체 흰 맵을 카메라 위에 세우는 것은 기본 모드가 아니다. 실물 작업대와
컨베이어를 덮어 현장을 못 보게 하기 때문이다.

| 역할 | 색으로 그림 | 깊이에 씀 | 예 |
|---|---:|---:|---|
| 실재 | 아니오 | 정합 통과 뒤에만 | 작업대·실재 컨베이어·실재 FR5 |
| 계획 | 예 | 예 | 설치 전 컨베이어·새 지그 |
| 고스트 | 반투명 파랑 | 아니오 | 대시보드가 고른 FR5 계획 자세 |
| 정합 | 진단 중 윤곽만 | 아니오 | AprilTag `0·1·2·4` |
| 미확인 | 아니오 | 아니오 | 존재 여부가 확인되지 않은 소품 |

첫 구현은 기존 `?only=conveyor` 원칙을 답사에도 적용해 **고스트와 계획 컨베이어만** 그린다.
새 배치 스키마를 먼저 만들지 않는다. 다른 계획 소품이 실제 소비자가 될 때 표시 역할을 계약에 추가한다.

### 깊이감

1. 이미 있는 투명 그림자 받이와 접촉 그림자를 유지한다.
2. 큰 고정물인 작업대 상판·옆판부터 단순 상자 형태의 **보이지 않는 깊이 가림 형상**으로 쓴다.
3. 정합 오차가 큰 상태에서는 깊이 가림도 함께 끈다. 틀린 가림은 없는 가림보다 더 거짓말처럼 보인다.
4. 사람·케이블·움직이는 팔의 실시간 가림은 첫 범위가 아니다. 별도 깊이 또는 분할 증거가 생길 때 연다.
5. 사실적인 재질은 계획 설비에만 적용한다. 실재 작업대를 정교하게 다시 모델링하는 것은 화면을 더 가릴 뿐이다.

## 화면 구성

### 글로벌카메라 화면

- 영상 100% 불투명
- 파란 FR5 고스트와 계획 컨베이어만 기본 표시
- 태그 검출 수·정합 RMS·드리프트 신뢰를 한 줄로 표시
- 전체 흰 배치맵은 진단 쿼리에서만 허용

### 휴대폰 답사 화면

- 카메라 전체 화면, PiP·미니맵 없음
- 시작 전: `태그 3/4 · 폰을 그대로 유지` 안내
- 정합 뒤: 파란 FR5 고스트만 먼저 표시
- 계획 설비는 한 개의 `계획 설비` 토글로 표시
- stale·정합 무효·로봇 미연결이면 고스트를 숨기고 사유 한 줄 표시

## 전송 경계

폰의 WebXR에는 보안 출처가 필요하고 공개 Vercel 화면은 실험실의 평문 WebSocket에 직접 붙을 수 없다.

- 랩 1차: 신뢰된 HTTPS/WSS 게이트웨이가 AR 정적 파일과 브리지 상태를 같은 출처로 프록시한다.
- 외부 사람의 폰: 같은 게이트웨이에 읽기 전용 세션을 붙인다. 로봇 명령 경로는 노출하지 않는다.
- 게이트웨이가 없으면 태그 정합 데모까지만 가능하며 라이브 대시보드 고스트 공유는 완료가 아니다.

구체적인 게이트웨이 제품은 태그→XR 킬-실험 통과 뒤 선택한다. 가장 큰 기하 위험을 닫기 전에
네트워크 배포를 먼저 만들지 않는다.

## 구현 순서와 게이트

### 1. 태그→XR 좌표 인계 킬-실험

- 로봇 명령 0, 정적 100mm 검증 상자 하나만 표시
- 태그 3장 이상, 재투영 RMS ≤3px인 프레임만 인계
- 태그 주변의 알려진 세 지점에서 중앙 오차 중간값 ≤30mm, 최악 ≤60mm
- 2m 이동 또는 60초 중 먼저 도달할 때까지 추가 드리프트 ≤30mm

하나라도 실패하면 고스트·전체 맵·깊이 가림을 붙이지 않는다. 카메라 광학중심과 XR viewer 원점
차이를 먼저 잰다.

### 2. 같은 고스트 한 벌

- ✅ `/ws/visualization`과 `/ws/state.visualGhost` 계약을 로컬 구현했다.
- ✅ FR5 조작 화면의 `preview` 관절 6개와 `seq`가 글로벌 화면에 같게 도착했다.
- ✅ 게시 탭을 닫은 뒤 글로벌 화면이 56ms에 숨었다(상한 2초).
- ✅ 글로벌 화면은 읽기 전용 `/ws/state`만 쓰며 명령 API를 갖지 않는다.
- ⬜ 휴대폰 답사 화면에서 같은 값·해제를 확인하는 일은 태그→XR 좌표 인계 뒤다.

자동 검증은 `scripts/check/visual-ghost-web-verify.mjs`로 재현한다. 고정물 실렌더로 전달·표시를 닫았으며 실제 IP 영상 정합 판정은 아니다.

### 3. 현장 렌더

- 실재 작업대·실재 로봇 색 모델 숨김
- 계획 컨베이어와 파란 고스트만 표시
- 정합 통과 뒤 작업대 깊이 프록시를 하나씩 켜 가림 앞/뒤를 실폰에서 확인
- 답사 렌더 30fps 이상을 유지

### 4. 동시 운용과 외부 관찰자

- 글로벌카메라와 폰 답사를 동시에 10분 실행
- 두 화면의 유효 고스트 `seq`가 같고 정지·만료가 같이 반영됨
- HTTPS/WSS와 읽기 전용 접근을 확인한 뒤 다른 사람의 폰으로 판정

## 레퍼런스 이미지

모델링 전에 다음 세 장을 같은 실제 장면에서 만든다.

1. 글로벌카메라 — 실영상 + 파란 고스트 + 계획 컨베이어
2. 폰 답사 — 작업대가 보이고 그 뒤의 고스트만 가려지는 시점
3. 실패 기준 — 전체 흰 맵이 실물과 태그를 덮는 모습에 금지 표시

이 세 장을 기준으로 Astra급 모델링은 컨베이어 실루엣·재질·접촉 그림자만 개선한다. 실재 작업대의
고해상도 복제와 새 GLB 묶음은 첫 범위가 아니다.

### 공장 모델링 1차 — 실측 셀과 가상 배경 (2026-09-11)

`factory-walk`은 **실측 셀 + 가상 공장 배경 · 연출** 프리셋이다. `realmap`의 작업대 3판·카트·
FR5 베이스·스테이션·컨베이어 좌표와 치수는 그대로 재사용한다. 늘린 방·검사대·수납장·차폐 부스는
미실측 연출이며, 실측 방이나 라이브 운용 증거로 인용하지 않는다. `realmap`과 기존 `defense-line`은
바꾸지 않고 현장 AR 기본 화면에도 이 배경을 자동으로 올리지 않는다.

외형 참고는 `artifacts/reference/ip-global-defense-factory-route-conveyor-v3.png`와
`phone-walk-defense-factory-reference-v1.png`다. 사진은 재질·설비의 모양만 정하며, 사진에서
화각·거리를 새로 역산하거나 실측 컨베이어 단면을 키우지 않는다. 컨베이어는 여전히 순정 TurtleBot
이동 경로에 고정된 이야기 레이어다. 33번은 640×120×80mm, 32번은 560×120×80mm를 유지한다.

공유 부품의 평벨트는 단부 드럼·반환면·금속 프레임·얕은 표면 이음으로 만든다. 새 자산·텍스처·
전역 재질 변경 없이 기존 재질을 재사용한다. 프레임과 발판은 고정하고 표면 이음만 이동한다.

- `belt.setTravelMm(signedMm)` — 절대 누적 이송 거리. 같은 값은 같은 표면을 만들며 되감기도 가능하다.
- 배치 뷰의 `setConveyorTravel(id, signedMm)`와 앵커 층의 `setConveyorTravel(tagId, signedMm)`가
  같은 부품 API를 호출한다. 양수는 해당 컨베이어 로컬 +X(설치 방위) 방향이다.
- `setConveyorPose(id, {xMm, yMm})` — 호출자가 **현재 활성인 컨베이어 구간**을 지정하고 동일 lab
  좌표의 TurtleBot 위치를 준다. 처음은 기준만 잡고 이후 이동을 구간 길이축에 투영한다. 정지·
  제자리 회전에는 벨트가 흐르지 않는다. `null`로 연결을 놓으면 기준을 버리고 표면은 멈춘다.
- 절대 거리 주입은 pose 기준을 초기화한다. 재생·되감기는 절대 거리 API를 쓰고, pose API는
  순서대로 도착하는 유효 위치에만 쓴다. 태그 재정합으로 구간이 재생성되면 새 기준에서 시작한다.
- 로봇 미연결·stale 상태는 호출자가 `null`로 전달한다. 이 모델링 단계는 네트워크 구독이나
  로봇 명령을 만들지 않는다. 실제 구간 이벤트·실주행 동기 검증은 로봇 재연결 뒤에 남는다.

실렌더와 게이트 결과는 [`factory-walk-model-v1.md`](../../evidence/2026-09-11/factory-walk-model-v1.md)에 남긴다.

### 레퍼런스 색·질감 2차

`factory-walk`의 `appearance: defense-reference-v1`에서만 레퍼런스의 차콜 벽·진회색 에폭시
바닥·도장 강판·브러시드 스테인리스·검은 프레임·무색 청회색 유리를 적용한다. 작은 반복
질감은 코드로 만든 `DataTexture`를 공유해 새 이미지 자산이나 의존성을 추가하지 않는다.
실측 `realmap`, 작업대·카트·FR5, 전역 조명과 후처리는 바꾸지 않는다. IP카메라·폰 답사에서는
방 전체가 아니라 계획 컨베이어 같은 가상 설비에만 같은 재질 역할을 재사용한다.
