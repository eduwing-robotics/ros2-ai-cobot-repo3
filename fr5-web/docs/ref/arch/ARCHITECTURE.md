# ARCHITECTURE — 구조

분류: **SSOT**. 새 폴더를 만들거나 코드를 어디 둘지 모를 때 여기를 먼저 고친다.

## 우리 몫은 시각화다

팀 안에서 역할이 갈렸다(2026-07-30). **이 경계를 넘지 않는다.**

| | 누가 | 무엇 |
|---|---|---|
| **우리** | 이 저장소 | **맵 편집기와 AR — 맵 편집, 지표 표시·비교, 실물 위 실물 배치** |
| 팀원 | 다른 코드 | 생산성 수치를 내는 알고리즘 (시뮬레이션·계산) |
| 팀원 | 다른 코드 | AMR 자율주행 |

**우리는 수치를 만들지 않는다. 받아서 보여준다.** 그래서 우리가 지켜야 할 것은 둘이다 —
**받는 모양(계약)을 우리가 먼저 제시하는 것**, 그리고 **나중에 데이터베이스·백엔드로
바꿔 끼울 수 있게 격리해 두는 것**.

## 전체 그림

```
[FR5 컨트롤러] ─TCP:8080─ [FR5/bridge :5055] ─REST/WS─ [FR5 관제화면]  ← 우리
   실물 로봇        공식 파이썬 SDK · FastAPI                │
                                                            ├─ 맵 편집기 (PC, React)   ← 우리
[팀원의 알고리즘] ─────── 지표 데이터 ──────────────────┤
[팀원의 AMR]                                            └─ AR 화면 (폰, 바닐라)   ← 우리
```

**목표는 실기 ↔ 우리 대시보드·AR 이다.** 유니티 펜던트는 이 그림에 없다 —
같은 로봇을 이미 실기로 붙여 본 **선례**이고 받쳐야 할 클라이언트가 아니다.
검증된 숫자와 함정만 가져온다 (`unity/unity-bridge-protocol.md`).
나중에 붙이려면 변환 라우트 하나를 더한다 — 우리 계약은 그대로 둔다.

**브리지 서버가 로봇의 유일한 관문이다.** 클라이언트는 로봇과 직접 말하지 않는다.
안전 상한을 한 곳에서 강제하고 조종권 충돌을 한 곳에서 막기 위해서다.

**지표 데이터는 로봇 경로와 별개다.** 팀원 알고리즘이 어디서 돌든 우리는
`Shared/data/datasource/` 하나로만 받는다 (아래 §확장성).

## 확장성 — 데이터 출처를 한 곳으로 격리한다

지금은 팀원의 알고리즘도, 데이터베이스도, 백엔드도 없다. **그래도 화면은 지금 만든다.**

```
화면 (Dashboard/features/metrics · layout   ·   AR/features/overlay)
   ↓  이 경계만 안다
Shared/data/datasource/    ← 함수 몇 개. 화면은 출처를 모른다
   ├── mock.js              지금: 손으로 만든 JSON
   ├── http.js              나중: 팀원 API · 백엔드
   └── (db)                 나중: 데이터베이스
```

**화면은 `fetch`를 직접 부르지 않는다.** 부르는 순간 출처가 화면에 박히고,
나중에 백엔드를 붙일 때 화면을 전부 다시 짜야 한다.

목업에서 실물로 바꾸는 작업이 **파일 한 개 교체**여야 한다. 그게 이 경계의 완료 판정이다.

**규칙** — 새 최상위 폴더를 만들기 전에 이 문단을 먼저 고친다.
폴더 경계와 파일 귀속은 `docs/ref/arch/BUILD-VITE.md`가 정본이다.
현재 루트 `package.json`은 `Shared`·`AR`·`Dashboard`·`TurtleBot`·`FR5`·`Sim` 여섯을
**npm workspaces**로 묶는다. 빈 패키지는 만들지 않는다 — 실행 패키지가 생길 때 더한다.
`Sim` 은 그 규칙대로 **`@mujoco/mujoco` 를 실제로 부르는 파일이 생긴 날**(2026-08-11 · V2) 들어왔다.

호스트는 OS 가 아니라 **로봇 랜선이 꽂힌 기계**가 정한다 (D112 · 2026-08-11).

## UI 통일 — codegate를 시각 정본으로, 토큰은 `Shared/tokens/` 한 곳

외부 시각 정본은 외부 codegate 프로젝트의 `src/app/globals.css`의
**KITvibe 에디토리얼 아카데믹**이다. FR5Web은 외부 폴더를 런타임 import하지 않고
`Shared/tokens/tokens.css`에 값과 의미를 미러링한다. Dashboard와 FR5 웹은
`data-theme="light"`를 쓰고, AR은 카메라 위 가독성을 위해 같은 의미의 어두운 값만 쓴다.

| 공유한다 | 공유하지 않는다 |
|---|---|
| 색 역할 · 4px 간격 스케일 · 타이포 역할 · 반경 · 상태/출처 색 | 버튼·패널·표 같은 컴포넌트 스타일 |
| 선택·포커스·disabled 같은 인터랙션 의미 | 레이아웃 · Tailwind · shadcn |

**시각 문법** — 밝은 중립 바탕, 1px 경계, 기본 반경 2px, 넓은 여백, 작은 모노 라벨이다.
네온·그라디언트·장식적 글래스·게임화는 쓰지 않는다. 3D 위 정보판만
`--c-overlay` 반투명을 허용하며, 일반 카드에는 `--c-card`를 쓴다.

**상태색은 장식색이 아니다.** 정상=`--c-ok`, 경고/armed=`--c-warn`, 정지/recording=
`--c-danger`, 시뮬레이션=`--c-info`다. 탭 선택·주요 버튼은 `--c-selected`와
`--c-primary`의 중립 흑백을 쓴다. 선택을 초록색으로 칠하면 “정상”과 구별할 수 없다.

**타이포** — Geist/Geist Mono가 있으면 우선하고 없으면 시스템 폰트로 폴백한다.
10px 대문자·`0.16em` 자간은 구역 라벨에만, 수치·좌표·시간은 모노+tabular 숫자를 쓴다.
새 폰트 의존성은 넣지 않았다. 실제 Geist 로딩은 화면 구현 때 별도 판정한다.

**왜 컴포넌트는 공유하지 않나** — AR·맵 편집기·관제화면은 정보 밀도와 입력 방식이
다르다. 공용 컴포넌트보다 의미 토큰만 공유해야 각 화면이 억지로 닮지 않고도 같은 제품으로 보인다.

## 비전 → 로봇 움직임 (확장 지점 · 안전이 먼저다)

"비전 인식값에 따라 로봇 움직임이 바뀐다"는 **자동으로 명령이 생성되는 경로**다.
**하드 룰 3**(속도 상한 + 사람 확인 없이 큰 동작 금지)과 정면으로 부딪힌다.

**그래서 비전은 명령을 만들지 않는다. 제안을 만든다.**

```
Vision  ──제안(proposal)──▶  FR5/bridge 안전 게이트  ──검사 통과분만──▶  로봇
                                    │
                     ┌──────────────┴──────────────┐
                     │ 속도 상한 · 관절 변화 상한   │
                     │ 도달 범위 · 조종권          │
                     │ **큰 동작이면 사람 확인**    │
                     └─────────────────────────────┘
```

| 규칙 | 왜 |
|---|---|
| 비전은 `POST /proposal` 로 **제안만** 보낸다 | 명령 주인은 한 명이다 (하드 룰 4) |
| 서버가 검사하고 **거부 사유를 응답한다** | 클라이언트를 믿지 않는다 |
| 상한 안의 작은 보정만 자동 통과 | 큰 동작은 사람 확인 |
| 비전이 죽으면 **아무 일도 안 일어난다** | fail-closed (`SAFETY-RULES.md`) |
| 제안·판정·실행이 전부 기록된다 | 나중에 왜 움직였는지 답할 수 있어야 한다 |

**계약은 이미 있다 — [`VISION-CONTRACT.md`](../contract/VISION-CONTRACT.md)** (2026-08-05 `API-CONTRACT.md` 에서 분리).
`Vision/` 이 소유하는 것은 **손목캠 검출 · hand-eye 변환 · 제안 클라이언트 셋뿐**이고,
`/proposal` 의 서버 쪽(접수·판정·번역·기록)은 안전 게이트 안이라 `FR5/bridge/` 몫이다.
**글로벌 카메라(폰)는 비전이 아니다** — 캘리브 `scripts/map/` · 실물 배치 `AR/` · HUD `FR5/src/features/live/`.

## 자율주행 로봇(TurtleBot) — 관제는 우리, 주행 알고리즘은 팀원

**스코프가 개정됐다 (2026-07-31, D31).** 기종이 TurtleBot3 Burger ×2 로 확정되면서
**관제 인프라**(켜고 끄기 · teleop · 매핑 · 슬롯 교체 · 로그 · 실험 기록)를 우리가 만든다.
주행 알고리즘은 여전히 팀원 몫 — 팀원 파이썬이 `TurtleBot/bridge/slots/` 에 꽂힌다.

```
로봇 ×2 (bringup만) ─ROS2/WiFi─ 로봇 라즈베리파이 (Nav2·SLAM·슬롯·tb-bridge:5056) ─┐
                                   브리지가 웹 빌드도 서빙                        ├─ 팀원 브라우저
계약 · 안전(속도 상한·워치독·estop) · 미래 접점 5 → docs/ref/contract/TB-CONTRACT.md ┘
```

- **FR5 `bridge/` 와 형제·무의존** — 로봇마다 관문 하나. 서로 호출하지 않는다.
  협업 시나리오는 슬롯 스크립트가 두 관문의 클라이언트가 된다 (`TB-CONTRACT.md` §미래 접점)
- 안전 책임을 지는 대신 FR5 와 같은 원칙을 미러한다 — fail-closed · 조종권 · 서버 강제 상한
- 기존 확장 지점 둘(맵 `amr` 블록 · `Shared/data/datasource/`)은 그대로 산다 —
  맵↔실주행 연결은 맵 메타 `mapToLab` 하나로 잇는다

## 각 층이 책임지는 것

| 층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| `FR5/bridge/` | 로봇 연결, 상태 폴링·브로드캐스트, 안전 검사, 조종권, 지점 저장, 경로 계산 | 화면 렌더링 |
| `FR5/src/` | 조작·티칭·슬롯·경로 검토·실행 기록 | 안전 판단 · SDK 직접 호출 |
| `Dashboard/` | 맵 편집, 지표 표시·비교, FR5 상태 요약·연결, 3D 표시 | **로봇 명령** · 지표 계산 · 안전 판단 |
| `AR/` | 마커 정합, 맵·경로를 실물 위에 겹치기 | 맵 편집 · 로봇 명령 |
| `Shared/data/` | 맵 모양 · 단위 · 설정 · **데이터 출처를 아는 유일한 곳** | 화면·렌더링·계산 |
| `Shared/view3d/` | URDF·궤적·안전 범위 렌더링 (바닐라 three) | **React** · 데이터 가져오기 |
| 팀원 알고리즘 | 생산성 수치 산출 | — (우리 저장소 밖) |
| 팀원 AMR | 자율주행 | — (우리 저장소 밖) |

## 좌표계

| 곳 | 단위 | 축 |
|---|---|---|
| 로봇 · API 계약 | 도(°), 밀리미터(mm) | 로봇 베이스 기준 |
| URDF · 3D 내부 | 라디안, 미터 | Z-up |
| three.js 화면 | 라디안, 미터 | **Y-up** → `robot.rotation.x = -π/2` |
| AR 마커 | 미터 | 마커 원점 → 로봇 원점 변환은 설정값 |

**변환은 경계에서 한 번만.** 중간에서 또 바꾸면 원인을 못 찾는다.

## 상태 흐름

```
로봇 상태 폴링 (서버, 33ms 목표 — 실측 27Hz)
   → 안전 검사 통과분만
   → WebSocket 브로드캐스트 (전원)
   → 3D 관절 갱신 · AR 겹치기 갱신
```

명령은 반대 방향이되 **조종권을 가진 하나만** 통과한다. `stop`은 예외로 항상 통과한다.
