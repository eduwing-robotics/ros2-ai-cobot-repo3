# Database — 스키마·마이그레이션 · **착수 (2026-08-07)** · 서빙 읽기 API 는 아직

**저장소는 SQLite 다 (2026-08-06, D81 — D46 개정).** 두 층으로 쓴다 — 로봇 옆에서 도는 것은
브리지의 로컬 파일(`~/fr5-data/`)이 정본이고, **랩 안 상주 기계의 SQLite** 가 팀 공유·집계용
상위 저장소다. **인터넷이 끊겨도 티칭·실행도 열람도 멈추지 않아야 한다** (fail-closed 의 데이터 판).

**클라우드(Supabase)는 보류다** — "랩 밖에서 봐야 하는가" 가 참이 되는 순간 상주 기계가
동기화 주체가 되어 층 하나를 더 얹는다. 그때까지 `.env` 의 Supabase 값은 비워 둔다.

- 저장 후보 — 배치안 · 지표 실행 결과 · 명령/상태 기록(F6) · 이동 지점
- **화면이 여기를 직접 부르지 않는다.** `Shared/data/datasource/` 가 유일한 경계다.
  목업에서 실물로 바꾸는 작업이 **파일 한 개 교체**여야 한다
- 배치안 좌표는 **실험실 바닥 원점 기준 mm·도**로 저장한다 (SR_23).
  로봇 베이스 기준으로 저장하면 배치안끼리 비교가 불가능해진다
- 스키마를 만들기 전에 `docs/ref/contract/API-CONTRACT.md` 를 먼저 고친다 (하드 룰 1)
- **브라우저가 저장소를 직접 부르지 않는다.** 서버만 말한다 — 로그인이 없는 구조(D41)에서
  브라우저에 접근 수단을 주면 주소를 아는 누구나 남의 기록을 지울 수 있다
- **쓰는 주체는 프로세스 하나다** (D81). SQLite 는 네트워크 DB 가 아니라 여러 곳에서 동시에
  쓰면 깨진다. 나머지는 HTTP 로 읽는다. 그리고 기록 DB 를 **SD카드에 두지 않는다** — 쓰기 수명
- **시각을 잃지 않는 기계여야 한다** — 정전 후 재부팅에 타임스탬프가 오염되면 기록 전체가
  무의미해진다 (D48 §두 개의 시계). 내장 시계가 없는 기계면 외부 모듈로 받친다
- **모든 행에 정체를 함께 저장한다** — `robotId` · 펌웨어 문자열 · tool/user · 그리퍼 정체 ·
  `source`(사람/텔레오퍼레이션/정책). 나중에 소급해 채울 수 없는 값들이다
- **영상·큰 바이너리는 테이블에 넣지 않는다** — 경로만 저장하고 파일은 따로 둔다

## 폴더

표준 라이브러리만. **정본은 계약이다** — 어긋나면 `docs/ref/contract/RECORD-NODE-CONTRACT.md` 가 이긴다.

- `schema.sql` — 10 테이블 DDL (정본은 계약 · 여기는 사본, 어긋나면 계약이 이긴다)
- `migrate.py` — 스키마 적용·버전 관리 (idempotent)
- `retention.py` — 보존 게이트 순수 함수 (움직일 때만 + 전이는 항상 · 계약 §보존 정책)
- `collector.py` — WS 읽기 구독 → 보존 적용 → 저장 (한 수집기 = 한 브리지)
- `test_retention.py` — 보존 게이트 단위 (게이트 `scripts/check/db-unit.sh`)
